# КЭС: `kes-reader` — требования (согласование)

Статус: **идёт сбор требований**, реализацию не начинаем.
Связано: `docs/kes-memory.md` (карта измерений и **настроек** КЭС, модели),
`docs/map-reader.md`, `docs/map-contract.md`, `docs/events.md` (§11 — заглушки КЭС),
`docs/legacy/kes-legacy-malina2.md` (разбор legacy КЭС из бэкапа `.60`).

## 1. Что делаем

Новый демон **`kes-reader`**: читает один/несколько **КЭС** по **протоколу MicroArt**
(Modbus КЭС **не умеет** — только MicroArt), публикует данные в **shared memory**
(свой сегмент) и ведёт **свой список устройств** (`kes-list`) — по образцу `map-reader`
и `map-list`. Данные КЭС доступны панелям, «Мастер-Узлу» и менеджеру событий.

## 2. Ключевые ограничения

- **Протокол КЭС — только MicroArt.** Никакого Modbus.
- **Железа КЭС нет** → разработка и тесты **без железа**, на программном эмуляторе;
  финальная приёмка — на реальном КЭС (когда появится).
- Общий код с `map-reader` — **обязательно переиспользуем** (без дублирования).

## 3. Общий код (рефакторинг)

Вынести из `map-reader` в общие пакеты (используются и `map-reader`, и `kes-reader`) —
конкретный раскрой, границы и порядок выноса: **`docs/daemons-shared.md`** (единый модуль
`daemons`, пакеты `lib/{transport,microart,shm,control,ports,device}`). Статус:
`transport`, `microart`, `shm` (механика), `control` (каркас), `ports` (примитивы портов),
`device` (коды `_Device`) — **уже вынесены**; `map-reader` переведён без изменения поведения.

- транспорт: открытие serial, RS485-режим, latency/тайминги, ретраи → `lib/transport` ✅;
- протокол **MicroArt**: кадры чтения/записи, эхо, адресация/unit → `lib/microart` ✅;
- **shared memory**: механика сегмента/seqlock (`Segment/Slot/Item`) → `lib/shm` ✅;
- **unix-сокет управления**: каркас `Serve`+JSON → `lib/control` ✅;
- **порты**: `ListPorts/RdevOf/BusyRdevs` (device-agnostic) → `lib/ports` ✅;
- **идентификация**: коды `_Device` (3/5/7/9) → `lib/device` ✅;
- контракт `*-list` (формат полей записи) и оркестрация пробы (**Modbus/скорости**) —
  остаются у демона (MAP-специфика).

Требование: рефакторинг **не ломает** `map-reader` (MAP) — тесты и контракт `map-*`
остаются валидными.

## 4. Контракт КЭС (по карте из sunReceiver)

Источник истины — карта: `~/src/sunReceiver/docs/map/mppt/Карта Памяти_MPPT_WG_2021_01_18.xlsx`
(актуальная). Отдельный **shm-сегмент** + отдельный **`kes-list`** (id/gen/port/baud/model/
lastSeen — по образцу `map-list`). Полная карта (измерения + **настройки/EEPROM** + модели
КЭС 200/100, 250/60, 200/60) — `docs/kes-memory.md`.

**Идентификация (probe) — РЕШЕНО:** `_Device=0x00` — код устройства; **у КЭС `= 5`**
(у МАП `3`, зарядник `7/9`). Probe = штатное MicroArt-чтение 1 байта по адресу `0x0000`;
провал/нет ответа → `0`. Дизасм `usbscanner` + `tty_scan.sh` (D5→mpptd) —
`docs/legacy/kes-legacy-malina2.md` §1a.

**Измерения (RAM; чтение «Монитором» — адрес + `0x1F0`):**

| Поле | Адрес | Смысл |
|---|---|---|
| `Vc_PV` | 0x2D9 | Напряжение СП |
| `Ic_PV` | 0x2DF | Ток СП |
| `V_Bat` | 0x2E5 | Напряжение АКБ |
| `P_PV` | 0x2EB | Мощность СП |
| `P_MPPT` | 0x2ED | Мощность на выходе (= поле `P_Out` в legacy JSON) |
| `P_Load`/`P_EXTS[1]` | 0x2F5 / 0x40C | Мощность нагрузки |
| `P_curr` | 0x2F9 | Мощность заряда |
| `I_Ch` | 0x2FB | Ток заряда АКБ |
| `I_Out` | 0x2FF | Ток на выходе |
| `Temp_Int` | 0x31D | Внутренняя температура (`x-50`) |
| `Temp_Bat` | 0x31E | Температура АКБ (`x-50`) |
| `Pwr_W`/`Pwr_kW` | 0x39F / 0x3A1 | Энергия за сутки (Вт / кВт) |
| `I_EXTS[0/1]` | 0x406 / 0x408 | Ток датчиков (нагрузка) |
| `P_EXTS[0/1]` | 0x40A / 0x40C | Мощность (альт. источник / нагрузка) |
| `Relay_C` | 0x3E3 | Состояние реле (3 реле) |
| `RSErrSis` | 0x3B6 | Ошибки контроллера |
| `I2C_Err` | 0xD5A | Ошибки I2C |

- **Поля legacy-контракта, которых нет в карте напрямую:** `P_Out` (≈ `P_MPPT` 0x2ED)
  и **`windspeed`** (**RAM 0x3F8**, LE, 16 бит; `65535` = н/д — подтверждено дизасмом
  `mpptd`, см. `docs/legacy/kes-legacy-malina2.md` §1b).
- **Дополнительные ячейки (из дизасма `mpptd`, недокументированы):** **`Mode` = RAM 0x2C2**
  (ASCII; mapper: `0x2A<b≤0x7C` → символ, иначе `'U'`), **`Sign`/`MPP` = 0x37A/0x379**,
  **`UID` = RAM 0x2C9** (LE, 16 бит; `0` → `idx+1`).
- **Серийник КЭС = `UID` (RAM 0x2C9, 16 бит)**, а не `SerialNum0/1` (см. §7.4).

- **Реле КЭС — 3 шт.** (состояние `Relay_C` 0x3E3, установки `Relay_1/2/3` в EEPROM).
- BMS-зонд (если есть): `UakbCell[32]` 0xD80, `TakbCell[32]` 0xDC0, `Q_Cell[32]` 0xDE0,
  `ErrCells[32]` 0xE00; параллельные MPPT: `I_Akb_MPPT[16]` 0xE30, `Mode_MPPT[16]` 0xE50,
  `Takb_MPPT[16]` 0xE60, `ErrMPPT[16]` 0xE70.
- **Поля контракта — все** из карты (§4).
- **Серийник КЭС — по аналогии с МАП** (в `docs/map` ячейки `SerialNum*` описаны только
  для МАП; для КЭС — допущение): `SerialNum0` 0x018, `SerialNum1` 0x019
  (числовой, 2 байта) + буква `SerialNum3` 0x023.

## 4.1. Что даёт `docs/map` (сканирование `~/src/sunReceiver/docs/map`)

Просканированы **все** документы папки (не только КЭС/MPPT): `protocol_*_cells_*.doc`,
`protocol_2016/2020.doc`, паспорта МАП/Титанатор (PDF), `malina2.pdf`, `speed.pdf`,
`reverse-firmware/*.md`, `mppt/*.xlsx`, `mapread/`. Извлечённое — `/tmp/kilo/mapscan`.

**Протокол.** КЭС(MPPT) использует **тот же MicroArt-протокол**, что МАП:
`protocol_MAP_cells_2026_07_15` («поддерживается всеми моделями МАП и КЭС(MPPT)»),
`protocol_2020_12_29` (схема `PC → МАП (КЭС)`). Кадр `r/w`+P+A1A0+CRC+`\n`, эхо,
экранирование `0xDB 0xDC`(=LF)/`0xDB 0xDD`(=0xDB), CRC=сумма mod256, дефолт **19200**,
диапазон **19200–115200**, пауза >5с = разрыв.

**Отличия КЭС(MPPT) от МАП (документированы, кандидат в probe):**
- `7 ComMAP_Call_load_EEProm` — **только МАП** (у MPPT настройки вводятся при настройке прибора);
- `8` — у МАП `StatReset` (v≥25.4d), у **MPPT(ИЗУ)** = `Read_EEProm` (EEPROM→RAM);
- `1/2/4/5/9` (ON/OFF/Charge*/DischOff) — **только МАП**.

**Карта КЭС (источник истины) — `mppt/Карта Памяти_MPPT_WG_2021_01_18.csv`** (=xlsx):
RAM `Vc_PV 0x2D9, Ic_PV 0x2DF, V_Bat 0x2E5, P_PV 0x2EB, P_MPPT 0x2ED, P_Load 0x2F5,
P_curr 0x2F9, I_Ch 0x2FB, I_Out 0x2FF, Temp_Int 0x31D, Temp_Bat 0x31E, Pwr_W 0x39F,
Pwr_kW 0x3A1, Sign_C[0/1] 0x404/0x405, I_EXTS[0/1] 0x406/0x408, P_EXTS 0x40A/0x40C,
Relay_C 0x3E3, RSErrSis 0x3B6, I2C_Err 0xD5A`; BMS `UakbCell[32] 0xD80, TakbCell 0xDC0,
Q_Cell 0xDE0, ErrCells 0xE00`; параллельные MPPT `I_Akb_MPPT[16] 0xE30, Mode_MPPT[16] 0xE50,
Takb_MPPT[16] 0xE60, ErrMPPT[16] 0xE70`. RAM-чтение «Монитором» — **адрес +0x1F0**.
Температуры `x-50`. `Mode_MPPT`: 0 цикл,1 дозаряд,2 буфер1,3 буфер2.
- `mppt/Карта Памяти_WG.csv` — таблица **настроек КЭС** (EEPROM мл./ст. байт + RAM):
`MPPWM_mode 0x21C`, `I2C_Own_Addr 0x241`, `Bat_Volt_Cyc 0x246`, `Bat_Volt_Buf 0x248`,
`Bat_I_Ch_max 0x24C`, `Relay_1/2/3 0x23D..0x23F` и т.д.

**Legacy Malina-2 (`malina2.pdf`, прямой аналог задачи):** до **4 КЭС на 1 микро-ПК по USB**;
«автоопределение скорости 19200–115200»; «автосортировка по **UID** (4 байта, прошивка КЭС
≥6.3)»; управление реле КЭС по событиям (прошивка КЭС ≥6.3); API `write_sec.php`/`read_sec.php`
(`id` 1..4, `relay` приоритетнее `data`, таймаут 3с), `read_json.php?device=mppt` c `UID`,
`Vc_PV`, `Ic_PV`, `V_Bat`, `P_PV`; КЭС на шине I2C МАП — индивидуальные токи, группы
0=солнце/1=ветер, `_MPPTs_mode`. Адаптеры FT232/PL2303 (`speed.pdf` — таймаут COM «16»→«1»).

**Железо КЭС (паспорта):** DOMINATOR 200В/100А, 250В/60А; PRO 200В/60А; **100В/20А — без
связи с МАП** (не наш вариант). Связь КЭС↔МАП по I2C (RJ-12 X1/X2 → «MPPT/BMS»), адрес
задаётся в меню КЭС; есть свой датчик температуры.

**GAP.** Все ячейки-протоколы ссылаются на **«дополнительное описание к КЭС/MPPT»**
(«см. соотв. ячейки в дополнительном описании к КЭС») — **этого файла в `docs/map` нет**.
Именно там были бы: код устройства КЭС, его `_DevOpt`/«тип контроллера», ячейка скорости,
версия. Проверен и весь `~/src/sunReceiver` — код устройства КЭС (`0x05`) нигде не встречается
(в `cmd/probe` `0x05` — это Modbus Deye, к делу не относится).

## 4.2. Legacy Malina-2 из бэкапа `.60` (скрипты/веб)

Подробный разбор — `docs/legacy/kes-legacy-malina2.md` (бэкап
`/u03/archive/solar/microart/malina_backup/titanator_malina_fixed_20261007`). Кратко:

- **Probe реализован в `usbscanner`** (ELF ARM): пишет `/var/map/devices_found` строки
  `<порт>D<тип>R<baud>`; тип `D5` = КЭС/MPPT, `D3` = МАП, `D0` = нет, `D7/D9` = зарядник;
  боды `R0/R1/R2` = 19200/57600/115200. Горячий скан: `udev 108-usb.rules → add_tty.service
  → tty_scan.sh → usbscanner`.
- **Один процесс `mpptd` на все КЭС, до 4** — подтверждает нашу схему «один процесс —
  много портов»; лимит 4 (как в PDF).
- **IPC legacy:** shm **1995** — сырой образ ячеек КЭС, **2048 Б на КЭС**; shm **2016** —
  JSON-снимки КЭС, 4×1024. Очереди сообщений **2200 to-mppt / 2201 from-mppt**; запись
  в КЭС — сообщением **`<id>:<cell>:<value>:<ts>\0`** (id 0-based).
- **Реле КЭС:** состояние — байт **`0x3E3`** в блоке КЭС (`Relay_C`, биты 0/1/2 = реле 1/2/3);
  запись нового состояния legacy слала в ячейку **3645 (`0x0E3D`)** — назначение уточнить
  при дизасме `mpptd`.
- **Ошибки:** `RSErrSis` биты 0 Перенапряжение панелей, 1 Перенапряжение АКБ,
  2 Переразряд АКБ, 3 КЗ АКБ, 4 Перегрев АКБ, 5 Ошибка связи I2C, 6/7 н/о.
- **Поля/подписи JSON** — см. §4 (в т.ч. `P_Out`, `windspeed`). Группы «солнце/ветер»
  задаются списком индексов в `/settings/web-data/wind_mppts`.

## 4.3. Legacy API КЭС (совместимость — делаем тоже)

Требуется **воспроизвести старый HTTP-API КЭС** `malina-web` (как для МАП,
см. `docs/legacy-api.md`). Полное поведение/биты — `docs/legacy/kes-legacy-malina2.md`.

**Чтение (без авторизации, как legacy-МАП):**

| Эндпоинт | Запрос | Ответ |
|---|---|---|
| `GET /read_sec.php` | `id` (1..N), `offset` (≥0), `count` (≥1) | JSON-массив байт (decimal); `error` при выходе за границы / нет `offset` |
| `GET /read_json.php?device=mppt` | — | JSON-массив до 4 объектов КЭС (поля §4, §5 legacy-дока); `device=map`/`bat` — как сейчас |

`id` — **1-based** порядковый номер КЭС в списке (legacy-порядок = по `UID`/подключению);
границы чтения `0 ≤ offset`, `offset+count ≤ 2048` (размер блока КЭС = 2048).

**Запись (HTTP Basic → PAM, как legacy-МАП):**

| Эндпоинт | Запрос | Ответ |
|---|---|---|
| `GET|POST /write_sec.php` | `id`, `relay` (1..3), `mode` (`on`/`off`/`1`/`0`) | `Ok` / `error` / `unread` |
| `GET|POST /write_sec.php` | `id`, `data=[[cell,val],…]` (decimal) | `Ok` / `error` / `unread` |

- `relay` имеет приоритет над `data`; если состояние уже совпадает — сразу `Ok`.
- Реле КЭС: **состояние — `Relay_C` 0x3E3** (биты 0/1/2 = реле 1/2/3). Legacy-запись
  шла в **ячейку `0x0E3D`** (в карте не описана; гипотеза — командный регистр реле;
  требует подтверждения на железе, см. §7.7).
- Формат сообщения записи (legacy): `<id0based>:<cell>:<value>:<ts>\0`.
- **Путь записи в `mpptd` (дизасм):** сначала байт `3` (`ComMAP_EEPromWR`) в адрес `0`,
  затем байт `value` страницей 1 по адресу **`cell` как есть — без `+0x1F0`** (в отличие
  от чтения RAM, где `+0x1F0`). См. `docs/legacy/kes-legacy-malina2.md` §1c.
- `unread` — есть необработанная предыдущая команда на запись.

**Служебные:**

| Эндпоинт | Запрос | Ответ |
|---|---|---|
| `GET /devices.php` | — | текст `MAC:n`, `MPPT:n`, `CHARGER:n` |
| `POST /find_devices.php` | — | пересканировать порты (legacy: `systemctl start add_tty`) |
| `POST /wind_mppts_set.php` | `numbers` (индексы 0-based через запятую) | `ok` / `failed`; группа «ветер» |
| `GET /get_mppt_e.php` | `mppt` (0..3) | JSON `[[unixtime, Wh],…]`; `-1` |
| `GET /mppt_errors.php` | `mppt` | HTML-таблица `RSErrSis` |
| `POST /mppt_errors_history.php` | `device,start_date,end_date` | HTML-строки |
| `POST /mppt_counters_history.php` | `device,start_date,end_date` | HTML-строки |
| `GET /service_control.php` | `action,service=mpptd` | управление демоном (совместимость) |

**Маппинг на нашу систему:** `id` 1..N ↔ порядок в `kes-list`; чтение ячеек — из shm КЭС
нашего `kes-reader`; запись (реле/ячейки) — через писателя `kes-reader` (аналог
`map-reader`), реле — `Relay_C` 0x3E3. `read_json.php?device=mppt` — из снимка `kes-reader`.
Таймаут ответа на запись — как у legacy (≈3 с).

## 5. Эмулятор (без железа)

Архитектура — `daemons/kes-emu/readme.md`. Кратко:

**Решение:** «настоящий COM-порт» делаем **USB-serial gadget на самом устройстве** (`.60`),
без usbip и без сети:

- `dummy_hcd` + `g_serial` → появляются **`/dev/ttyGS0`** (gadget-сторона) и
  **`/dev/ttyACM0`** (host-сторона, реальный ttyACM).
- **`kes-emu`** — **один процесс**, обслуживает **несколько портов** (старт — **3 КЭС**):
  по одному gadget-CDC-ACM (или PTY) на КЭС; отвечает по **MicroArt** (регистры — сценарий/
  случайно; 3 реле). `kes-reader` читает host-стороны (`ttyACM*`).
- `kes-emu` — отдельная программа (не встроенный `sim`), чтобы гонять ридер максимально
  «по-настоящему». (В прежних версиях дока назывался `kes-sim` — переименован в `kes-emu`.)

**Разведение портов (важно):**
- Скан readers включает `/dev/ttyACM*`, но **не** `/dev/ttyGS0` — gadget-сторону ридеры
  не трогают.
- Host-сторона (`ttyACM0`) от эмулятора **отсеивается probe'ом**: **маркер КЭС — `_Device`
  (0x0000) == 5** (см. §7.6), поэтому `map-reader` отбрасывает порт как «не МАП» (`_Device≠3`),
  а `kes-reader` принимает по `_Device==5`.
- Занятый порт защищён flock (`scan.go`) — два ридера за один порт не борются.

**Запасной вариант (проще, без ядра):** `socat` PTY-пара `/dev/ttyKES0 ↔ /dev/ttyKES1`
(протокол тестируется полностью, но без USB-слоя). **usbip** — только если появится
физический USB-serial-адаптер на другом хосте; как основной путь не берём.

- Временный `simInjectKesBms` в `map-reader` — **убрать**, когда появятся
  `kes-reader` + `kes-emu`.
- Тесты: unit (протокол/парсинг) на эмуляторе; e2e на `.60` с gadget-эмулятором.
- **`kes-emu` в деплой не входит:** собирается/ставится вручную на конкретный хост при
  необходимости (dev/test); в образ и `deploy/` не включается (см. `daemons/kes-emu/readme.md` §0).

## 7. Открытые вопросы

1. **Поля контракта** — **все** из карты `sunReceiver/docs/map/mppt` (см. §4).
2. **Адресация** — только MicroArt, **один КЭС на порт** (шины/unit-id нет).
3. **Скорости/тайминги** — **такие же, как у МАП**.
4. **Серийник КЭС — РЕШЕНО (дизасм `mpptd`):** это **`UID`**, ячейка **RAM `0x2C9`**
   (16 бит LE; при `0` → `idx+1`). `SerialNum0/1` 0x018/0x019 в ID-окне есть, но `mpptd`
   их не использует. См. `docs/legacy/kes-legacy-malina2.md` §1b.
5. `kes-contract.md` — **делаем сразу** (свой список + своя карта памяти + формат shm).
6. **Сигнатура/probe КЭС — РЕШЕНО (дизасм `usbscanner`):** probe = штатное MicroArt-чтение
   1 байта по адресу **`0x0000`**; **маркер КЭС = значение ячейки `0x0000` == `5`**
   (МАП — `3`, зарядник — `7/9`); провал/нет ответа → `0`. Подробности —
   `docs/legacy/kes-legacy-malina2.md` §1a. Осталось принять этот критерий в `kes-reader`
   (`_Device==5`) и в `map-reader` (отвергать `_Device!=3`).
7. **`windspeed` — РЕШЕНО:** RAM `0x3F8` (16 бит LE, `65535` = н/д). Реле: состояние —
   `0x3E3`; legacy-запись реле идёт в **`0x0E3D`** (в карте не описана; кандидат —
   командный регистр реле) — **подтвердить на железе**; путь записи идёт без `+0x1F0`.
   Подтверждённые окна чтения `mpptd`: `0x0000`(190), `0x02C2`(240), `0x04B2`(240),
   `0x05A3`(240), при этом `адрес_устройства = RAM + 0x1F0`.

_(решено: КЭС — только MicroArt; **probe: `_Device`(0x0000)==5**; **серийник = `UID` 0x2C9**;
один КЭС на порт; скорости как у МАП; эмулятор — USB-gadget на `.60`; лимит КЭС — 4;
один процесс на все порты; запись `<id>:<cell>:<value>:<ts>`; реле КЭС 3 шт., биты 0/1/2 в
`Relay_C` 0x3E3; `windspeed` 0x3F8; `Mode` 0x2C2.)_

_(решено: КЭС — только MicroArt; своя сигнатура/`_DevOpt` ≠ МАП; один КЭС на порт; скорости как у МАП; эмулятор — USB-gadget на `.60`.)_
