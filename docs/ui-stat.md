# UI статистики (Графики / Таблицы)

**Статус:** **реализовано (MVP)** — tsdb: `direction`/`limit` и мета-запросы
`list`/`extremes` (`docs/telemetry-store.md` §9/§10); страницы `/stats/charts`
(каркас) и `/stats/tables`, API `/api/stats/devices`, `/api/stats/extremes`,
`/api/stats/table`, клиентский рендер `web/assets/static/js/stats.js`, i18n §8 локалей;
пересчёт значений в человеческие единицы (`web/internal/web/units.go`) и закреплённый
заголовок таблицы. **«Графики» — реализовано** (§3): `/stats/charts`, API
`/api/stats/series`, Chart.js (локально), `map v3` (`docs/stat.md`).
Связано: `docs/telemetry-store.md` (§9 — режимы чтения, §10 — протокол; там же
доработка `limit`/`direction`), `docs/accumulator.md`, `docs/stat.md` (контракты
полей). UI — шаблоны `web/assets/templates`, i18n `web/assets/i18n/*` (источник
строк — русский; паритет ru/be/zh/en/ka/kk/uz/tg), рендер — **на клиенте**.

## 1. Меню

Верхний пункт **«Статистика»** (`menu.stats`) → 2 подпункта: **«Графики»**
(`menu.charts`, → `/stats/charts`) и **«Таблицы»** (`menu.agg`, → `/stats/tables`).
Ссылки в `layout.html` реализованы.

## 2. Общие требования (обе страницы)

1. Страница открывается с **закладками по имеющимся устройствам**.
2. **Список устройств** — мета-запрос **`list`** к обеим tsdb (raw
   `/run/malina-ts-raw`, avg `/malina/var/malina-ts`); сервер отдаёт устройства
   **из памяти** (без сканирования каталогов/сегментов); объединение по
   `(type, device_id)`.
3. **Крайние точки** статистики (min/max времени) — мета-запрос **`extremes`**
   (из памяти) **точечно по устройству активной закладки**, при её выборе; по
   обеим БД. На закладке **в первой строке** — крайние точки имеющейся статистики
   (первая/последняя запись).
4. **Порядок закладок** (группировки-дерева нет):
   1. **все МАП** (сортировка по серийнику), после каждого МАП — **его BMS**
      (`mbms` с тем же `device_id`), если есть;
   2. затем **все КЭС** (сортировка по серийнику);
   3. затем **BMS-сироты** (`mbms` без своего МАП), если найдены.
   Заголовок каждой закладки — **в одну строку** (закладок может быть много).
5. Наполнение закладок **разное** для «Графиков» и «Таблиц».

## 3. Графики

Страница **`/stats/charts`** — **временные ряды из tsdb** по устройству **активной
закладки**. Закладки — как §1/§2. **Реализовано.**

### 3.1. Что показываем

- **Исторические ряды** выбранных метрик за период (не «живой» режим).
- Метрики выбираются **предустановленными наборами** (§3.2), **несколько метрик на
  одном графике** (совмещённые линии на общих осях X — время, Y — значение).
- Наборы формируются так, чтобы **метрики были одной размерности** (одна единица на
  график: все в В, или все в А, или все в Вт, или все в °C), иначе совмещение на
  общей оси Y некорректно. Смена набора — перерисовка.

### 3.2. Предустановленные наборы

- Наборы — **предустановленные** (фиксированные), по типу устройства; метрики в
  наборе — **одной размерности** (§3.1).

**МАП (`map`).** Состав — **как в панели 1 МАП** (`web/assets/static/map.js`).
Карточки-наборы:

1. **Напряжения** — `Uin`, `Uout`, `Uacc` (поля `UNET` (1), `UOUTmed` (6),
   `UAcc_med` (8)), **В**;
2. **Токи** — `Iin`, `Iacc`, `Iout`, **суммарный ток MPPT** — **А**;
3. **Мощности** — `Pnet`, `Pbat`, `Pout`, **мощность MPPT** — **Вт**;
4. **Частоты** — `Fnet` (`6250/TFNET`, поле `7`) и `Fout` (`6250/ThFMAP`), **Гц**;
5. **Температуры** — `Tacc`, `Ttor`, `Ttr` (поля `Temp_Grad0/1/2` (14/15/16)),
   **°C**.

- **Вычисляемые на клиенте:** `Iin = INET_16_4/(INET≥16 ? 4 : 16)`; `Iacc` — знак
  по режиму; `Iout = Pout/Uout`; `Pnet = Uin·Iin` со знаком по `PNET_Sign_P`
  (0 → отрицательно, как в панели 1), `Pbat = Uacc·Iacc`,
  `Pout = Pnet−Pbat`; мощность MPPT = `Uacc · (суммарный ток MPPT)`. Формулы —
  как в панели 1 / `measure` (§4.3).
- **Новые поля контракта — `map v3`:** `ThFMAP` (частота выхода), **первые 4 канала
  MPPT** (`I_Akb_MPPT0..3`, ограничение реализации) и `PNET_Sign_P` (знак `Pnet`);
  суммарный ток MPPT = **сумма**
  по каналам (на клиенте). `map v3` = `map v2` + эти поля. Панель 1 (`map.js`) также
  исправлена: ток MPPT — сумма, не среднее.
- **Зависимость от `map v3`:** карточки **«Токи»** (линия MPPT), **«Мощности»** (линия
  MPPT) и **«Частоты»** (линия `Fout`) заполняются **только после ввода `map v3`**;
  до него эти линии пусты (в `map v2` их полей нет). `Fnet` и остальные линии —
  доступны сразу.
- **Каналы MPPT (осознанно):** графики используют **4 канала** (`I_Akb_MPPT0..3`),
  тогда как события (`imppt`) и legacy суммируют **до 16**; для устройств с >4
  каналами значения в графиках будут **меньше** (см. `docs/stat.md` `map v3`).
- **Не входит в графики:** вентилятор (`CulerSpead`), реле (`Relay`), энергии
  (`M_POWhour*`), фазные токи/мощности, MPPT-температуры, дискретные
  (`MODE_RAM`/`StatusCh`/ошибки/`flagUnet2`).

**КЭС (`kes v1`).** Сквозная нумерация полей — по контракту `docs/stat.md`
(`1 VcPV`, `2 IcPV`, `3 PPV`, `5 VBat`, `8 TempBat`, `9 POut`, `11 IOut`,
`12 TempInt`). Карточки-наборы:

1. **Напряжения** — `VcPV` (1), `VBat` (5), **В**;
2. **Токи** — `IcPV` (2), `IOut` (11), **А**;
3. **Мощности** — `PPV` (3), `POut` (9), **Вт**;
4. **Температуры** — `TempBat` (8), `TempInt` (12), **°C**.

Остальные поля КЭС (`4 Windspeed`, `6 ICh`, `7 PCurr`, `10 PLoad`, `13 Mode`,
`14 RelayC`, `15 RSErrSis`) в графики **не входят** (по согласованию —
дискретные/неопределённые).

**BMS (`mbms Vn`).** Сквозная нумерация полей: `id = 3·(i−1)+{1,2,3}` =
`UakbCell{i}` / `TakbCell{i}` / `Q_Cell{i}`, `i = 1..n`. Карточки-наборы:

1. **Напряжения ячеек** — `UakbCell1..n`, линия на ячейку, **В**;
2. **Разброс ячеек (max−min)** — `max−min(UakbCell*)`, **В** — *вычисляемая*;
3. **Напряжение пакета** — `Σ UakbCell*`, **В** — *вычисляемая*;
4. **Температуры ячеек** — `TakbCell1..n`, **°C**;
5. **Токи ячеек** — `Q_Cell1..n`, **А**.

Вычисляемые ряды (разброс, пакет) считаются **на клиенте** из уже полученных рядов
ячеек (сервер не нагружаем, §5.6). Число линий — по числу ячеек `n`; скрытие
лишних — чипами легенды (§3.4). Имена серий — логические («Ячейка 1…n»).

- Имена серий в легенде — **логические** (человеческие, локализованные), **не сырые
  имена полей** (напр. «Напряжение АКБ», а не `UAcc_med`); локализованы во всех 8
  языках. Значения — в **человеческих единицах** тем же слоем
  (`web/internal/web/units.go` / `measure`, §4.3).

### 3.3. Период и источник

- Периоды — **как в «Таблицах» (§4.1):** кнопки («24 часа» по умолчанию, «Сегодня»,
  «Вчера», «7 дней», «Месяц», «Последние данные»); время — по локали клиента,
  24-часовой формат.
- **Источник (`raw`/`avg`) выбирается автоматически** по ширине диапазона —
  **чекбокса «Детальные данные» на «Графиках» нет.** Если границы диапазона
  **не шире 20 минут** — берём **`raw`** (детально); иначе — **`avg`**. Порог
  **20 минут** фиксирован.
- **Обе tsdb**, приоритет `raw` в его зоне (raw хранит **48 ч**).
- **Сервер ничего не прореживает** (и не агрегирует): отдаёт точки как есть. Объём
  ограничен самим выбором источника (`raw` — только ≤ 20 мин → ≤ ~1200 точек;
  длинные периоды — `avg`, минутное разрешение).
- **Ограничение:** число метрик на график (напр. ≤ 8). Лимит строк таблиц (200) к
  графикам не применяется.

### 3.4. Рендер и вид (эталон — страница BMS SunReceiver)

- **Рендер — на клиенте** (canvas; библиотека — Chart.js), сервер отдаёт только
  числа (§5.6). Библиотеку берём **локально** (без CDN — устройство офлайн), версия
  как в эталоне (Chart.js 4 + time-адаптер + плагин зума).
- **Карточки-графики**: **одна карточка = один предустановленный набор** (§3.2);
  **сетка 2 колонки**, на узком экране — **1**.
- **Карточка**: заголовок (имя набора — **шапка нашего цвета**); **toolbar** со
  строкой диапазона и подсказкой про зум; область графика (canvas).
- **Линии**: толщина ~1.5, сглаживание (tension ~0.35, монотонное), **без точек**,
  без заливки; палитра ~16 цветов по кругу. Для знаковых метрик (ток/мощность) —
  **симметричная ось Y вокруг нуля**; иначе — авто-диапазон.
- **Оси:** X — время (локаль клиента, 24-часовой формат, форматы тиков от мс до лет);
  Y — значение с подписью единицы.
- **Легенда — кастомные чипы** (встроенная легенда Chart.js скрыта): ЛКМ по чипу —
  **вкл/выкл линии**, **двойной ЛКМ — только эта линия**, кнопка **«Все»** — показать
  все. На тач: тап — вкл/выкл, long tap — только эта.
- **Перемещение карточек** — стрелки **↑ ← ↓ →** (2 колонки, row-major); порядок
  хранится **на клиенте** (`localStorage`), **отдельно по типу устройства**
  (у МАП/КЭС/BMS — свои порядки), восстанавливается при загрузке.

### 3.5. Интерактивность (эталон — страница BMS SunReceiver)

- **Зум — два вида:** (1) **Ctrl+колесо** мыши; (2) **Ctrl+выделение отрезка** —
  выбранное окно становится текущим диапазоном всех графиков.
- **Панорама** — **drag** мышью по графику (сдвиг по времени).
- **Touch:** **пинч** — зум по X, **свайп** — панорама, **двойной тап** — сброс
  зума; хинт со значениями на тач — **по тапу** (авто-хинт по движению отключён).
- **Пороги:** минимальное окно зума — **5 минут**; Ctrl-выделение короче **1 минуты**
  игнорируется.
- **Связанность карточек:**
  - окно по X **общее** для всех карточек — зум/панорама одной переносятся на все;
  - **вертикальная черта-курсор** рисуется **на всех карточках одновременно** по
    общему времени под курсором;
  - **хинты (тултипы) синхронны** — показываются на всех карточках для одного среза
    времени; значения всех видимых линий; уход курсора с графика гасит их везде.
- **Перегрузка данных под окно:** по завершении зума/панорамы ряд **перезапрашивается
  с сервера под новое окно целиком** (без прореживания), поля «С/по» обновляются;
  сброс зума (двойной тап) возвращает стандартный вид.
- **Сохранение состояния:** скрытые линии и зум **не теряются** при обновлении
  данных; порядок карточек — по типу устройства (§3.4).
- **Обновление данных — только по кнопке** «Обновить» (авто-таймера нет, в отличие
  от эталона).
- **Кнопки диапазона** — **как в «Таблицах»** (§4.1); постраничной навигации таблиц
  («Вверх/Вниз») на графиках **нет** — по времени двигаются **зумом/панорамой**.

### 3.6. API (набросок, при реализации)

- Эндпоинт `GET /api/stats/series?type=&id=&from=&to=&fields=` — реализован;
  `fields` пусто → возвращаются **все поля ряда** (один запрос на устройство); ответ
  `{"source":"raw|avg","series":{"<key>":[[t,v],…]}}` **без прореживания**. Источник
  выбирается по ширине диапазона (≤ 20 мин → `raw`, иначе `avg`).
- **Сервер отдаёт только ряды отдельных параметров**, но **одним запросом** —
  **набор рядов на запрос/устройство** (список `fields` за один вызов), не по одному
  полю за запрос. **Вычисляемые величины** (разброс, пакет и т.п.) на сервер **не
  запрашиваются** — считаются на клиенте (§3.2).

## 4. Таблицы

### 4.1. Выбор периода

- **Явный период**: две даты со временем **ИЛИ** «за день» (поле типа «Дата»);
  кнопка **«Показать»** — для первых двух.
- **Быстрые кнопки**: **«24 часа»** (по умолчанию при открытии закладки),
  **«Сегодня»**, **«Вчера»**, **«7 дней»**, **«Месяц»**, **«Последние данные»**
  (хвост БД).

### 4.2. Источник и запрос

- **Переключатель «Детальные данные»** — чекбокс **справа вверху, на уровне
  заголовка** страницы; **по умолчанию выключен** → запрос **только из `avg`**.
  При включении — `raw`+`avg` с приоритетом `raw` (§4.2 ниже). **Изменение
  чекбокса → обновление** текущего представления.
- **Время в UI** — по локали клиента (`navigator.language`), **24-часовой формат**
  (без AM/PM).
- **Обе tsdb**: при перекрытии периодов **приоритет — `raw`** (детально).
  Порядок опроса по направлению:
  - **`from`** (вперёд) — сначала **`avg`**;
  - **`to`** (назад) — сначала **`raw`**, `avg` подключается, если `raw` не
    покрывает (raw хранит **48 ч**; если `to` уходит **дальше 48 ч назад**, в raw
    смысла нет — только `avg`).
- Выборка — **только по устройству активной закладки** за период.
- **Не более 200 строк** (`limit` **фиксирован**, `docs/telemetry-store.md` §9).
- Кнопки периодов и «Показать» — запрос в режиме **`from`-`limit`**.

### 4.3. Таблица и навигация

- Колонки — **по контракту устройства** (`docs/stat.md`); **смена версии
  контракта** в периоде разделяется отдельным **заголовком** (колонка «версия»).
- **Заголовок колонки** — имя поля **как есть** (например `UAcc_med`), **второй
  строкой** — **единица измерения** (`В`, `А`, `Вт`, `Гц`, `°C`); у кодов/битфилдов
  второй строки нет.
- **Значения** переводятся в **человеческие единицы** (сервер, `web/internal/web/units.go`):
  линейные коэффициенты (`×0,1`, `×0,01`, `×1/16`, `×100`), сдвиги (`V−50`),
  специальные (`6250/V` Гц; `V+100` В; ток `INET_16_4` делится на 4/16 в зависимости
  от `INET`; ток ячейки BMS `Q_Cell = (Q/100)·UakbCell`), «нет данных» (`0` Гц,
  `Windspeed=0xFFFF`, температура банки `0xFF` — нет датчика) → **«—»**; если
  **зависимое поле отсутствует** (presence-бит не выставлен) — тоже **«—»**, а не
  подстановка нуля. **Эталон формул — панель 1 МАП** (`web/assets/static/map.js`,
  `compute()`); общие формулы МАП вынесены в `web/internal/measure` (единый слой с
  менеджером событий, `docs/events.md` §4); также `docs/stat.md` (КЭС),
  `docs/legacy/bms-api.md` (BMS); где
  масштаб не задокументирован — поле показывается **сырым** (колонка помечается
  звёздочкой `*` с подсказкой, `statsCol.raw`). Округление — на клиенте (`°C` — 1
  знак, `В`/`А`/`Гц` — 2, `Вт`/коды — целые). `Mode` — только печатаемый ASCII,
  иначе «—».
- **Спец-поля:** КЭС `Mode` — **символ** (`i`/`v`/`B`/`b`/`S`), не код;
  **реле** (КЭС `RelayC`, МАП `Relay` из `map v2`) — **3 колонки** `Relay1/2/3`
  со значениями `0`/`1`; у **BMS** заголовок колонки версии — **«Ячеек»** (число
  банок `n` в `mbms Vn`).
- **`map v3`** (при переходе — `docs/stat.md`): в таблицу МАП добавляются колонки
  `ThFMAP` (Гц) и `I_Akb_MPPT0..3` (А; первые 4 канала — ограничение реализации) —
  с заголовком (имя как есть), единицей (`measure.Freq6250`/`measure.MpptCurrent`)
  и описанием-хинтом (`stats.f.map.*`).
- **Заголовок таблицы закрепляется** при скролле страницы (`position: sticky`),
  чтобы имена колонок и единицы оставались на экране.
- **Всплывающее описание у каждого заголовка** — по **щелчку** на заголовке
  показывается подсказка с описанием поля (смысл, единица, «нет данных»); формулы
  преобразования в хинте не приводятся (значения уже пересчитаны); повторный
  щелчок или щелчок вне — закрыть. Ключ описания — `stats.f.<имя поля>`
  (`stats.hint.time/version/cells` для служебных колонок), локализован во всех 8
  языках.
- Остаётся (целевое): **расшифровка кодов** ошибок/статусов в текстовые значения.
- **Над таблицей** — широкая **рельефная кнопка «Вверх»** (стрелка, не подпись);
  **под таблицей** — **«Вниз»** (рельефная стрелка). Дисейбл — **раздельный**:
  «Вверх» гаснет на верхней границе данных, «Вниз» — **никогда** (см. ниже).
- **«Вверх»** — режим `to` со временем **крайней (верхней)** строки,
  **включительно** (крайняя строка попадает и в новую выборку — перекрытие на одну
  строку, без провала в пустоту). **«Вниз»** — режим `from` от нижней строки, тоже
  включительно.
- **«Вверх»** дисейблится на верхней границе данных; **«Вниз» — никогда не
  дисейблится**: в БД идёт запись, снизу всегда могут появиться новые данные.
- Границы для дисейбла «Вверх» — по **активному источнику**: при выключенных
  «Детальных» — по `avg`, при включённых — по объединению `raw`+`avg`.

## 5. Решения по вопросам

1. **Источник:** обе tsdb; перекрытие → `raw`; порядок опроса по направлению (см.
   §4.2); оговорка raw 48 ч.
2. **Поля:** единицы и физический пересчёт — сделаны (§4.3, эталон — панель 1);
   символы (`Mode`), реле (3 колонки), «Ячеек» для BMS — сделаны; остаётся
   расшифровка кодов ошибок/статусов.
3. **Версии:** разделять (доп. заголовок).
4. **Порядок закладок:** МАП(+BMS) → КЭС → BMS-сироты; сорт по серийнику; без
   группировки-дерева.
5. **`mbms`:** сразу после своего МАП (см. п.4).
6. **Рендер:** на клиенте (JS), сервер не нагружаем.
7. **`limit`:** 200, фиксирован.
8. **Границы:** кнопки навигации дисейблить.
9. **«Последние данные»:** режим `to` + `limit` от конца БД.
10. **Бинарный контракт** (§10) — между клиентом tsdb и сервисом `malina-tsdb` по
    Unix-сокету (обе стороны наши). Доработка: `read_frame` + `direction` + `limit`
    (описано в `docs/telemetry-store.md` §9/§10).
11. **«Показать»:** запрос `from`-`limit`.
12. **Графики:** история из tsdb; **карточка = предустановленный набор** (§3.2,
    состав — отдельно), имена серий **логические**; несколько метрик одной размерности
    на одном графике; сетка **2 колонки (моб. — 1)**; периоды — как в таблицах,
    **постраничной навигации таблиц нет** (движение по времени — зумом/панорамой);
    источник (`raw`/`avg`) — **автоматически по ширине диапазона** (≤ 20 мин → `raw`,
    иначе `avg`), **без чекбокса**; **прореживания на сервере нет**; рендер — на
    клиенте (Chart.js локально), **эталон вида/интерактива — BMS SunReceiver**
    (§3.4/§3.5: драг-панорама, зум 2 вида, синхронные курсор/хинты, чипы-легенда,
    порядок карточек в `localStorage` по типу устройства, touch-жесты); обновление
    данных — **только по кнопке**; экспорт не нужен.

## 6. Доработка tsdb (сделано)

- `read_frame` (§10): добавлены `direction u8` (`0=from`, `1=to`) и `limit u32`;
  сервер — обратная выборка + ограничение `limit` (включая row-режим с
  разреженным индексом); клиент `lib/tsdbclient` — соответствующие поля.
- **Мета-кадры** `meta_frame`/`meta_reply` (`MTSI`/`MTSO`, §10): `cmd=1` (list) —
  список устройств, `cmd=2` (extremes) — крайние точки; читаются из памяти
  (`Store.series`), без открытия сегментов. Заменяют прежнее сканирование ФС и
  выборку min/max запросами чтения (это и давало ≈5 с на `/api/stats/devices`).
- Эндпоинты UI: `/api/stats/devices` (список), `/api/stats/extremes` (min/max по
  устройству), `/api/stats/table` (страница данных).
- Документация — `docs/telemetry-store.md` (§9/§10/§14); **`docs/stat.md` — только
  контракты полей**, туда не пишем.
