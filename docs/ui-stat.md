# UI статистики (Графики / Таблицы)

**Статус:** **реализовано (MVP)** — tsdb: `direction`/`limit` и мета-запросы
`list`/`extremes` (`docs/telemetry-store.md` §9/§10); страницы `/stats/charts`
(каркас) и `/stats/tables`, API `/api/stats/devices`, `/api/stats/extremes`,
`/api/stats/table`, клиентский рендер `web/assets/static/js/stats.js`, i18n §8 локалей.
Требования ниже — источник истины; «Графики» — наполнение позже.
Связано: `docs/telemetry-store.md` (§9 — режимы чтения, §10 — протокол; там же
доработка `limit`/`direction`), `docs/accumulator.md`, `docs/stat.md` (контракты
полей). UI — шаблоны `web/assets/templates`, i18n `web/assets/i18n/*` (источник
строк — русский; паритет ru/be/zh/en/ka/kk/uz/tg), рендер — **на клиенте**.

## 1. Меню

Верхний пункт **«Статистика»** (`menu.stats`) → 2 подпункта: **«Графики»**
(`menu.charts`, → `/stats/charts`) и **«Таблицы»** (`menu.agg`, → `/stats/tables`).
Ссылки в `layout.html` реализованы.

## 2. Общие требования (обе страницы)

1. Страница открывается с **закладками по имеющимся устройствам**.
2. **Список устройств** — мета-запрос **`list`** к обеим tsdb (raw
   `/run/malina-ts-raw`, avg `/malina/var/malina-ts`); сервер отдаёт устройства
   **из памяти** (без сканирования каталогов/сегментов); объединение по
   `(type, device_id)`.
3. **Крайние точки** статистики (min/max времени) — мета-запрос **`extremes`**
   (из памяти) **точечно по устройству активной закладки**, при её выборе; по
   обеим БД. На закладке **в первой строке** — крайние точки имеющейся статистики
   (первая/последняя запись).
4. **Порядок закладок** (группировки-дерева нет):
   1. **все МАП** (сортировка по серийнику), после каждого МАП — **его BMS**
      (`mbms` с тем же `device_id`), если есть;
   2. затем **все КЭС** (сортировка по серийнику);
   3. затем **BMS-сироты** (`mbms` без своего МАП), если найдены.
   Заголовок каждой закладки — **в одну строку** (закладок может быть много).
5. Наполнение закладок **разное** для «Графиков» и «Таблиц».

## 3. Графики

На MVP наполнение **не реализуем** (каркас страницы/закладок).

## 4. Таблицы

### 4.1. Выбор периода

- **Явный период**: две даты со временем **ИЛИ** «за день» (поле типа «Дата»);
  кнопка **«Показать»** — для первых двух.
- **Быстрые кнопки**: **«24 часа»** (по умолчанию при открытии закладки),
  **«Сегодня»**, **«Вчера»**, **«7 дней»**, **«Месяц»**, **«Последние данные»**
  (хвост БД).

### 4.2. Источник и запрос

- **Переключатель «Детальные данные»** — чекбокс **справа вверху, на уровне
  заголовка** страницы; **по умолчанию выключен** → запрос **только из `avg`**.
  При включении — `raw`+`avg` с приоритетом `raw` (§4.2 ниже). **Изменение
  чекбокса → обновление** текущего представления.
- **Время в UI** — по локали клиента (`navigator.language`), **24-часовой формат**
  (без AM/PM).
- **Обе tsdb**: при перекрытии периодов **приоритет — `raw`** (детально).
  Порядок опроса по направлению:
  - **`from`** (вперёд) — сначала **`avg`**;
  - **`to`** (назад) — сначала **`raw`**, `avg` подключается, если `raw` не
    покрывает (raw хранит **48 ч**; если `to` уходит **дальше 48 ч назад**, в raw
    смысла нет — только `avg`).
- Выборка — **только по устройству активной закладки** за период.
- **Не более 200 строк** (`limit` **фиксирован**, `docs/telemetry-store.md` §9).
- Кнопки периодов и «Показать» — запрос в режиме **`from`-`limit`**.

### 4.3. Таблица и навигация

- Колонки — **по контракту устройства** (`docs/stat.md`); **смена версии
  контракта** в периоде разделяется отдельным **заголовком** (колонка «версия»).
- **MVP:** показываем **сырые** значения. **Целевое:** расшифровка кодов
  (режимы/ошибки) и приведение к правильным **единицам измерения**.
- **Над таблицей** — широкая **рельефная кнопка «Вверх»** (стрелка, не подпись);
  **под таблицей** — **«Вниз»** (рельефная стрелка). Дисейбл — **раздельный**:
  «Вверх» гаснет на верхней границе данных, «Вниз» — **никогда** (см. ниже).
- **«Вверх»** — режим `to` со временем **крайней (верхней)** строки,
  **включительно** (крайняя строка попадает и в новую выборку — перекрытие на одну
  строку, без провала в пустоту). **«Вниз»** — режим `from` от нижней строки, тоже
  включительно.
- **«Вверх»** дисейблится на верхней границе данных; **«Вниз» — никогда не
  дисейблится**: в БД идёт запись, снизу всегда могут появиться новые данные.
- Границы для дисейбла «Вверх» — по **активному источнику**: при выключенных
  «Детальных» — по `avg`, при включённых — по объединению `raw`+`avg`.

## 5. Решения по вопросам

1. **Источник:** обе tsdb; перекрытие → `raw`; порядок опроса по направлению (см.
   §4.2); оговорка raw 48 ч.
2. **Поля:** MVP — сырые; целевое — расшифровка + единицы.
3. **Версии:** разделять (доп. заголовок).
4. **Порядок закладок:** МАП(+BMS) → КЭС → BMS-сироты; сорт по серийнику; без
   группировки-дерева.
5. **`mbms`:** сразу после своего МАП (см. п.4).
6. **Рендер:** на клиенте (JS), сервер не нагружаем.
7. **`limit`:** 200, фиксирован.
8. **Границы:** кнопки навигации дисейблить.
9. **«Последние данные»:** режим `to` + `limit` от конца БД.
10. **Бинарный контракт** (§10) — между клиентом tsdb и сервисом `malina-tsdb` по
    Unix-сокету (обе стороны наши). Доработка: `read_frame` + `direction` + `limit`
    (описано в `docs/telemetry-store.md` §9/§10).
11. **«Показать»:** запрос `from`-`limit`.

## 6. Доработка tsdb (сделано)

- `read_frame` (§10): добавлены `direction u8` (`0=from`, `1=to`) и `limit u32`;
  сервер — обратная выборка + ограничение `limit` (включая row-режим с
  разреженным индексом); клиент `lib/tsdbclient` — соответствующие поля.
- **Мета-кадры** `meta_frame`/`meta_reply` (`MTSI`/`MTSO`, §10): `cmd=1` (list) —
  список устройств, `cmd=2` (extremes) — крайние точки; читаются из памяти
  (`Store.series`), без открытия сегментов. Заменяют прежнее сканирование ФС и
  выборку min/max запросами чтения (это и давало ≈5 с на `/api/stats/devices`).
- Эндпоинты UI: `/api/stats/devices` (список), `/api/stats/extremes` (min/max по
  устройству), `/api/stats/table` (страница данных).
- Документация — `docs/telemetry-store.md` (§9/§10/§14); **`docs/stat.md` — только
  контракты полей**, туда не пишем.
