# МАП: карта читаемой памяти по логическим областям

Разбиение читаемой памяти МАП (Микроарт, Титанатор/Pro/Hybrid/Dominator) на
логические части — для планирования опроса телеметрии и батч-чтения.

Источник: `protocol_MAP_cells_2026_07_15.doc` (+ `protocol_2020_12_29.doc`).

## Область чтения

Читаемая память — **`0x000..0x7FF` (2048 байт)**:

- **EEPROM `0x000..0x3FF`** — идентификация и настройки (энергонезависимые);
- **RAM `0x400..0x7FF`** — телеметрия и текущее состояние (энергозависимые).

Адресация одинакова для нативного протокола и Modbus (байтовые ячейки).
Границы документально подтверждённых ячеек указаны точно; промежутки без
описания помечены «резерв/недокументировано».

## Граница RAM (`_RAM_END`)

Ячейки `_RAM_END_L/H` (`0x08/0x09`) задают конец **документированной** RAM:

```
RAM конец = 0x400 + (_RAM_END_H*256 + _RAM_END_L)
```

Проверено на устройствах:

| Модель | `_RAM_END` | Граница `0x400+RAM_END` |
|---|---|---|
| Титанатор | `0x03A0` | `0x7A0` |
| Доминатор | `0x01E1` | `0x5E1` |

Все **документированные** ячейки модели укладываются в эту границу. `_SoC`/`_SoH`
(`0x718..0x71B`) — **Титанатор-only** (в документе это не помечено — недоработка
документации); у Доминатора за его `RAM_END` там `0xFF`, поэтому **не читаем**.

За границей документированных ячеек описаний нет: данные Титанатора выше
`0x7A0` (до ~`0x11FF`) — служебная/недокументированная область.
**Правило:** читать только известные ячейки; за `0x400+_RAM_END` ничего не
интерпретировать.

## Модель стоимости чтения

По замерам (115200, native): `время ≈ посылки×3.8 мс + байты×0.093 мс`.
- страница 16 Б → 5.3 мс, 64 Б → 9.7 мс, 256 Б → 27.6 мс;
- «мост» через дыру выгоден, если лишних байт < ~41 (≈ цена лишней посылки);
- лимит одной посылки — 256 Б (нативный протокол).

## Оптимальные области чтения (весь набор ячеек за проход)

Задача: за проход прочитать **все документированные** ячейки, минимизируя
`посылки×3.8 + байты×0.093`. Решение — динамическое программирование по
«островкам» ячеек.

### Pro / Hybrid / Dominator — алгоритм общий, определяется эмпирически

Железо у трёх моделей одинаковое (отличается от Титанатора), поэтому алгоритм
чтения для них **общий**. Параметры стоимости снять на реальном железе (пока
предварительно, по документу, без Титанатор-only ячеек и без `_SoC/_SoH`):

| Область | Байт |
|---|---|
| `0x000..0x083` | 132 |
| `0x0D7..0x107` | 49 |
| `0x120..0x127` | 8 |
| `0x138..0x1CE` | 151 |
| `0x400..0x458` | 89 |
| `0x516..0x52E` | 25 |
| `0x582..0x59F` | 30 |

5 из 6 областей совпадают с Титанатором; отличаются: начало EEPROM (у Титанатора
`0x000..0x08A`, здесь `0x000..0x083`) и отсутствие хвоста `0x718..0x71B`.

Выбор алгоритма — по букве модели (`T` → титанаторовский; `P/H/D` → общий).
