# Тип BMS: EnBMS RS485 (PACE ASCII)

**Режим:** активный опрос. **Протокол:** PACE (YD/T 1363), ASCII-hex.
**Скорость:** 19200 8N1. **Вариант:** RS485 (не BLE).
**Топология:** шинная — до нескольких BMS на линии, **`ADR` 0..15** (0 — host,
1..15 — слейвы).

## 2. Транспорт и сигнатура

- Serial (COM) или **TCP-шлюз в режиме `none`** (native) — прозрачный RS485.
- **PACE ASCII:**
  - запрос: `~ VER(2) ADR(2) 46 CID2(2) LEN(4) INFO(hex) CHK(4) CR`;
  - ответ:  `~ VER(2) ADR(2) 46 RTN(2) LEN(4) INFO(hex) CHK(4) CR`;
  - `VER=0x20`; `ADR` — адрес устройства (**0-based**); `RTN=0` — успех;
  - `LENID = len(INFO)` в hex-символах, `LCHKSUM` — 4-бит. дополнение суммы нибблов;
  - `CHK` — 16-бит. дополнение суммы ASCII-кодов от `VER` до конца `INFO`;
  - ответ читается до `CR` (внутри hex-ASCII байта `0x0D` быть не может).
- CID2: **0x42** TeleMeter (телеметрия, 75 Б), **0x44** TeleState (защиты/режим),
  **0x51** BasicInfo (модель ASCII, ≤30 Б).
- **Серийный номер есть:** CID2 **`0xA4` GetBatSN** (host-RS485, 19200, без INFO) →
  30 Б ASCII (напр. `EMU110110S-XXXX-YYMMDD-NNNNN`). Запрос:
  `~ 20 ADR 46 A4 0000 <CHK> CR`; ответ `RTN=00` + 30 Б ASCII. Заводское BLE-имя `BP00`
  не уникально — не использовать.
- **RM485 — вне границ типа.** На RM485 `0xA4` не поддерживается (`RTN=04`), SN не
  читается → по правилу «нет SN — не наша» такой порт даёт `NotMine`. Наш тип —
  **host-RS485** (19200).

## 3. Probe: критерии и сценарий

**Вход — открытый источник** (COM или TCP `none`); транспорт и скорость (19200) задаёт
**оркестратор**. Probe порт не открывает и скорость не меняет.

1. Сканировать **ADR** (0-based, **0..15**): для каждого ADR — CID2 **`0xA4`**
   (GetBatSN), **`0x51`** (модель), **`0x42`** (телеметрия).
2. Проверить кадры: границы `~…CR`, `CHK` сходится, `LENID` = длине INFO, `RTN=0`.
3. **Признание своим:** **`0xA4` вернул валидный 30-байтный ASCII SN** (основной
   признак: «есть серийник — значит наша»), `0x42` разбирается (payload ≥ 67 Б),
   `1 ≤ cell_count ≤ 16`, напряжения ячеек правдоподобны, `soc ≤ 100`, `totalcap` в
   разумных пределах. Ответ по PACE с валидным кадром, но без валидного SN/проверок →
   **NotMine** (общий цикл probe — `docs/bms-reader.md` §2). Никто не ответил →
   **NoAnswer**.
4. Нашли на ADR `a` → **шинный** источник: продолжить `a+1…` до `15` (или до первого
   неответившего) → список слотов.

## 4. Опрос: сценарий (модуль опроса)

Вход — **источник + конкретный слот (ADR)**; модуль опрашивает **один слот** (перебор
слотов — задача пулера, `docs/bms-reader.md` §3). Последовательность команд на слот:

1. **`0x42`** (TeleMeter) → телеметрия → мэппинг в контракт (§5).
2. **`0x44`** (TeleState) → режим/ключи/баланс/`alarm` (§5). Ошибка `0x44` телеметрию
   **не** отбрасывает.

Нет ответа / кадр битый → ретрай (≤ 500 мс); неуспех → модуль возвращает
**«слот потерян»**.

## 5. Мэппинг на общий контракт (`docs/bms-reader.md` §1)

Источник — 0x42 TeleMeter (big-endian); `o` — текущее смещение. Контракт — бинарный
фиксированной длины, макс. 16 ячеек (§1).

| Поле контракта | Источник (0x42), приведение |
|---|---|
| `cell_count` | p[2] (ограничить 16) |
| `cells_mv[i]` | u16 (мВ, как есть) |
| `temp_count` | p[o] |
| `temps_dc[i]` | u16 − 2731 (0.1 °C) |
| `current_da` | −s16 (уже 0.01 А; инверсия знака: разряд +) |
| `total_cv` | u16 (0.01 В) |
| `remaining_mah` | u16 × 10 (0.01 А·ч → мА·ч) |
| `cap_mah` | u16 × 10 (totalcap) |
| `rated_mah` | u16 × 10 |
| `soc_dp` | u16 (0.1 %) |
| `soh_dp` | u16 (0.1 %) |
| `cycles` | u16 |
| `port_cv` | u16 (0.01 В) |
| `power_w` | `total_voltage_v · current_a` (округление) |
| `flags` / `balance_mask` | 0x44 TeleState (ключи; баланс → маска) |
| `mode` | 0x44 `Mode_Byte` → младший байт `mode` (u16) |
| `alarm` | 0x44 → битфилд (см. «Раскладка `alarm`» ниже) |

### Классификация `mode` (0x44 `Mode_Byte`)

| `Mode_Byte` (источник) | → канон `mode` | Режим |
|---|---|---|
| `0x00` | `0x00` | Ожидание |
| `0x01` | `0x01` | Разряд |
| `0x02` | `0x02` | Заряд |
| `0x04` | `0x03` | Поддержание |
| `0x08` | `0x04` | Полный заряд |
| `0x10` | `0x00` | Ожидание (standby) |
| `0x20` | `0x05` | Выключение |

В контракт пишется **канон** (младший байт `mode`); старший — резерв (`0`). Канон —
`docs/bms-reader.md` §1. Вне контракта: `SN` (0xA4) и `model` (0x51) —
только для probe/ID; `keys[]`/`balance_cells[]` (дублируют ядро `flags`/`balance_mask`).

### Раскладка `alarm` (EnBMS)

Поле `alarm` (§1) — 19 Б (152 бита); значимо **147 бит**, остальное `0`. Источник —
0x44 TeleState.

| Биты | Содержимое |
|---|---|
| 0..63 | ячейки: 16 × **4 бита**; на ячейку `[0]` HVwarn, `[1]` OVprot, `[2]` LVwarn, `[3]` UVprot |
| 64..95 | температуры: 8 × **4 бита** (тот же порядок warn/protect) |
| 96..99 | одиночные warn: `[env, power, chargecurrent, customer]` |
| 100..146 | `Ext_Bit` **Byte0..5** (47 бит) в порядке byte/bit |

`Ext_Bit` Byte0..5 → биты `alarm`:
- Byte0 (8) → 100..107; Byte1 → 108..115; Byte2 → 116..123;
- Byte3 → 124..131; Byte4 → 132..139; Byte5 (bits 0..6) → 140..146.

Смысл сигналов Byte0..5 — `protocol-BLE.md` §7 / `protocol-485.md` §6.1. **Не включаем**
(дублируют ядро): Byte6 (ключи), Byte7–8 (балансировка), Byte12, Byte13.
Режим — отдельным полем `mode`.

## 6. Идентификатор

Серийник есть (`0xA4`) → **BASE = `<SN>`** (30 Б ASCII, напр.
`EMU110110S-XXXX-YYMMDD-NNNNN`), при желании с префиксом `EnBMS-`. **Нет SN — это не
наша enbms-rs485** (`NotMine`).

**ID = BASE = SN**, без суффикса `-NNNNN` и без реестра. Одинаковый SN у двух
устройств (клоны) даст один ID и общий ряд tsdb — принятый риск; уникальность BASE
обеспечивает пользователь.
