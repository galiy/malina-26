# BMS-Receiver: UI (меню, страница устройства, главная) — ТЗ

**Статус:** требования согласованы. **Реализация — только по отмашке.**
Связано: `docs/bms-reader.md`, `docs/bms-reader-arch.md`, `docs/mainpage.md`,
`manuals/ui.md`.

## 1. Структура меню

- Пункты **МАП**, **КЭС**, **БМС** — **постоянные** (видны всегда, даже без устройств).
- В каждом — **единая обвязка вставки устройств**: подпункты конкретных устройств
  добавляются **перед** пунктом **«Настройка»** (последний всегда).
- Подпункт устройства → страница конкретного устройства:
  - МАП: `/map?id=<slot>&gen=<gen>`;
  - КЭС: `/kes?id=<slot>&gen=<gen>`;
  - **БМС: `/bms?id=<slot>&gen=<gen>`** (как у map/kes).
- **«Настройка»**:
  - МАП → `/map/settings` — **Включено** + **Уровень логирования** map-reader
    (сохранить → `map-reader.json` + `reload` демона `map-reader`);
  - КЭС → `/kes/settings` — **Включено** + **Уровень логирования** kes-reader
    (сохранить → `kes-reader.json` + `reload` демона `kes-reader`);
  - БМС → `/bms/settings` — таблица IP-шлюзов BMS-Receiver (сохранить→конфиг+reload)
    + рамка **«BMS-Reader»** (Включено / Уровень логирования; сохранить →
    `bms-reader.json` + reload демона `bms-reader`)
    + рамка **«БМС-Прокси»** (Включено / Скорость порта / Уровень логирования /
    Адресация инвертора; сохранить→`bms-proxy.json`+reload демона `bms-proxy`).
- Подпункт **«Монитор» удалить** (пункт, страница `/bms/monitor`, шаблон
  `bms_monitor.html`, обработчик, маршрут, i18n-ключи).
- Порядок: **МАП, КЭС, БМС**, затем **СТАТИСТИКА**, **МАСТЕР-УЗЕЛ** (без изменений).
- Без устройств пункт меню содержит только «Настройка».
- **nav.js**: динамическая подгрузка устройств для всех трёх — МАП (`/api/map/devices`),
  КЭС (`/api/kes/devices`), **БМС (`/api/bms/devices`)** → ссылки на страницы устройств.

## 2. Страница устройства BMS (`/bms?id&gen`)

- Аналог `/map`, `/kes`: каркас; заголовок — **серийник**; закладки скрыты, кроме
  **«Панель»** (Информация/Управление — заглушки, не показываются).
- Источник — `GET /api/bms/raw?id&gen` (бинарь, договор `docs/bms-reader.md` §1),
  декод на клиенте (`bms.js`), пул ~1 с; `bms_type` — из `/api/bms/devices`.
- **Панель**: KPI-плашки (SoC, U сборки/порта, I, P, ёмкость, мин/макс/разн,
  SoH/циклы/режим/номинал), карточки «Ячейки», «Температуры», «Ключи», «Алармы»;
  ниже — графики (общий `stats_charts.js`, режим `window.STATS_FIXED={type:"bms",id}`).
- Авторизация — cookie; i18n — все 8 языков.

### 2.1. Ячейки — сигналы

- Ячейка — «батарейка»: **заливка** по напряжению, цвет заливки — по роли
  (**max** — красный, **min** — синий, прочие — зелёный).
- **Рамка** `cell-batt`: **max** — красная, **min** — синяя.
- **Контур** — отдельный канал сигнала (не мешает рамке max/min):
  - **балансировка** (`bal`) — **янтарный пунктир**;
  - **предупреждение** (`warn`) — **оранжевый**;
  - **защита** (`prot`) — **красный, мигает** (акцент на сработавшей защите).
- Приоритет контура: **защита > предупреждение > балансировка**.
- **Легенда** — в шапке карточки «Ячейки» (балансировка/предупреждение/защита/max/min).
- **Ограничение:** позлементные `warn`/`prot` есть только у **EnBMS-RS485**
  (в контракте **AntBMS-DSP** — только сборные коды заряда/разряда/баланса, без
  позлементных флагов), поэтому на AntBMS контур warn/prot не отображается.
- **Плитка на главной** использует тот же язык сигналов (сервер отдаёт раздельные
  маски `cell_warn_mask` / `cell_prot_mask`, `web/internal/web/bms.go`):
  `cell-prot` (красная рамка + мигание), `cell-warn` (оранжевая рамка),
  `cell-bal` (янтарная рамка), `cell-max`/`cell-min` (цвет цифры).

## 3. Главная страница — раздел «БМС»

- Новый раздел (аналог разделов МАП/КЭС), источник — `/api/mainlist` → блок `bms[]`
  (уже есть: `id`, `gen`, `title`, `type`, `mode`, `soc`, `pack` U/I/P/T, `online`).
- Плитки в стиле МАП/КЭС; клик → `/bms?id&gen`.
- На плитке (на моё усмотрение, далее уточним): **тип** (метка), **заголовок**
  (`тип · serial`), **режим**, **SoC**, **U сборки**, **I**, **P**, **T**, индикатор
  **online/offline**.
- Раздел показывается при наличии устройств (как у МАП/КЭС).

## 4. i18n

- **`menu.bms`**: во всех локалях — перевод (ru — «**БМС**», остальные — по языку).
- Новые строки: закладки «Панель/Информация/Управление», подпись Memo,
  «в разработке» (для заглушек настроек), метки типов/режимов (`bms.type.*`,
  `bms.mode.*` — уже добавлены).
- Паритет ключей во всех 8 языках обязателен (правило проекта).
