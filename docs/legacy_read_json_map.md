# Мэппинг legacy `read_json.php?device=map` → ячейки/контракт МАП

Детальная справка по реверсу старого контракта Малины.

Источник данных старой веб-панели: **`read_json.php?device=map`** — JSON из
System V shm `2015`, который формирует демон **`mapd`**. Ключи JSON соответствуют
ячейкам памяти МАП (`protocol_MAP_cells_2026_07_15.doc`,
`sunReceiver/docs/read_json.md`).

Наш `map-reader` публикует **сырые** ячейки (бинарный контракт `MapData`,
`docs/map-contract.md`). Все вычисляемые величины ниже считаются **на клиенте**
(панель `web/assets/static/map.js`); в контракт/демон они не добавляются.

## 2. Композитный режим `_MODE` (алгоритм)

`mapd` формирует `_MODE` функцией `compound_mode` (дизасм: `0x11e10`). Входы
(передаются из ячеек):

| Арг. | Ячейка | Смысл |
|---|---|---|
| M | `MODE_RAM` 0x400 | базовый режим (0 off,1 off+net,2 генерация,3 трансляция,≥4 заряд) |
| N | `LCD_NETAlg` 0x16B | алгоритм сети: 0 Трансляция+заряд, 1 Только трансляция, 2 ЭКО, 3 Тарифная |
| E | `flag_NETON_ECO` 0x585 | биты: 1 = F_ECO_GenOff, 2 = F_TARIFMIN |
| U | `LCD_NetUpECO` 0x13C | 0 ПринудГенер, 1 Подкачка, 2 Продажа, 255 нет |
| L | `LCD_NetUpLoad` 0x13B | режим подкачки по Pmax |
| V | `UNET` 0x422 | `UNET` (в mapd `+100`, признак «есть сеть» = V>100) |
| P | `Pmax_On` 0x58C | бит1 = Pmax_On_UpLoad |

Алгоритм (эквивалент дизасма):

```
if M <= 1: return M
if M > 3:  return M                 # заряд — код = M
if U == 0:
    if L == 1 and (P & 2) and V > 100: return 18
    if M == 2:
        if V > 100:
            if N == 2: return 10
            if N == 3 and (E & 2) == 0: return 11
            if N == 3: return 12
        return 2
    return 3                        # M==3, U==0
if M == 3:
    if U == 1:
        if N == 2: return (E & 1) ? 15 : 13
        if N == 3: return (E & 2) ? 12 : 16
    if U == 2:
        if N == 2: return (E & 1) ? 15 : 14
        if N == 3: return (E & 2) ? 12 : 17
return M
```

Тексты (индекс → строка; из `locale/RU/local_js.js`, массив `map_mode`):

```
0  МАП выключен и нет сети на входе
1  МАП выключен. Сеть на входе
2  МАП включен. Генерация от АКБ. Нет сети.
3  МАП включен и транслирует сеть
4  МАП включен. Трансляция + заряд
10 Принудительная генерация
11 Тарифная сеть. максимальный тариф. принудительная генерация
12 Тарифная сеть. минимальный тариф
13 Трансляция + эко-подкачка
14 Трансляция + продажа в сеть
15 Ожидание внешнего полного заряда
16 Тарифная сеть. трансляция+эко-подкачка
17 Тарифная сеть. трансляция+продажа в сеть
18 Подкачка Pmax
```

## 3. `_Status_Char` (0x402) — биты состояния заряда

| Бит | Имя | Смысл |
|---|---|---|
| 0 (1) | `ChargeIlow` | заряд малым током (буферный) |
| 1 (2) | `ChargeNeed` | необходим заряд (1-я ступень; вне заряда — «надо заряжать») |
| 2 (4) | `ChargeEnd` | идёт 2-я ступень |
| 3 (8) | `ChargeUmax` | дозаряд постоянным напряжением (3-я ступень) |

Приоритет (для режима заряда): `ChargeIlow` → `ChargeUmax` → `ChargeEnd` → `ChargeNeed`.

**Наша доработка:** при `_MODE > 3` (заряд) код уточняется **точным равенством**
`StatusCh` (не приоритетом битов):

| `_StatusCh` | `_MODE` | Текст |
|---|---|---|
| `0x00` | 4 | …Трансляция |
| `0x01` | 5 | …Буферный заряд |
| `0x02` | 6 | …Заряд 1 ступень |
| `0x04` | 7 | …Заряд 2 ступень |
| `0x08` | 8 | …Дозаряд 3 ступень |
| иное (несколько бит) | 9 | …Режим `<dec> (<bin>)` / «Прочие режимы» |

Зарядные коды — **4..9**. Алгоритм вынесен в общую серверную функцию
`internal/mapmode.Mode` (плоский список по кодам полей), зеркало — в панелях.

## 4. Что `mapd` читает с МАП (сниф COM-порта `.68`)

Поток снят `strace` (fd0 = serial), пробросом UDP на `.9`:

- **Старт:** EEPROM **`0x000..0x0FF`** и **`0x100..0x1FF`** (по 256 Б, один раз).
- **Цикл (~1/с):** RAM **`0x400..0x4FF`** и **`0x500..0x5FF`**.
- Обмен — **побайтовый с эхо** (как у нашего демона), 115200.

## 5. Persisted/внутреннее состояние `mapd` (не ячейки МАП)

---

### 5.1 Файлы энергий (кто и как формирует)

- **`/settings/logs/map_energy.json` — пишет `mapd`.** Формат: строка на сутки
  `YYYY-MM-DD:_E_NET_B:_E_ACC_B:_E_ACC_CHARGE_B:_E_NET_SIGN_B` (дневной снимок
  накопительных счётчиков). Читают/используют также `dbed`/`db_read` (история в БД),
  `mac_collector` (облако), `batmond`.
- Текущие `_E_*_B` в JSON = сегодняшние накопленные значения; `_E_NET/_E_ACC/
  _E_ACC_CHARGE/_E_NET_SIGN` (без `_B`) — **дневные дельты** (за текущие сутки).
- **`/settings/logs/mppt0..3_energy.json`** и **`/var/map/mppt0..3_energy.bin`** —
  пишет **`mpptd`** (MPPT/КЭС). При отсутствии КЭС файлов нет/устарели.
- **`/settings/map/mac_energy_base.bin`** — база энергии для `mac_collector` (облако).
- `wind_mppts` (`/settings/web-data/`) — данные ветряка; без ветряка отсутствует.

Вывод (уточнено реверсом дизасма `mapd`, `all.asm` `0x13bb8`–`0x13f58`):
`_E_NET`/`_E_ACC`/`_E_ACC_CHARGE` — **не интеграция `mapd`**, а прямые счётчики
самого МАП:

| JSON | Ячейка МАП | Формула |
|---|---|---|
| `_E_NET` | `M_POWhourNET_L/H/HH` 0x44D..0x44F | `L + H<<8 + HH<<16` (24-бит) |
| `_E_ACC` | `M_POWhourMAP_L/H/HH` 0x450..0x452 | `L + H<<8 + HH<<16` |
| `_E_ACC_CHARGE` | `M_POWhourMAPCharge_L/H/HH` 0x453..0x455 | `L + H<<8 + HH<<16` |
| `_E_NET_SIGN` | 0x592..0x595 | знаковое 32-бит (`M_POWhourNET_sign` и след.) |

`_E_*_B` = **base + daily**, где `base` — накопитель переполнений/суток. Условие
«фиксации» base: `|_E_NET_SIGN| ≥ 118000`, либо `_E_NET > 236999`, либо
`_E_ACC`/`_E_ACC_CHARGE > 1219999` (и отдельный флаг): тогда `base += daily`,
`daily` сбрасывается, `base` пишется в `/settings/map/mac_energy_base.bin`
(32 Б = 4×int64). У нас файла нет (см. требования §8.3: состояние только в
памяти) → `base` стартует с 0 и теряется при рестарте.

### 5.2 Внутренние поля `mapd`

- **`_Inet_flag`** — внутренний флаг `mapd`, которым он **инвертирует знак**
  `_INET`/`_PNET_calc` в JSON. Это поведение **ошибочно** (флаг не кодирует направление
  мощности) — «грабля», которую мы не повторяем: направление берём по сырой
  `PNET_Sign_P` (0x587). Отдельной формулы в ячейках нет (внутреннее состояние).
- **`_I_acc_avg`** — поле состояния `mapd` (struct+0x68). В цикле обнуляется и
  перезаполняется **только когда ячейка `0x156` ∈ {2,3}** (признак наличия функции
  КЭС); иначе — `0`. На `.68` (с КЭС) было `-3.9`.
- **`_MPPTs_mode`** — поле `mapd` (struct+0x7a), тоже заполняется в блоке при
  `0x156` ∈ {2,3} (из ячейки `0x524`); без КЭС остаётся `0`.
- **Строки КЭС** (`{"MID":…}`/`{"CID":…}`) и пересчёт `_I_mppt_avg`/`_P_mppt_avg`
  также выполняются в этом же блоке (`0x14630`+), т.е. **только при наличии КЭС**;
  у нас КЭС нет → блок пуст, `_I_mppt_avg`/`_P_mppt_avg`/`_MPPTs_mode` = `0`.

Эти поля — внутреннее состояние `mapd` (зависит от накопленного времени/наличия
КЭС, а не от одной ячейки); для нашего демона при отсутствии КЭС они равны `0`.

## 6. Примечания и известные «грабли»

- **Направление сети:** `mapd` определял знак мощности/тока сети некорректно. Мы берём
  направление по сырой ячейке `PNET_Sign_P` (0x587): 1 — потребление, 0 — отдача/продажа.
- **`_fl_UAccChBUF_24h`:** док даёт `0x516`, но реально `mapd` читает **`0x45A`**
  (в контракт добавлена ячейка `fl_UAccChBUF_24h_45A` @0x45A; `0x516` тоже есть).
- **`_TFNET_Limit`:** эмпирика `.68` даёт `2500/raw` (не `6250/raw` из дока).
- Все производные величины считаются **на клиенте** (панель), в контракт демона не
  добавляются.

## 7. Точный формат ответа `mapd` (для реализации `legacy-api`)

Получено из дизасма бинарника `mapd` (`/tmp/kilo/mapd/`, `strings` + `json.asm`).

**Основной объект** — одна строка формата (ключи и типы printf, порядок важен;
все значения — строки):

```
{"timestamp":"%u","time":"%02d:%02d:%02d","_UID":"%lu","_MODE":"%d","_Status_Char":"%d","_Uacc":"%.1f","_Uch_T":"%.1f","_Ubuf_T":"%.1f","_Iacc":"%i","_PLoad":"%i","_PLoad_calc":"%.1f","_F_Acc_Over":"%d","_F_Net_Over":"%d","_UNET":"%i","_INET":"%d","_PNET":"%i","_PNET_calc":"%.1f","_TFNET":"%.1f","_ThFMAP":"%.1f","_UOUTmed":"%i","_TFNET_Limit":"%.1f","_UNET_Limit":"%i","_RSErrSis":"%d","_RSErrJobM":"%d","_RSErrJob":"%d","_RSWarning":"%d","_Temp_Grad0":"%i","_Temp_Grad2":"%i","_INET_16_4":"%.1f","_IAcc_med_A_u16":"%.1f","Temp_off":"%d","_E_NET":"%lu","_E_ACC":"%lu","_E_ACC_CHARGE":"%lu","_E_NET_SIGN":"%ld","_Inet_flag":"%d","_I_acc_avg":"%.1f","_I_mppt_avg":"%.1f","_I2C_Err":"%d","_Temp_Grad1":"%i","_Relay1":"%d","_Relay2":"%d","_Flag_ECO":"%d","_RSErrDop":"%d","_flagUnet2":"%d","_CoolerSpeed":"%d","_MPPTs_mode":"%d","_I_acc_3ph":"%.1f","_I_ph1":"%.1f","_I_ph2":"%.1f","_I_ph3":"%.1f","fw":"%d.%d","_P_mppt_avg":"%i","_P_acc_3ph":"%i","_P_ph1":"%i","_P_ph2":"%i","_P_ph3":"%i","_E_NET_B":"%llu","_E_ACC_B":"%llu","_E_ACC_CHARGE_B":"%llu","_E_NET_SIGN_B":"%lld","_I_MPPT_WIND":"%.1f","_P_MPPT_WIND":"%.0f","_fl_UAccChBUF_24h":"%d"}\n
```

**После основного объекта** `mapd` дописывал блок КЭС (две формы; у нас — только
если КЭС есть у этого МАП). Форматы строк:

- `{"CID":"%d","V":"%.2f","I":"%.2f","t":"%d"},` — индивидуальный КЭС с
  напряжением `V`; `t = сырое − 50`;
- `{"MID":"%d","I":"%.2f","T":"%d"},` — КЭС по агрегатам МАП; `MID = (i/2)+1`.

Блок КЭС (только если КЭС есть у МАП) открывается `[`, строки перечисляются через
запятую, закрывается `]`; далее маркер `#EOF` (реверс `all.asm` `0x146c0`+, `0x14888`).
- `{"MID":"%d","I":"%.2f","T":"%d"},` — по агрегатам МАП: `I` из
  `I_Akb_MPPT_L/H` (0x530+i, `((H&0x7F)*256+L)/16`), `MID=(i/2)+1`, `T` — из
  `Takb_MPPT*` (0x560+); число КЭС задаёт служебный байт у 0x157.
- `{"CID":"%d","V":"%.2f","I":"%.2f","t":"%d"},` — индивидуальный КЭС с `V`
  (данные вне контракта МАП, у нас не опрашиваются).

**Агрегаты КЭС (реверс):** `_I_mppt_avg` = среднее токов КЭС; `_P_mppt_avg =
_Uacc × _I_mppt_avg`; `_MPPTs_mode` — агрегатный режим КЭС. Весь этот блок
(строки КЭС + агрегаты + `_I_acc_avg`) выполняется `mapd` **только при
`0x156` ∈ {2,3}**; при отсутствии КЭС блок отсутствует, а `_I_mppt_avg`,
`_P_mppt_avg`, `_MPPTs_mode`, `_I_acc_avg` = `0` (наш случай).

**Накопители `_E_*`/`_E_*_B`** (реверс `all.asm` `0x13bb8`–`0x13f58`):
`_E_NET/_E_ACC/_E_ACC_CHARGE` = ячейки `M_POWhourNET/MAP/MAPCharge` (24-бит),
`_E_NET_SIGN` = знаковое 32-бит из 0x592..0x595; `_E_*_B` = base + daily (base —
накопитель переполнений, персистится `mapd` в `mac_energy_base.bin`; у нас — в
памяти). Подробности — §5.1.

**Сверено снифером COM-порта `mapd` на `.68` (2026-10-09):** поток `read()` fd0
(побайтовое эхо) разобран по кадрам `o…S` с проверкой контрольной суммы; обе
страницы RAM (`0x400..`, `0x500..`) сопоставлены с живым JSON. Подтверждено:
`_Uacc`, `_Uch_T/_Ubuf_T` (сдвиг `UACC&0x1F`), `_I_phN`/`_I_acc_3ph`/`_P_*`,
`_UNET`(+100), `_INET`, `_INET_16_4=/16`, **`_PNET_calc=_UNET×(0x431/16)`**,
**`_PNET=PNET_8(0x59A)×10`**, `_TFNET`/`_ThFMAP` (6250/V), `_TFNET_Limit` (2500/V),
`_UNET_Limit`/`_UOUTmed` (+100), `_Temp_Grad*`, `_MODE` (композитный),
`_E_*` (ячейки `M_POWhour*`), `_E_NET_SIGN=s32(0x592..0x595)`,
`_Flag_ECO`/`_Relay1/2`/`_flagUnet2`/`_CoolerSpeed`/`_fl_UAccChBUF_24h` (0x45A).
`read_memory.php` (shm 1996) для сверки не годится — отстаёт на циклы.
