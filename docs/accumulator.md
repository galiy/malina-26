# Аккумулятор телеметрии (в составе `malina-web`)

**Статус:** **реализован** (`web/internal/accumulator`, запуск из `malina-web`;
настройка `/malina/etc/malina/accumulator.json`, страница «Параметры»).
Связано: `docs/telemetry-store.md` (§14 — два уровня хранения), `docs/stat.md`
(контракты), `docs/map-reader.md` / `docs/kes-reader.md` (пулеры).

## 1. Назначение

Горутина в составе `malina-web` (не отдельный демон). Усредняет **сырые** снапшоты
устройств из **raw-tsdb** за интервал и пишет **усреднённые** снапшоты в
**persist-tsdb**. Детальные данные остаются в raw (графики свежего периода),
усреднённые — в persist (долгая история).

## 2. Вход / выход

- **Вход:** raw-tsdb (`/run/malina-ts-raw/tsdb.sock`) — за последнее окно усреднения.
- **Выход:** persist-tsdb (`/run/malina-ts/tsdb.sock`) — усреднённые снапшоты.
- **Состав устройств** — «что насыпалось в raw за окно»: берём **из самих raw-данных**
  (устройства, отметившиеся в окне), не из `map-list`/`kes-list`.
- Транспорт — бинарный API tsdb (§10), доступ локальный (Unix-сокет).

## 3. Период и тик

- Период усреднения — **настраиваемый**; **разрешены** кратные минутам: **1, 2, 3, 4, 5,
  6, 10 мин**; **7, 8, 9 и прочие — запрещены** (валидация настройки).
- Окна — **по календарным границам**: для периода `P` окно = `[⌊t/P⌋·P, ⌊t/P⌋·P + P)`.
  Запрос к raw: `from` = начало окна, `to` = начало **следующего** окна **минус 1 мс**
  (минимальный тик) — окна **не перекрываются** (строка ровно на границе не попадёт
  сразу в два окна).
- **Активация** — через **5 с** после начала минуты, следующей за окончанием окна:
  окно `…12:10` → старт в `12:10:05`; забираем окно из raw, усредняем, пишем в persist.
- Обрабатываем ровно прошедшее окно (без «догонов» произвольной длины).

## 4. Алгоритм (по устройству за окно)

1. Прочитать из raw снапшоты устройства за окно (все поля контракта, диапазон по времени).
2. Усреднить поля по правилам §5; **время avg-снапшота = время последнего снимка окна**.
3. Собрать avg-снапшот по контракту `docs/stat.md` (**та же версия**) и записать в persist.
4. Нет данных за окно → **пропуск** (не писать).

## 5. Правила усреднения

- **Измеряемые** поля — **среднее** за окно.
- **Время** avg-снапшота — **последний снимок окна** (§4.2).
- **Дискретные/флаговые** — пофайлово (сквозная нумерация):

| № | Контракт/id | Поле | Кат. | Правило |
|---|---|---|---|---|
| 1 | `map` 11 | `StateUAcc` | С | последнее |
| 2 | `map` 12 | `F_AccOver` | флаги (биты) | **ИЛИ** |
| 3 | `map` 17 | `Temp_off` | маска датчиков | **ИЛИ** |
| 4 | `map` 19 | `MODE_RAM` | С | последнее |
| 5 | `map` 20 | `StatusCh` | маска ступеней заряда | последнее |
| 6 | `map` 21 | `RSErrSis` | битмаска | **ИЛИ** |
| 7 | `map` 22 | `RSErrJobM` | битмаска | **ИЛИ** |
| 8 | `map` 23 | `RSErrJob` | битмаска | **ИЛИ** |
| 9 | `map` 24 | `RSErrDop` | битмаска | **ИЛИ** |
| 10 | `map` 25 | `RSWarning` | битмаска | **ИЛИ** |
| 11 | `map` 26 | `flagUnet2` | биты входов | если в окне активен 2-й вход → 2-й; иначе 1-й/никакой |
| 12 | `kes` 13 | `Mode` | С | последнее |
| 13 | `kes` 14 | `RelayC` | биты | последнее |
| 14 | `kes` 15 | `RSErrSis` | битмаска | **ИЛИ** |
| 15 | `map` 27 | `Relay` (v2) | биты реле | **ИЛИ** |

- `mbms` — среднее по каждой ячейке (число ячеек фиксировано версией `Vn`).
- **Источник раскладок:** `protocol_MAP_cells_*.doc` (производитель МАП) —
  `RSErrSis`/`RSErrJobM`/`RSErrJob`/`RSWarning`/`RSErrDop` описаны как **битовые маски**
  (8 бит); `_Temp_off` — биты наличия/исправности датчиков; `_flagUnet2` — биты входов
  сети. `kes RSErrSis` — множество битовых кодов (`Карта Памяти_MPPT`, `0x3B6`).
- `StatusCh` тоже маска, но выбрано **последнее** (текущее состояние заряда).

## 6. Пропуски / ошибки

- Нет данных за окно у устройства → пропуск (в persist ничего не пишем).
- raw/persist-tsdb недоступны → повтор с backoff + лог; следующее окно.
- Смена числа ячеек `mbms` между окнами (`V8`→`V10`): `n` — число присутствующих ячеек
  BMS в снимке МАП (`docs/map-reader.md`); писать версией по концу окна (или усреднять по
  совпадающим — уточняется).

## 7. Запись в persist

- Через бинарный API tsdb (батч). Версия — как в raw.
- **Retention/лимит у persist нет** — растёт; контроль объёма внешний (§14.3).

## 8. Настройка в `web` (страница «Параметры системы»)

- **Период усреднения** — селект из разрешённых значений (**1, 2, 3, 4, 5, 6, 10 мин**);
  запись настройки в конфиг `web`.
- **Вкл/выкл аккумулятора** (тумблер).
- Изменение периода вступает в силу с ближайшего тика (текущее окно доигрывается).
- Адреса сокетов raw/persist — служебные (не в UI). Страница — по правилам `web`
  (i18n ru/en/zh и т.д.).

## 9. Открытые вопросы

1. Признак «измерение/состояние» для полей контракта (§5) — где хранить.
2. Правило для дискретных полей (последнее/мода/…) — согласовать.
3. Поведение при смешанном окне версий `mbms`.
