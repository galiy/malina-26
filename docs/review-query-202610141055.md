## 1. Проблема, которую решали

Замеры на `.60` (до правок):

| запрос | время | причина |
|---|---|---|
| `/api/stats/devices` | **≈5.03 с** | перечисление обеих tsdb **сканированием ФС** + крайние точки min/max **запросами чтения** по каждому устройству — до ~10 полных сканов row-сегментов |
| `table detail=1 dir=to` | 0.53 с | `readSegmentRow` сканировал сегмент с начала до конца (без индекса и без лимита) |
| `table detail=0` | 0.046 с | (avg, колоночный — ок) |

Дополнительно по ТЗ: крайние точки не должны тянуться по всем устройствам сразу —
только по **активной вкладке**; список устройств — отдельно от границ.

## 2. Принятые решения

1. **Мета-API tsdb `list`/`extremes` из памяти.** Список устройств и `[min,max]`
   отдаёт сам `malina-tsdb` из `Store.series` (границы сегментов уже в памяти) — без
   открытия и сканирования файлов. Список и границы **разделены**: `list` — при
   открытии страницы, `extremes` — точечно на активной вкладке.
2. **row-чтение по разреженному индексу + ранний стоп по `limit`.** Старт с нужной
   `idxEntry` (binary search), для `dirTo` — отступ на `limit` записей назад.
3. **Суточная обрезка avg по свободному месту ФС** (возрастной/объёмный retention у
   avg не задаётся).
4. **UI:** `/api/stats/devices` = список; новый `/api/stats/extremes`; `stats.js`
   запрашивает границы при выборе вкладки.

## 3. Изменения по компонентам

### 3.1. tsdb: режимы чтения `direction`/`limit` (было в ТЗ, реализовано здесь)

- `wire.go`: `read_frame` несёт `direction u8` (0=`from`, 1=`to`) и `limit u32`;
  валидатор отклоняет `direction > 1`.
- `store.go`: `Query{… Direction, Limit}`; обратная выборка `readSegment` (col) —
  чтение блоков с конца, `maxRange`-ограничение применяется только при `limit == 0`.
- `lib/tsdbclient`: `DirectionFrom`/`DirectionTo`, `EncodeReadReq(..., direction, limit)`,
  `Query(..., direction, limit)`.
- Потребители: аккумулятор передаёт `DirectionFrom, 0`; UI — страницы.

### 3.2. tsdb: мета-API `list`/`extremes` (новое)

- `wire.go`: магики `MTSI` (req) / `MTSO` (reply); `metaList=1`, `metaExtremes=2`;
  `decodeMetaReq`, `encodeMetaList` (`count u16 | {type,id}*`),
  `encodeMetaExtremes` (`found u8 | min i64 | max i64`).
- `store.go`: `devMeta{Type,ID}`, `seriesBounds` (min/max по `sealed` + `active`),
  `ListDevices` (пустые серии — все сегменты вычищены — **пропускаются**),
  `Extremes(type,id)`. Оба — под `RLock`, только память.
- `api.go`: dispatch + `doMeta`.
- `lib/tsdbclient`: `DevInfo`, `List()`, `Extremes()`, `readStrAt`.

Контракт — `docs/telemetry-store.md` §10 (`meta_frame`/`meta_reply`).

### 3.3. tsdb: row-чтение (оптимизация)

`row.go::readSegmentRow`:
- старт не с `hdrSize`, а с `ref.entries` (binary search по `FirstTime` относительно
  `q.From`, для `dirTo` — относительно `q.To`); база строки entry восстанавливается
  как `FirstTime − Δt(первой строки по offset)`;
- `dirFrom`: собираем первые `limit` строк и выходим;
- `dirTo`: держим только последние `limit` (сдвиг головы среза) — **отступ на
  `limit/rowK + 1` записей назад**, иначе индекс проскакивал нужное окно (баг
  пойман тестом `TestStoreRowLimitDirection`).

### 3.4. tsdb: суточная очистка avg по свободному месту

- `store.go`: `Options{MinFreeBytes, FreeEvictBytes}`; запуск `freeRetentionLoop`,
  если `MinFreeBytes > 0`.
- `main.go`: флаги `-min-free` (МБ, дефолт 0=выкл.), `-free-evict` (МБ, дефолт 100).
- `retention.go`: `freeRetentionLoop` (сразу при старте + раз в 24 ч),
  `freeSpaceBytes` (`syscall.Statfs`), `sweepFree` — при `free < min-free` удаляет
  старейшие (по `maxTime`) **целые** сегменты, пока не освобождено
  `max(min-free − free, free-evict)`.
- `tsdb.service` (avg): `ExecStart=… -min-free 500`.

### 3.5. web: UI статистики (MVP)

- `internal/web/stats.go` (новый): `statsDevices` (union `list` обеих tsdb, порядок
  МАП(+BMS)→КЭС→BMS-сироты, сорт по серийнику), `statsTable` (приоритет raw в его
  зоне, `detail` — только avg), хендлеры `handleStatsCharts/Tables`,
  `handleAPIStatsDevices`, `handleAPIStatsExtremes`, `handleAPIStatsTable`.
- `server.go`: `Options.Tsdb{RawRoot,RawSock,Sock,AvgRoot}`, маршруты
  `/stats/charts`, `/stats/tables`, `/api/stats/{devices,extremes,table}`,
  регистрация шаблонов.
- `cmd/malina-web/main.go`: флаг `-ts-avg-root` + проброс путей tsdb в `Options`.
- `assets/static/js/stats.js` (новый): клиентский рендер — закладки, периоды,
  чекбокс «Детальные данные», 24-часовое время по локали, «Вверх/Вниз»
  (включительно; «Вниз» никогда не дисейблится), **границы — из `/api/stats/extremes`**.
- `assets/templates/stats_tables.html`, `stats_charts.html` (каркас), `layout.html`
  (меню → `/stats/*`), `app.css` (`.stats-*`; фон кнопок исправлен под светлую тему).
- i18n: ключи `menu.agg`, `stats.*` во всех **8 локалях** (паритет проверен).

### 3.6. контракты (имена полей для UI)

`tscontract.Field` получил `Name`; заданы имена `map` v1 (26), `kes` v1 (15),
`mbms` (`UakbCellN`/`TakbCellN`/`Q_CellN`). `/api/stats/table` отдаёт
`columns:[{id,name,type}]`. **Семантику значений хранилище по-прежнему не знает.**

### 3.7. аккумулятор (краевой случай)

`accumulator.go`: `to = windowEnd − 1 мс` (минимальный тик), чтобы строка ровно на
границе окна не попала сразу в два окна (`docs/accumulator.md` §3).

### 3.8. деплой

`deploy/update.sh`: помимо бинарников — установка unit-файлов tsdb (avg+raw) из
репозитория (короткое `remount,rw /` только под `/etc`), `daemon-reload`. Это нужно,
чтобы новый флаг `-min-free` применился на устройстве.

## 5. Краевые случаи и ограничения (осознанные)

- **`list` из памяти** отражает серии, загруженные при старте tsdb + созданные при
  записи. Внешние изменения каталогов (появились/исчезли без записи) подхватятся
  только после перезапуска tsdb. Для raw (tmpfs, 48 ч) и avg это приемлемо.
- **Пустые серии** (все целые сегменты вычищены) `list` пропускает (`seriesBounds`
  возвращает `ok=false`).
- **row-чтение `to`**: собирает последние `limit` строк сканом вперёд от отступа;
  на практике ограничено ~`limit + 2·rowK` строк.
- **Приоритет raw/avg в таблице** (`docs/ui-stat.md` §4.2) сохранён; оговорка об
  avg-строке на шве (пересекающей `rawMin`) — пренебрежимая для MVP.
- **Мета-кадры `MTSI`/`MTSO`** — аддитивное расширение протокола; сторона клиента и
  сервера общие (обе наши), обратной совместимости со старыми бинарниками нет —
  обновлять надо парой (что и делает `deploy/update.sh`).

# 8. Замечания ревьюера (для разработчика)

Проверено по факту: мета-API `list`/`extremes` из памяти, row-чтение по разреженному
индексу, суточная обрезка avg, UI с чекбоксом «Детальные данные» и `extremes`-API.
Сборка/vet/тесты зелёные; тесты `TestStoreMeta`, `TestStoreRowLimitDirection`,
`TestWireCompatClientServer` покрывают ключевые пути. Блокирующих дефектов нет —
замечания ниже по важности.

## Важные

### R1. `readSegmentRow` при `dirTo` и `limit=0` возвращает неполный диапазон
`daemons/tsdb/row.go:167-185` — при `dirTo` старт = последний `idxEntry` с
`FirstTime <= q.To` (минус отступ **только** при `limit>0`), дальше скан **вперёд**.
При `limit=0` строки в `[q.From, idx.FirstTime)` не читаются — возвращается лишь
хвост от последнего индекса, а не весь `[from,to]`. Это расходится с §9 («to — читать
назад от to к from») и асимметрично col-ветке (`readSegment` честно идёт по блокам
назад). Практической дыры сейчас нет (аккумулятор и UI всегда задают `limit` либо
направление `from`), но контракт нарушен — стоит либо закрыть `dirTo+limit=0`, либо
явно задокументировать ограничение.

### R2. `readSegmentRow` читает сегмент целиком в память
`daemons/tsdb/row.go:156` — `os.ReadFile(ref.path)` на каждый запрос, независимо от
`limit`. Формулировка §5 («на практике ограничено ~limit+2·rowK строк») описывает
**скан**, а не IO: фактически читается весь сегмент. Для raw (tmpfs, `segmax` 1 МБ,
48 ч) это приемлемо, но утверждение документа вводит в заблуждение — поправить
текст, либо читать окно через `ReadAt`.

## Средние

### R3. Гонка границ и первого запроса на вкладке
`web/assets/static/js/stats.js:127-134` — `select()` вызывает `refreshExtremes()`
без `await`, затем сразу `query(...)`. Первый `query` уходит с `rawmin=0`, сервер
делает fallback `Extremes`-запрос (`stats.go:116-119`), а `active.ex` подтягивается
асинхронно после отрисовки таблицы. Работает, но лишний round-trip при каждом
открытии вкладки и визуальный «двойной» проход границ. Рекомендация: `await
refreshExtremes()` перед первым `query`.

### R4. `encodeMetaList` использует `count u16`
`daemons/tsdb/wire.go:205` — число устройств в `meta_reply(list)` ограничено 65535
(`uint16`); при переполнении кадр тихо битый. Нереалистично для ПАК, но как граница
формата (§10) не отражена — стоит зафиксировать в `docs/telemetry-store.md` §10.

### R5. Пустые каталоги сегментов не удаляются
`daemons/tsdb/retention.go` (`retentionSweep`, `sweepFree`) удаляют файлы, но не
подчищают опустевшие `<root>/<type>/<id>/<bucket>/` директории. На длинной дистанции
накапливается мусор в дереве. Косметика, но `list`/`extremes` сканирование не
затрагивают (всё из памяти), так что только ФС-мусор.

## Мелкие

### R6. `sweepFree` занижает `freed` при ошибке `os.Stat`
`retention.go:146-151` — при неудаче `os.Stat` (файл уже удалён) размер не
прибавляется к `freed`, но `os.Remove` вызывается; счётчик «освобождено» может
недобрать и удалить лишний сегмент. Для суточного прохода не критично.

### R7. Кнопка «Вниз» никогда не дисейблится — ТЗ не обновлён
`stats.js:120` — `downBtn.disabled = false` всегда (обосновано: в БД идёт запись).
Это осознанное отклонение от `docs/ui-stat.md` §4.3 («на границах соответствующая
кнопка дисейблится»), но сам §4.3 не скорректирован под новое поведение.

### R8. `handleAPIStatsExtremes` маскирует ошибку tsdb
`web/internal/web/stats.go:237-243` — `ex()` при ошибке `Extremes` возвращает
`{found:false}`, неотличимо от «данных нет». Клиент увидит «—» вместо индикации
сбоя сокета tsdb. Приемлемо для MVP, но сбой хранилища молча скрывается.

## Подтверждено корректным

- Приоритет raw/avg (зона `rawMin`), направление `from`/`to`, `detail` (только avg
  по умолчанию) — согласованы с `docs/ui-stat.md` §4.2/§4.3.
- Отступ `idx -= limit/rowK + 1` и восстановление базы строки из `idxEntry`
  (`row.go:167-185`) — корректны; покрыто `TestStoreRowLimitDirection`.
- Мета-кадры `MTSI`/`MTSO`, кодеки req/reply, CRC, `found/min/max` — симметричны
  (`wire.go` ↔ `tsdbclient`), покрыто `TestWireCompatClientServer`.
- `seriesBounds`/`ListDevices`/`Extremes` — только память под `RLock`, пустые серии
  пропускаются (`store.go:910-961`).
- Суточная обрезка avg: `target = max(min-free − free, free-evict)` (гистерезис),
  удаление только целых (запечатанных) сегментов по `maxTime` — корректно.
- `deploy/update.sh`: rw-окно только под `/etc` для unit-файлов tsdb, `daemon-reload`,
  обновление парами сервер+клиент — корректно.
