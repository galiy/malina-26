Документ содержит **только достоверное**. Источников истины ровно два:
1. **`Карта Памяти_MPPT_WG_2021_01_18.xlsx`** (карта измерений/регистров КЭС).

## 2. Подтверждённые ячейки (источник 2)

Подтверждено экспериментом (эмулятор ↔ монитор `MAP2Gui`):

| Ячейка | Поле | Значение/формула |
|---|---|---|
| `0x00` | `_Device` | `= 5` (КЭС) |
| `0x01` | `Pow` (строка `SUN PowN …`) | значение как есть |
| `0x02` | `Ver ПО` (строка `Ver X.Y`) | `major = v & 0x0F`, `minor = v >> 5` (`0xA8`→`8.5`) |
| `0x05` | Мощность модели (`… Вт`) | Вт = `значение × 100` (`0x32`→5000) |
| `0x9B` | Напряжение модели (`… В`) | В = `значение × 12` (`4`→`48 В`) |
| `0x0C` | **`Pic` и `Модель` одновременно** | фиксировано `= 1` |
| `0x0D` | `Net` | значение как есть |
| `0x2C9` | **Серийник, младший байт** | `ID = eeprom[0x2C9] + eeprom[0x2CA]·256` |
| `0x2CA` | **Серийник, старший байт** | отображается **сырым десятичным** |
| `0x0E3D` | **Команда реле** | запись байта-маски (биты 0/1/2 = реле 1/2/3); подтверждено |

Примеры (проверено): `0x2C9=0x3E, 0x2CA=0x05` → `ID 1342`; `0x2C9=0x52, 0x2CA=0x8E` → `ID 36434`.

**Подтверждено поведение (но адрес ячейки ещё не найден):**
- Задержки реле = `значение × 30 сек`;
- Пороги `T Вкл/Вых`, токи/ёмкость АКБ — реагируют на значения (`0x000..0x1FF`).

Точные адреса этих ячеек — **не подтверждены** (`docs/kes-memory-not-accepted.md`).

## 4. Запись (подтверждено)

### 4.1. Реле
- **Состояние** — `Relay_C` (`0x3E3`), байт: **бит0 = реле1, бит1 = реле2, бит2 = реле3**.
- **Команда** — запись **нового байта-маски в ячейку `0x0E3D`** (изменение сразу всех реле;
  незатронутые биты сохраняются — **read-modify-write**).
  - Алгоритм: прочитать `0x3E3` → выставить/снять нужный бит → записать полученный байт в `0x0E3D`.
  - Если состояние не меняется — запись можно не делать (эквивалентно «уже так»).
- Подтверждено: `relay=1, on` → в устройство уходит байт `0x01` в `0x0E3D`.

### 4.2. Общий путь записи данных
- На **каждую** записываемую ячейку: сначала **команда `3` (`EEPromWR`)** в адрес `0x0000`
  (разрешение записи), затем — **байт(ы) по адресу «как есть»** (без `+0x1F0`, в отличие от чтения).
- Одинаково для **EEPROM** (`<0x400`) и **RAM** (`≥0x400`): разделение — на стороне клиента
  (в контроллер уходит ровно тот адрес, который передал клиент). Пример: за один запрос
  `[[0x200,0x11],[0x201,0x22],[0x2D9,0x01],[0x2DA,0x02]]` → 4 пары «`3` + байт», все адреса как есть.
- **Post-команда не требуется.**
