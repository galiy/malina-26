# malina-arch — резервное копирование raw/avg

**Статус:** требования зафиксированы 2026-10-20. Сервис не реализован.
Связанные документы: `docs/telemetry-store.md`, `docs/grid-reader.md`,
`docs/accumulator.md`, `requirements.md`.

## 1. Назначение

`malina-arch` — единый сервис резервного копирования и восстановления
хранилищ телеметрии:

- **raw** — текущее окно детальных данных на tmpfs;
- **avg** — усреднённая история на `/malina`.

Сервис:

- делает резервную копию **raw** и **avg**;
- восстанавливает **raw** автоматически при загрузке и вручную;
- восстанавливает **avg только вручную** по кнопке «Восстановить обе БД»;
  автоматического восстановления avg при загрузке нет;
- хранит резервную копию на сетевом ресурсе **или** на внешней флэшке;
- обрезает устаревшие данные в резервной копии.

`malina-tsdb-raw` и `malina-tsdb` (avg) не знают про сеть и внешние носители.
Всю работу с резервными копиями выполняет только `malina-arch`.

## 2. Термины

- **raw** — row-хранилище на `/run/malina-ts-raw`, tmpfs 200 МБ.
- **avg** — усреднённое хранилище на `/malina`.
- **архив** — резервная копия на выбранном носителе: сеть или флэшка.
- **пункт назначения (target)** — сетевой ресурс или внешний носитель.
- **run_id** — маркер текущего запуска raw; в архиве одновременно только
  одно состояние.
- **sealed** — запечатанный сегмент raw.
- **active** — текущий незапечатанный сегмент raw.

## 3. Общая архитектура

1. Raw продолжает работать на tmpfs и не пишет на SD.
2. Avg продолжает работать на `/malina`.
3. `malina-arch` — **один общий сервис**. Отдельного сервиса восстановления
   нет.
   Сервис **всегда запущен**; включение/выключение резервного копирования —
   это логическая настройка, а не enable/disable systemd-юнита.
4. У сервиса две фазы:
   - **init** — до старта `malina-tsdb-raw`: доступ к target, восстановление
     raw или фиксация `clean_start`;
   - **archive** — после старта: копирование sealed/active, backup avg,
     обрезка, переинициализация raw-архива.
5. Init-фаза завершается сигналом готовности (`Type=notify` или эквивалент), и
   только после этого стартует `malina-tsdb-raw`. `TimeoutStartSec` у
   `malina-arch` не должен убивать restore; при принятом «restore без
   таймаута» он задаётся явно (например, `infinity`). На shutdown задаётся
   бюджет flush active (например, 20 с), после которого raw считается
   потерянным и архивариус завершается.
6. При остановке порядок: producers → `malina-tsdb-raw` → `malina-arch`
   (flush active). Сеть/флэшка должны оставаться доступными до завершения
   flush.
7. `malina-arch` не пишет на системную SD ни на одном этапе: ни raw, ни avg,
   ни restore, ни проверки. Это относится к системному диску/разделу
   `/malina`. Запись на внешнюю флэшку разрешена — это отдельный носитель.
   Единственное исключение — **ручной restore avg**: он пишет напрямую в
   avg-БД на `/malina` по явной команде оператора, без временных файлов и
   staging.
8. Если резервное копирование выключено настройкой, сервис не обращается к
   target (кроме явного read-only `test`), не делает restore, не копирует и
   не обрезает данные. Он остаётся запущенным, держит control-сокет и спит до
   `reload`/включения.

### 3.1. Порядок остановки

1. Останавливаются producers.
2. `malina-tsdb-raw` переводится в quiesce: сливает writer-очередь и отдаёт
   финальный `committed_offset` через `MTSP/MTSQ` **до** остановки.
3. После получения offset `malina-tsdb-raw` останавливается.
4. `malina-arch` доливает active-сегменты на target до этого offset.
5. Только после завершения flush останавливается `malina-arch`.
6. Если target недоступен или flush не уложился в бюджет, raw помечается
   потерянным в журнале/аудите; записи на SD нет.

## 4. Настройки и пункты назначения

### 4.1. Варианты target

Поддерживаются **два варианта**:

1. **network** — сетевой ресурс;
2. **flash** — внешняя флэшка/USB-накопитель.

Одновременно активен один target. Режим одновременного дублирования
`network + flash` в минимальный объём не входит; архитектура оставляет для
него место отдельным расширением.

### 4.2. Network

Настройки:

- протокол: `sftp` или `smb2` (оба в первой версии);
- хост/адрес и порт;
- путь/ресурс;
- пользователь;
- пароль;
- для SMB2 — домен (если требуется);
- для SFTP — fingerprint host key;
- таймаут получения доступа;
- параметры шифрования/доверенного канала.

Секреты хранятся только в защищённом конфиге на устройстве, не в репозитории
и не возвращаются в UI/API.

### 4.2.1. Сетевые протоколы

**Основной протокол — SFTP over SSH.**

- Логин+пароль.
- Обязательная проверка host key: fingerprint показывается при первом
  подключении и сохраняется после подтверждения оператором. Режим
  `InsecureIgnoreHostKey` не используется.
- Транспорт шифруется SSH.
- Поддерживаются: создание каталогов, запись, `WriteAt(offset)` для
  active/delta, `posix-rename` для атомарного manifest, удаление, `readdir`,
  `stat`.
- Нет kernel-mount, поэтому boot-restore не зависит от поведения CIFS/NFS.

**SMB2/3 — полноценный вариант первой версии.**

- Используется, если сетевой ресурс предоставляет SMB.
- В UI доступен выбор `sftp` / `smb2`; поля SMB2 участвуют в приёмке.
- Логин+пароль, при необходимости domain.
- Шифрование SMB3 — если NAS его поддерживает. Если нет — это принятый риск
  проекта, без отдельного предупреждения в UI.
- Создание каталогов, запись по offset, `stat`/размер, rename-replace,
  delete, readdir — через SMB2-адаптер.

**Не используем:**

- NFS — нет логина/пароля, kernel-mount и риск зависания загрузки;
- WebDAV — нет нормального append для active-сегментов;
- FTP/FTPS — слабый append, нет атомарного manifest;
- S3 — нет append, непригоден для row-сегментов;
- rsync — внешняя зависимость и shell на стороне NAS.

Реализуются оба адаптера: **SFTP** и **SMB2/3**.

### 4.2.2. Операции поверх протокола

- **Sealed:** запись во временное имя `.part`, проверка размера/хеша,
  атомарная замена/rename в финальное имя (SFTP `posix-rename`, SMB2
  rename-replace), атомарное обновление manifest. Если atomic replace
  недоступен — версионирование: `<name>.vNNN`, рядом маркер завершённости и
  хеш; читатель выбирает максимальную валидную версию. То же — для manifest.
- **Active:** `WriteAt(data, committed_offset)`; offset увеличивается в
  manifest только после подтверждения записи. Оборванный хвост не считается
  валидным.
- **Manifest:** временное имя + атомарный rename. При отсутствии
  POSIX-rename — версионирование и явная проверка.
- **Версии manifest и устойчивость к обрыву:** запись идёт как
  `manifest.json.new` → обратное чтение и побайтовая сверка → текущий
  `manifest.json` уходит в `manifest.json.old` → `.new` переименовывается в
  основной. Читатель пробует `manifest.json`, `.old`, `.new` и берёт самый
  свежий валидный по полю `updated`. Так обрыв между двумя rename на сетевой
  ФС не оставляет архив без читаемого описания.
- **Реконструкция manifest:** если все версии невалидны, но каталог
  `files/` доступен, описание восстанавливается сканированием фактических
  файлов (относительный путь → размер) и сразу записывается обратно. Для raw
  в boot-restore принимается новый `run_id`, в фоновой архивации — текущий
  `run_id` сессии (в сегментах он не хранится): разрушенный манифест означает
  пересоздание сессии. Реконструкция выполняется и при boot-restore, и в
  фоновой архивации.
- **Удаление:** в `<target>/<device-id>/raw/...` — по raw-retention; в
  `<target>/<device-id>/avg/...` — только замена старой полной копии и
  удаление orphan-сегментов/незавершённых копий. Удаление вне своего
  namespace запрещено; отсутствие файла — не ошибка.
- **Boot-restore:** прямой SFTP/SMB2-клиент с таймаутом на доступ; без
  kernel-mount; поток сразу в `/run/malina-ts-raw`; без временных файлов на
  системной SD.

### 4.3. Flash

Настройки:

- идентификатор раздела флэшки — **UUID** (метка только для отображения);
  носителей может быть несколько, настраивается конкретный;
- `malina-arch` сам монтирует/размонтирует выбранный раздел в фиксированную
  точку (например, `/run/media/malina-arch`), точка не задаётся в UI;
- при недоступности выбранного раздела — поведение как при недоступной сети;
- контроль свободного места.

Требования:

- это должен быть **внешний** носитель;
- список кандидатов берётся из udev/`/sys/block` по признаку
  `removable=1` и/или отсутствию признаков корневого диска; выбор — по
  UUID (метка только для отображения);
- система должна отвергать системную SD/корневой раздел как target
  (проверка UUID/родительского устройства/точки монтирования `/`);
- при извлечении флэшки сервис помечает target недоступным и не пишет на SD;
- после повторного подключения работа продолжается по общим правилам
  доступности target;
- в init-фазе ожидание появления флэшки ограничено тем же таймаутом доступа,
  что и для сети. Если носитель не найден — `clean_start`; после появления —
  переинициализация raw-архива по §6.2.

### 4.4. Раскладка на target

```
<target>/<device-id>/raw/...
<target>/<device-id>/avg/...
```

- `<device-id>` — уникальный идентификатор ПАК: серийный номер платы
  (`/proc/device-tree/serial-number`), а не `machine-id` (он может быть общим
  для партии/образа).
- Raw и avg разделены: переинициализация raw не удаляет avg.
- Raw-архив хранит одно состояние, без каталогов нескольких сессий.
- Наличие `run_id` в manifest обязательно.

### 4.5. Control-сокет

По аналогии с reader-демонами:

- Unix-сокет: `/run/malina-arch/control.sock`;
- каталог `/run/malina-arch`, сокет `root:<web-group> 0660`;
- JSON-строки, команда в поле `cmd`;
- каркас — `daemons/lib/control`;
- все изменяющие команды (`enable`, `disable`, `cancel`) аудируются с
  uid/pid, target, режимом и результатом; секреты не пишутся;
- сокет доступен и при выключенной настройке, и во время init-фазы
  (restore), чтобы оператор мог посмотреть статус или прервать restore.

Команды:

```json
{"cmd":"ping"}
{"cmd":"status"}
{"cmd":"reload"}
{"cmd":"test"}
{"cmd":"enable","mode":"restore"}
{"cmd":"enable","mode":"reset"}
{"cmd":"disable"}
{"cmd":"cancel"}
```

- `ping` — проверка живости;
- `status` — состояние: `enabled`, target, `phase`, `state`
  (`disabled|restore_required|restoring|restore_failed|enabled|degraded|
  credentials_invalid`), `restored|clean_start`, прогресс restore
  (`current/total`), последняя
  успешная выгрузка, очередь, размер raw/avg-архива, `last_error`,
  `last_avg_backup_at`, `free_space`. Секреты не возвращаются;
- `reload` — перечитать конфиг. Выключение → остановить сетевые операции и
  уснуть. Включение — только через `enable` с выбранным режимом;
- `enable mode=restore` — активировать архивариус с восстановлением архива
  (raw + avg), с остановкой логирования;
- `enable mode=reset` — активировать и **стереть архив**, начать новую
  сессию;
- `disable` — остановить backup/restore и уснуть;
- `cancel` — отменить текущий restore; `malina-arch` очищает частично
  восстановленный tmpfs и частично записанные avg-сегменты, помечает
  `restore_failed/degraded` и даёт raw стартовать пустым;
- `test` — read-only проверка доступа к target **и наличия/валидности
  архива** (для кнопки «Проверить» в UI). Это явное действие оператора:
  разрешено при выключенной настройке, не включает backup/restore и не
  считается работой архивариуса. При найденном валидном архиве состояние
  меняется на `restore_required`.

Web-настройки после сохранения отправляют `reload`/`enable` по сокету.
При включении архивариуса `enable` требует успешного read-only `test` по
control-сокету (он же возвращает наличие/валидность архива). Если валидного
архива нет — включает без диалога и создаёт новую сессию. Если архив есть —
показывает диалог:

- **«Включить с восстановлением из архива»** → `enable mode=restore`;
- **«Включить, стереть архив»** → `enable mode=reset`;
- **«Отменить»** → остаётся выключено.

`cancel`/`disable` во время restore прерывает init-фазу, очищает частично
восстановленный tmpfs и частично записанные avg-сегменты, помечает состояние
`restore_failed` и позволяет `malina-tsdb-raw` стартовать с пустым raw.
Архив на target при этом **не удаляется**: retry остаётся доступен, состояние
`restore_failed/restore_required`. Переинициализация §6.2 выполняется только
для настоящего `clean_start`, а не после cancel. Обычный reboot уже включённого архивариуса — это **дефолтный
запуск** без диалога: автоматически восстанавливается только raw, avg — нет.

### 4.6. Выключенная настройка

Если «Резервная копия БД» выключена:

- `malina-arch` всё равно запущен;
- в `status` состояние — `disabled`;
- target не опрашивается, кроме явного `test`;
- если оператор выполнил `test` и на target найден валидный архив, состояние
  меняется на `restore_required` (это разрешено при выключенной настройке);
- без `test`/проверки target состояние остаётся `disabled`;
- raw **не восстанавливается** из архива: raw стартует пустым/локальным;
- sealed/active не копируются;
- avg не копируется;
- remote-обрезка не выполняется;
- сервис спит и ждёт `reload`.

Включение выключенной настройки выполняется через `test` + `enable`:
если валидного архива нет — `enable mode=reset` без диалога; если архив есть —
диалог WEB:

- `restore` — остановить логирование, восстановить raw и avg из архива,
  принять `run_id`; локальные БД теряются;
- `reset` — удалить старый архив и начать новую сессию;
- «Отменить» — оставить выключено.

Если архив найден, но `restore`/`reset` ещё не выбраны, состояние —
`restore_required`. Архивариус не пишет и не удаляет архив до решения
оператора. Дефолтный запуск при обычном reboot включённого архивариуса
выполняет только автоматический restore raw; avg не восстанавливается.

## 5. Raw: резервное копирование

### 5.1. Sealed-сегменты

- При запечатывании сегмент копируется на target в фоне.
- Копирование не блокирует `malina-tsdb-raw`.
- Ошибки ставятся в очередь повторов.
- Сначала копия записывается, затем проверяются размер/хеш. Только после
  успешной проверки manifest обновляется как commit-точка. При ошибке
  manifest не меняется, сегмент остаётся в очереди повторов.
- Удаление старого сегмента на target идемпотентно.

### 5.2. Active-сегменты

- Копируются **delta/append**, без полной перезаписи.
- Для active-сегмента `malina-tsdb` обязан отдавать durable
  `committed_offset` через новый status/control-кадр в контракте (§10
  `telemetry-store.md`). Копирование «по текущему размеру файла» запрещено.
  Fallback-разбор row-записей без этого кадра не допускается.
- Manifest хранит:
  - `run_id`;
  - идентификатор сегмента;
  - `committed_offset`;
  - размер;
  - хеш/контрольную сумму;
  - признак `active`/`sealed`.
- При обрыве сети удалённая копия может содержать неполный хвост; при
  восстановлении используется только committed prefix.
- На штатном shutdown active-сегменты доливаются.

## 6. Raw: восстановление при старте

### 6.1. Доступ к target есть

1. `malina-arch` пытается получить доступ к target.
2. Таймаут ограничивает **только получение доступа к папке архива**.
3. Если доступ получен и файлы читаются, restore выполняется до полного
   завершения. Таймаута на передачу нет.
4. При обрыве доступа/сети во время restore — повтор до успешного завершения.
   Загрузка raw в это время не начинается.
   Это **осознанное проектное ограничение**: автоматического таймаута на
   передачу нет. Оператор может прервать restore через control-сокет
   (`reload` с выключенной настройкой) — см. §4.5; raw стартует как
   `degraded`.
   Restore-поток обязан быть отменяемым: проверять флаг отмены между
   блоками/чанками и иметь таймаут на отдельную операцию чтения, чтобы
   полуживой target не блокировал обработку `reload` навсегда.
5. Restore пишет напрямую в `/run/malina-ts-raw`.
6. После restore сервис сообщает готовность, затем стартует
   `malina-tsdb-raw`.
7. `run_id` при boot-restore берётся из manifest. Локального `run_id` до
   restore нет. Проверка несовпадения применяется только при работающем
   tsdb (сравнение с in-memory `run_id`); на boot проверяются только
   целостность manifest и его совместимость с сегментами.

### 6.2. Доступа к target нет

1. `init` ждёт target до 60 с (повтор каждые 5 с): сеть на старте может быть
   ещё не готова.
2. Если target так и недоступен:
   - локальный raw очищается (если `malina-tsdb-raw` ещё не работает);
   - `enabled` и настройка `enabled` в конфиге выключаются;
   - сервис отдаёт готовность, raw стартует с пустого tmpfs.
3. Автоматического переподключения и переинициализации архива нет: после
   устранения причины оператор включает копирование заново.
4. Если raw-tsdb уже работал (рестарт архивариуса), локальные данные не
   трогаются, но архивация всё равно выключается до решения оператора.

### 6.3. Архив невалиден

Сначала архивариус пытается пережить порчу манифеста, а не сдаётся:

1. Читаются версии `manifest.json`, `manifest.json.old`,
   `manifest.json.new`; берётся самый свежий валидный (`updated`).
2. Если валидных версий нет, но `files/` читается — манифест
   реконструируется по фактическим файлам и записывается обратно. Для raw
   принимается новый `run_id`, сессия продолжается.
3. Только если и это невозможно (ни одного валидного манифеста и `files/`
   пуст/недоступен), срабатывает аварийный режим:
   - restore не выполняется;
   - raw очищается и стартует пустым;
   - avg не очищается: остаётся текущая локальная БД;
   - архивация и её настройка выключаются (`restore_failed`, `enabled=false`);
   - архив на target не удаляется автоматически.

### 6.4. Архив больше tmpfs

Проектное допущение: архив может временно превышать локальный лимит raw.
Но restore не может записать больше, чем помещается в tmpfs.

Правило:

- restore восстанавливает **самые новые** сегменты до заполнения tmpfs;
- старые сегменты не восстанавливаются;
- сессия помечается `degraded`, пишется предупреждение;
- после старта raw локальный retention обрезает raw;
- затем `malina-arch` обрезает raw-архив на target.

«Обрезать после restore» не отменяет проверку размера: если архив не влезает,
применяется правило выше. Это деградация, а не штатный путь.

### 6.5. Ручное восстановление обеих БД

Ручное восстановление — единственный сценарий, в котором восстанавливается
avg. Оно выполняется по явной команде `enable mode=restore` (кнопка
«Восстановить обе БД»).

Порядок:

1. Проверить доступ к target и валидность manifest/сегментов raw и avg.
2. Preflight: проверить свободное место на `/malina` и в tmpfs с учётом
   **последующей очистки** локальных БД: `нужно ≤ свободно + размер текущего
   avg/raw`. Для raw при переполнении применяется §6.4 (новейшие сегменты).
   При нехватке после очистки — отказ **до** остановки сервисов.
3. Выполнить по явной команде оператора; выбор копии/даты и показ метаданных
   не требуется — восстанавливается последняя полная копия.
4. Остановить producers и приостановить аккумулятор avg. Web-сервер
   `malina-web` **не останавливается** — он показывает прогресс и статус
   restore; останавливается только запись avg. Оркестратор — `malina-arch`
   (через systemd/D-Bus), не WEB.
5. Остановить `malina-tsdb-raw` и `malina-tsdb` (avg).
6. Очистить локальные raw и avg-данные (каталоги данных, не конфиги).
7. Восстановить raw в `/run/malina-ts-raw` (tmpfs).
8. Восстановить avg в `/malina` (единственное разрешённое исключение из
   запрета записи на SD; без temp/staging, сегменты пишутся с проверкой).
   Точка восстановления — последняя полная копия; все sealed-сегменты,
   созданные после неё, и активный сегмент теряются.
9. Запустить в порядке: raw-tsdb → готовность → avg-tsdb → готовность →
   producers → аккумулятор.
10. Принять `run_id` из архива, не переинициализировать его.
11. Возобновить backup.

При ошибке или `cancel` ручного restore:
- локальные raw/avg очищаются;
- все сервисы (tsdb raw/avg, producers) запускаются на **пустых БД**;
- архивариус остаётся **выключенным** (`disabled`);
- в статусе сохраняется причина ошибки; повторный restore — отдельное действие
  оператора.
Producers обязаны быть запущены в любом исходе (успех, ошибка, отмена).
Автоматического rollback нет; повторный restore идемпотентен.

### 6.6. Активация архивариуса после перезаливки

Если ПАК перезалит и архивы уже есть в сети:

1. Backup по умолчанию выключен.
2. Пользователь настраивает и проверяет путь.
3. WEB проверяет наличие валидного архива. Если архива нет — включает
   архивариус без диалога и создаёт новую сессию. Если архив есть — показывает
   выбор:
   - восстановить обе БД (raw и avg заменяются данными архива);
   - стереть архив и начать новый;
   - оставить выключенным.
4. До выбора архивариус находится в `restore_required` и не переинициализирует
   архив.

Это закрывает гонку: старый архив нельзя стирать автоматически только потому,
что tsdb стартовал без restore.

## 7. Raw: обрезка

1. Локальный retention raw работает как обычно.
2. `malina-arch` удаляет на target сегменты, которые больше не нужны по
   политике архива; операция идемпотентна.
3. Обрезка raw-архива работает, когда архив уже инициализирован под текущий
   `run_id`, а локальный raw пуст или не содержит старых sealed-сегментов
   (например, после restore и local retention). Если raw стартовал пустым
   **без restore**, действует не обрезка, а полная переинициализация по
   §6.2 — иначе было бы два разных механизма затирания архива.
4. Обрезка raw не затрагивает каталог avg.
5. При недоступном target удаление откладывается; при появлении доступа
   выполняется до начала новой выгрузки.

### 7.4. Потеря сети при работающей системе

Если сеть пропала на время (например, два часа), но tsdb raw продолжает
работать:

- `run_id` не меняется;
- это **не** `clean_start` и не повод переинициализировать архив;
- запечатанные сегменты за время offline ставятся в очередь;
- после появления сети архивариус догоняет очередь sealed-сегментов, затем
  доливает active delta с `committed_offset`;
- переинициализации нет.

Если локальный retention удалил сегмент до выгрузки, этот сегмент просто не
копируется: архив должен отражать текущее локальное окно, а не хранить
удалённое. Никакого gap-состояния не вводим. Если `run_id` на target не
совпадает с текущим при **работающем** tsdb — архив не перезаписывается
автоматически, требуется решение оператора.

## 8. Avg: резервная копия и ручное восстановление

1. `malina-arch` ведёт **инкрементальное зеркало avg** на target.
2. Запечатанные сегменты копируются по мере появления; активный сегмент
   копируется при graceful shutdown/reboot. Полных копий и истории из N
   суточных копий нет.
3. Manifest avg хранит список файлов, размеры, `committed_offset` активного
   сегмента и хеши. Удалённые локально сегменты удаляются и на target.
3. Автоматического восстановления avg при загрузке нет.
4. Ручное восстановление avg выполняется только в сценарии §6.5
   (`enable mode=restore`), вместе с raw.
5. Резервная копия avg не требует snapshot/export API: запечатанные сегменты
   неизменяемы. Копирование живого активного сегмента не делается.
6. Периодичность — настройка; по умолчанию **не реже одного раза в сутки**.
   Допускается дополнительный запуск по требованию.
7. Резервная копия avg не должна создаваться через временный файл на
   системной SD. Допустимы потоковая передача на target и буфер в tmpfs.
8. На target хранится актуальное инкрементальное зеркало avg. После удаления
   сегмента локальным retention он удаляется и на target. Отдельной истории
   копий нет.
9. Недоступность target не блокирует raw; avg продолжает работать, backup
   avg может отставать и повторяется.
10. `malina-arch` не удаляет avg-архив при переинициализации raw.
11. При ручном restore avg восстанавливается актуальное зеркало avg. Если
    backup был выключен или target недоступен, локальный avg после очистки
    остаётся пустым; архивариус остаётся выключенным.

## 9. UI: страница «Настройки» (Статистика)

Настройки резервного копирования выносятся **не в системные настройки**, а на
новую страницу **«Настройки»** в меню **«Статистика»** — последним пунктом.
Маршрут: `/stats/settings`.

Страница содержит рамку **«Резервная копия БД»**.

Состав:

- выключатель «Резервная копия БД» (по умолчанию выключено);
- выбор target: **сеть** / **флэшка**;
- для сети:
  - протокол: `sftp` / `smb2`;
  - хост/адрес и порт;
  - путь/ресурс;
  - пользователь;
  - пароль (write-only);
  - для SFTP — поле «Ожидаемый fingerprint», кнопка подтверждения;
  - для SMB2 — домен;
  - таймаут доступа;
- для флэшки:
  - выбор раздела по UUID из списка внешних носителей;
  - показывать метку, размер, ФС, removable, свободное место;
  - системная SD в список не включается;
  - статус подключения;
- кнопка проверки доступа target;
- периодичность backup avg (по умолчанию раз в сутки);
- уровень логирования демона: `debug` / `info` / `warn` / `error`
  (по умолчанию `info`; `-debug` форсирует `debug`);
- прогресс restore и кнопка «Отменить восстановление» (`cancel`, только во
  время идущего restore);
- при включении без архива — одна кнопка «Включить копирование»;
- при найденном архиве:
  - «Восстановить обе БД» (raw и avg заменяются данными архива);
  - «Включить, стереть архив»;
  - «Оставить выключенным»;
- ручное восстановление доступно в свёрнутом блоке при включённой архивации;
- статус:
  - последняя успешная выгрузка;
  - очередь/ошибки;
  - размер raw- и avg-архива;
  - текущий `run_id`/состояние (`disabled`, `restore_required`, `restoring`,
    `restore_failed`, `enabled`, `degraded`, `credentials_invalid`);
- пароли/секреты не отображаются после сохранения;
- настройки валидируются: нельзя выбрать системную SD, нельзя сохранить
  неполный network-профиль.

Все новые строки локализуются на ru, be, zh, en, ka, kk, uz, tg. Источник
строк — русский. Пользовательская документация: обновить
`manuals/pages/stats-settings.md` (новая страница «Статистика → Настройки»)
и встроенную справку на всех 8 языках; добавить маппинг `/stats/settings`
в help. Обновить меню «Статистика»: пункт «Настройки» последним.

## 10. Безопасность

- Секреты target хранятся только в защищённом конфиге на устройстве.
- В репозиторий, документацию и логи секреты не попадают.
- Доступ к target — минимально необходимый, только свой namespace.
- `device-id` и пути не должны допускать выхода за пределы namespace.
- UI-настройки доступны только администратору; изменения аудируются без
  записи секретов.

### 10.1. Хранение пароля

- Пароль хранится в `malina-arch.json` в виде AES-256-GCM-шифртекста.
- Ключ — отдельный файл `/malina/etc/malina/arch.key`, `root:root 0600`.
- Ключ генерируется **на устройстве при первом запуске** идемпотентным
  `malina-arch -keygen` (ExecStartPre), а не при сборке образа; в образ и
  репозиторий не попадает. Если ключ утерян/повреждён — статус
  `credentials_invalid`, target не опрашивается, пароль нужно ввести заново.
- В конфиге: версия формата, nonce, ciphertext, AAD.
- nonce — 96 бит из CSPRNG на **каждое** шифрование; повторное использование
  при том же ключе запрещено, при смене пароля создаётся новый nonce.
- AAD детерминированно строится из поля, протокола и версии формата
  (`malina-arch/<protocol>/<field>/v1`) и сверяется с ожидаемым; значение
  AAD из конфига не является доверенным.
- При потере/повреждении ключа — `credentials_invalid`, target не
  опрашивается; пароль нужно ввести заново, ключ перевыпускается процедурой
  provisioning. Генерация `arch.key` описана в deploy/restore, не в рантайме
  архивариуса.
- В UI пароль write-only; после сохранения не отображается.
- В логах/`status` — только `***`.
- Ключ не коммитится, не копируется в образ и не попадает в резервную копию
  конфигурации.
- Это защита от случайного чтения через UI/API/логи и от копии **одного
  конфига** без ключа, но **не от root** и **не от копии всего раздела
  `/malina`/образа SD**: ключ и шифртекст лежат на одном носителе и при
  offline-чтении раздела доступны вместе. Для реальной защиты от чтения
  носителя нужен внешний секрет/TPM; на Raspberry Pi 3 TPM нет.
- `malina-arch` запускается под пользователем, у которого есть чтение
  `arch.key` и avg, и запись на внешний target (в базовой конфигурации —
  root; конкретный `User=` фиксируется в unit при реализации).
- Транспорт шифруется отдельно: SFTP — SSH, SMB2 — SMB3 encryption (если
  включено), WebDAV не используется.
- Для SFTP оператор может **заранее задать ожидаемый fingerprint**, чтобы
  закрыть TOFU-окно первого подключения; если fingerprint задан, он
  сверяется до любых операций.

## 11. Ошибки и деградация

- Target недоступен на boot после 60 с → raw очищается, архивация и
  настройка выключаются; автоматической переинициализации нет.
- Target недоступен на shutdown → active raw не долит; raw теряется
  (network/flash-only, локального snapshot нет).
- Обрыв restore → повтор; при окончательном сбое raw очищается, avg
  сохраняется, архивация и настройка выключаются.
- Restore можно прервать через `reload`/выключение настройки → `degraded`,
  raw стартует пустым (см. §4.5).
- Архив больше tmpfs → частичное восстановление самых новых сегментов,
  `degraded`, затем обрезка.
- Флэшка извлечена → target недоступен, записи на SD нет; после подключения
  работа продолжается по общим правилам.
- Avg backup не блокирует raw; backup avg может отставать и повторяется.
- Потеря сети при работающем tsdb → catch-up очереди; reinit нет.
- После перезаливки найден архив → `restore_required`, без автостирания.
- При автоматическом восстановлении на старте avg восстанавливается только
  если на устройстве нет ни одного avg-сегмента; иначе локальная avg
  сохраняется, а архив продолжается. Явное («Восстановить обе БД») заменяет
  и raw, и avg.

## 12. Критерии приёмки

1. Boot с доступным raw-архивом: restore завершён, `run_id` принят из
   manifest, raw продолжает данные.
2. Boot без target: raw пуст, архивация и настройка выключены; автоматической
   переинициализации и удаления архива нет.
3. Обрыв target во время restore: restore повторяется; при порче/обрыве
   манифеста используется `.old`/`.new` или реконструкция по `files/`; только
   если восстановить описание невозможно — raw очищается, avg остаётся,
   `restore_failed`, `enabled=false`; частичный tmpfs не используется.
4. Архив больше tmpfs: восстановлены самые новые сегменты, `degraded`,
   после старта raw target обрезан. После restore и local retention обрезка
   remote работает и при пустом локальном raw; при старте без restore
   используется переинициализация, а не обрезка.
5. Sealed: одна успешная выгрузка, повторы идемпотентны.
6. Active: delta/append, committed offset, оборванный хвост не читается как
   валидные данные.
7. Shutdown: producers → raw quiesce (финальный committed_offset через
   MTSP/MTSQ) → остановка raw → flush active → остановка архивариуса; при
   недоступном target или превышении бюджета raw помечен потерянным, записи
   на SD нет.
8. Аудит: за цикл raw-restore/archive/trim/avg-backup **нет записи на
   системную SD**; единственное исключение — явный ручной restore avg,
   который пишет avg-БД на SD (без temp/staging).
9. Avg backup содержит полную копию всех запечатанных сегментов; активный
   не копируется (кроме graceful shutdown); есть manifest копии. Автоматический
   restore на старте восстанавливает avg только при полном отсутствии локальных
   сегментов; ручной restore заменяет и raw, и avg.
10. Переинициализация raw не удаляет avg-архив.
11. UI: рамка «Резервная копия БД», оба target, проверка доступа, прогресс
    restore, кнопка отмены, fingerprint SFTP, статусы (включая
    `credentials_invalid`), локализация, секреты не раскрываются.
12. Флэшка: выбор внешнего носителя, отказ от системной SD, корректное
    извлечение/подключение; проверка свободного места перед записью; при
    нехватке — ошибка без записи на SD.
13. Avg: инкрементальное зеркало; sealed по мере запечатывания, active при
    graceful shutdown/reboot; snapshot/export API не требуется.
14. Выключенная настройка: сервис active, target не опрашивается, кроме
    явного read-only `test`; raw не восстанавливается, копирования нет;
    `ping`/`status`/`reload`/`test` работают.
15. Включение после `clean_start`: raw-архив переинициализирован, avg-архив
    не тронут.
16. SFTP: host key подтверждён и проверяется, пароль не возвращается в UI,
    sealed/active/manifest/delete работают по требованиям §4.2.2.
17. SMB2: логин+пароль/домен, mkdir, запись по offset, rename, delete, stat;
    SMB3-шифрование используется, если доступно; отдельного предупреждения
    при его отсутствии нет.
18. В конфиге нет открытого пароля; ключ устройства отсутствует в образе и
    репозитории.
19. Активация после перезаливки: диалог restore/reset/cancel; до выбора
    состояние `restore_required`, архив не стирается.
20. Ручной restore обеих БД: preflight свободного места; логирование
    остановлено; восстанавливаются raw и avg; producers подняты в любом
    исходе; при сбое raw и avg очищаются, архивация и настройка выключаются;
    `run_id` принят.
21. Потеря сети на 2 часа при работающем tsdb: sealed-очередь догоняется,
    active delta доливается, reinit нет.

## 13. Вне рамок

- Автоматическое восстановление avg при загрузке (ручное — в объёме).
- Полная история raw на target.
- Локальный snapshot raw на системной SD.
