# «Менеджер событий» (наш, на malina-web) — требования

Статус: **идёт согласование требований**, к реализации не приступаем.
Разбор legacy — `docs/legacy/event-manager.md`.

## 1. Что делаем

Порт legacy-«Менеджера событий» (`emd` + веб-редактор) **с полным рефакторингом**:
движок правил внутри `malina-web` (Go), без Perl-демона, без legacy-API.
Текущая логика должна поддерживаться: правило = «если параметр устройства по условию →
выполнить действие», оценка раз в 2 c, фронт условия + «Ok».

## 2. Область (согласовано)

- **Источники событий: только МАП** (и запланированный **КЭС/MPPT**).
- **BATMON и зарядник — исключаем** (ни источников, ни событий).
- **MPPT (КЭС): только заготовки/заглушки** — поля и действия заведём, но обработка
  КЭС пока не реализована.
- **У нас может быть много МАП и КЭС** (в legacy — один МАП). Поэтому обязательное поле
  правила — **серийный номер устройства-источника** (МАП или КЭС).
- Действия — **все**: E-mail, реле ON/OFF, «стоп генерации»/«стоп»/«старт» МАП,
  **SNMP-trap**.
- **Кросс-действие**: по событию одного МАП можно управлять **реле другого МАП или КЭС**.

## 3. Модель устройств и реле

| Устройство | Реле |
|---|---|
| МАП «Доминатор» | 2 |
| МАП «Титанатор» | 3 |
| КЭС (каждый) | 3 |

Число реле зависит от модели → UI и валидация зависят от модели устройства.

## 4. Наблюдаемые поля

- **МАП** — из нашего снимка (по именам полей, не индексами). Режим вычисляется
  **единой серверной функцией** (общая для legacy-API и менеджера событий — один источник
  правды), из полей `MODE_RAM`/`LCD_NETAlg`/`flag_NETON_ECO`/`LCD_NetUpECO`/
  `LCD_NetUpLoad`/`Pmax_On`/`UNET`. Алгоритм — как в панели 1 (`modeNum`),
  `legacy-API` **не вызываем** — берём общую функцию напрямую. Далее по тексту:
  `_UNET`, `_INET_16_4`, `_PNET_calc`, `_Uacc`, `_PLoad`, `_IAcc_med_A_u16`, `_E_NET`,
  `_E_ACC`, `_E_ACC_CHARGE`, `_I_mppt_avg`, `_Temp_Grad2` (МАП), `_Temp_Grad0` (АКБ),
  `_P_mppt_avg`, а также служебные **TIME** (`HH:MM`) и **MODE** (равенство режиму).
  Для MODE: значение — **режим в том виде, как его показывает панель 1** (вычисляемый
  режим), подписи берём из **тех же i18n-ключей `p1.modeN`, что и панель 1** (локализованы
  ru/be/zh/en). Не дублируем legacy-список.
- **КЭС/MPPT** — заготовка (набор полей определим, когда появится источник).
- **Серийник** источника/получателя — из **нашего снимка** (`SerialNum0`/`SerialNum1`
  из публикации `map-reader`; числовой, **без буквы**). Позже `kes-reader` даст свой
  список (для заглушек). Legacy-API не используем.

## 5. Модель правила (наш формат)

```json
{
  "version": 1,
  "events": [
    {
      "id": "a1b2c3d4",
      "enabled": true,
      "source":   { "kind": "map", "serial": "37005" },
      "mppt_no": 1,
      "field": "_UNET",
      "op": "le",
      "value": "180",
      "cooldown": 30,
      "action": "relay_on",
      "target": { "kind": "map", "serial": "37012" },
      "relay": 2,
      "trap_host": ""
    }
  ]
}
```

- `source.serial` — **обязателен** (серийник МАП/КЭС-источника, числовой).
- `field` — **имя** параметра; `op` — `le|ge|eq|ne|time|mode`; `value` — порог/`HH:MM`/код режима.
- `action` — `email|relay_on|relay_off|mac_stop_gen|mac_stop|mac_start|snmp`.
- `target` — устройство-получатель действия: поля **«Тип устройства (МАП/КЭС)» и
  «Серийный номер» — необязательные**; **если не заполнено — действие применяется к
  текущему (источнику)**. Реле допускается включать на **другом** МАП/КЭС.
  В интерфейсе серийник target выбирается **из выпадающего списка** (устройства, видимые
  хостом) **либо вводится вручную**.
- `relay` — номер реле (МАП: 2 у Доминатора, 3 у Титанатора; КЭС: 3),
  `trap_host` — IP приёмника trap.
- **Кулдаун — настраиваемый на каждое правило**, по умолчанию **30 c**: после срабатывания
  правило **не проверяем** заданное время (чтобы соседнее правило успело вернуть состояние
  и реле не «щёлкало» каждые 2 c).

## 6. Логика срабатывания

- Оценка правил — фоном, **раз в 2 c**.
- Фронт: условие стало истинным (после кулдауна) → выполнить действие; условие вернулось
  в норму → сбросить состояние и (для E-mail/trap) уведомление «Ok».
- Действия по «нашему» стеку:
  - **Режим (MODE)** — **общая серверная функция** вычисления режима (единственный
    источник правды), используется и `legacy-API`, и движком событий. Клиент считает
    сам (получает бинарное сырьё) — дублирование на клиенте осознанное;
  - **E-mail** → наш `mailer` (`SendText`/`SendHTML`, через аутбокс);
  - **Реле / МАП-команды** → через наш `control.sock` (запись в МАП), без очередей/EEPROM;
  - **SNMP-trap** → v2c на `trap_host`, **та же OID-схема MICROART-MIB**
    (OID параметра + значение с множителем + номер MPPT), чтобы существующие приёмники
    trap продолжали работать как раньше.

## 7. Логирование

- История на странице **не нужна**.
- **Все срабатывания и действия пишем в лог** — **отдельный лог на `.253`** (как
  ключевые события веб, но своей темой/тегом → отдельный файл), с результатом действия.
  Реализация — по образцу аудита web (отдельный syslog-тег → отдельный файл на log-хосте).

## 8. UI

- Пункт **Система → Менеджер событий**, страница `/system/events`.
- Таблица правил: устройство-источник (по серийнику), поле, условие, значение,
  действие, устройство-получатель, реле, IP trap; добавить/удалить/сохранить/очистить.
- Поля/операции/действия — по наличию и модели устройств.
- **Локализация ru/be/zh/en.**

## 9. Конфиг/движок

- Конфиг: **`/malina/etc/malina/events.json`** (свой версионированный формат).
- Состояние `trigger`/кулдаун — в памяти; рестарт сервиса — сброс (как legacy).

## 10. Не делаем

- BATMON и зарядник (источники/события).
- Реализацию КЭС-источника сейчас (только заглушки).
- Историю срабатываний на странице.
- Legacy-shm/очереди/EEROM/ssmtp/SIGUSR1/`events.parsed`.

## 11. Статус

Все вопросы закрыты. Открытых нет.

Итог:
- target — необязательный (пусто → текущее устройство), допускается кросс-устройство (реле);
  серийник numeric из `map-list`, в UI — список + ручной ввод;
- SNMP-trap — **та же OID-схема MICROART-MIB**;
- **TIME и MODE**-события — **в первой версии** (для МАП); MODE — **единая серверная
  функция** (общая с legacy-API), подписи из ключей `p1.modeN` (ru/be/zh/en);
  клиент считает сам (бинарное сырьё);
- кулдаун настраиваемый на правило (по умолчанию 30 c); КЭС — заглушки; BATMON/зарядник исключены;
- отдельный лог срабатываний/действий на `.253`.

К реализации **не приступаем** — ждём отдельного согласования.
