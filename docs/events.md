# «Менеджер событий» (наш, на malina-web) — требования

Статус: **реализовано** (движок, UI, E-mail, реле/команды МАП, SNMP-trap; источник КЭС).
Разбор legacy — `docs/legacy/event-manager.md`.

## 1. Что делаем

Порт legacy-«Менеджера событий» (`emd` + веб-редактор) **с полным рефакторингом**:
движок правил внутри `malina-web` (Go), без Perl-демона, без legacy-API.
Текущая логика должна поддерживаться: правило = «если параметр устройства по условию →
выполнить действие», оценка раз в 30 c, фронт условия + «Ok».

## 2. Область (согласовано)

- **Источники событий: МАП и КЭС** (MPPT/BMS — нет).
- **BATMON и зарядник — исключаем** (ни источников, ни событий).
- **КЭС: источник реализован** — снимок берётся из `kes-reader` (shm `kes-list` +
  слот `KESE/KESR/KESS`), параметры — `events.ParamsKes` (§4). Режим КЭС
  (`MODE`-события) не поддержан; действия на КЭС (реле/команды) требуют
  подтверждения на железе (§11).
- **У нас может быть много МАП и КЭС** (в legacy — один МАП). Поэтому обязательное поле
  правила — **серийный номер устройства-источника** (МАП или КЭС).
- Действия — **все**: E-mail, реле ON/OFF, «стоп генерации»/«стоп»/«старт» МАП,
  **SNMP-trap**.
- **Кросс-действие**: по событию одного МАП можно управлять **реле другого МАП или КЭС**.

## 3. Модель устройств и реле

| Устройство | Реле |
|---|---|
| МАП «Доминатор» | 2 |
| МАП «Титанатор» | 3 |
| КЭС (каждый) | 3 |

Число реле зависит от модели → UI и валидация зависят от модели устройства.

## 4. Наблюдаемые поля

- **Тип события** (явное поле, первый селектор в строке):
  - **`param`** — числовое сравнение (`≤/≥/=/≠`), **есть обратное действие** («Ok»);
  - **`time`** — срабатывание в заданное `HH:MM`, **без обратного действия**;
  - **`mode`** — равенство режиму МАП, **без обратного действия**.
- **Курированный список параметров (МАП)** — с **человеческими подписями** (ru/be/zh/en/ka/kk/uz/tg),
  а не сырыми именами ячеек:

  | № | Подпись | Помощь |
  |---|---|---|
  | 1 | Напряжение сети | `UNET` |
  | 2 | Ток сети | `INET_16_4`/`INET` |
  | 3 | Мощность сети | `PNET_L`/`PNET_H` |
  | 4 | Напряжение АКБ | `UACC` |
  | 5 | Ток АКБ | вычисл. (L/H) |
  | 6 | **Мощность АКБ** (по факту) | вычисл. (L/H) |
  | 7 | Ток MPPT/ветряка | вычисл. |
  | 8 | Мощность MPPT/ветряка | вычисл. |
  | 9 | Температура МАП | `Temp_Grad2` |
  | 10 | Температура АКБ | `Temp_Grad0` |
  | 11 | Температура 1 | `Temp_Grad1` |

  **Энергии** (`E_NET`/`E_ACC`/`E_ACC_CHARGE`) **убраны**.

  Значения параметров приводятся к **человеческим единицам** единым слоем
  `web/internal/measure` (общим с **UI статистики**, эталон — панель 1 `map.js`), и
  **порог правила** (`value`) задаётся в тех же единицах:
  - `unet` = `UNET+100` В (0 — нет сети);
  - `inet` = `INET_16_4 / (INET≥16 ? 4 : 16)` А;
  - `pnet` = `(PNET_L + PNET_H·256)·100` Вт;
  - `uacc` = `(UAcc_med_VH·256 + UAcc_med_VL)/10` В;
  - `iacc` = `(L+H·256)/16` А, **знак по режиму** (заряд → «+», `MODE_RAM>3`);
  - `pacc` = `(PLoad_L + PLoad_H·256)·100` Вт;
  - `tmap`/`tbat`/`t1` = `Temp_Grad2/0/1 − 50` °C;
  - `imppt` — среднее `(L+(H&0x7F)·256)/16` А по активным MPPT; `pmppt` = `uacc·imppt` Вт.

  > **Изменение формул (2026-10-14).** `inet`, `iacc`, `pnet` приведены к общему слою
  > `web/internal/measure` (эталон — панель 1), и **результат изменился**:
  > `inet` = `INET_16_4/(INET≥16 ? 4 : 16)` (было `/16`), `iacc` — **со знаком** по
  > режиму (было без знака), `pnet` = `(PNET_L+PNET_H·256)·100` (было `PNET_8·10`).
  > **Пороги правил** (`events.json`) задаются в тех же единицах, поэтому при наличии
  > сконфигурированных правил их `value` нужно **перепроверить/мигрировать**; на
  > 2026-10-14 действующих правил нет (`events.json` пуст).
  > `uacc`/`pacc`/`imppt`/`tmap`/`tbat`/`t1` — без изменения результата.
- **MODE**: значение — режим как в панели 1 (общая серверная функция), подписи `p1.modeN`
  (`0..18`, в т.ч. зарядные `4..9`; для `9` в списке — статический текст «…Прочие режимы»,
  в панели `9` — динамический «…Режим <dec> (<bin>)»); обратного действия нет.
- **КЭС** — реализован: `events.ParamsKes` (ключи `k_*`), значения из снимка КЭС
  (`kesSnapFields`), единицы — через `measure` (`k_vcpv/k_icpv/k_vbat/k_ich/k_iout` —
  `÷100`; `k_ppv/k_pout/k_pload/k_pcurr` — Вт; `k_tint/k_tbat` — `−50` °C;
  `k_windspeed` — как есть; `k_mode` — код). Режим КЭС (`MODE`-события) — только МАП.
- **Невалидные серийники**: устройства с серийником **0** и **0xFFFF (65535)** в списках
  **игнорируем** (как будто их там нет) — и в источнике, и в target, и в выпадающих списках.
- **Серийник** источника/получателя — числовой, **без буквы**, **2 байта** (`uint16`,
  little-endian: `SerialNum0` мл. + `SerialNum1` ст.). Буква индекса — отдельный байт
  (`SerialNum3`), в событиях не используется. Серийник **КЭС** — `UID` из `kes-list`
  (`kes-reader`); список серийников в UI — по типу источника (`EV_SERIALS`). Legacy-API не используем.

## 5. Модель правила (наш формат)

```json
{
  "version": 1,
  "events": [
    {
      "id": "a1b2c3d4",
      "enabled": true,
      "type": "param",
      "source":   { "kind": "map", "serial": "37005" },
      "mppt_no": 1,
      "field": "unet",
      "op": "le",
      "value": "180",
      "cooldown": 30,
      "action": "relay2_on",
      "target": { "kind": "map", "serial": "37012" },
      "recipient": "",
      "trap_host": ""
    }
  ]
}
```

- `type` — **`param|time|mode`** (тип события; для `param` используется `op`+`value`,
  для `time` — `value` как `HH:MM`, для `mode` — `value` как код режима).
- `field` — **ключ из курированного списка** (не сырое имя ячейки).
- **Идентификация и состояние**: правило адресуется **стабильным `id` (8 hex)**;
  состояние привязано к `id`, а не к позиции в списке (в legacy — по номеру,
  из-за чего состояние «съезжало»). Вставка/удаление/перестановка правил состояние
  остальных не сбивают; дубли `id` запрещены. При **изменении содержания** правила
  (источник/поле/условие/значение/действие/target/реле) состояние **сбрасывается**;
  состояния удалённых правил **чистятся** при перечитке конфига.
- **Хранение состояния — tmpfs**: `/dev/shm/malina-events/state.json` (переживает
  рестарт сервиса, теряется при ребуте хоста). Пишется при изменениях
  (срабатывание/сброс/правка/чистка), читается при старте.
- `source.serial` — **обязателен** (серийник МАП/КЭС-источника, числовой).
- `field` — **имя** параметра; `op` — `le|ge|eq|ne|time|mode`; `value` — порог/`HH:MM`/код режима.
- `action` — **`email`**, **6 команд реле** (`relay1_on|relay1_off|relay2_on|relay2_off|
  relay3_on|relay3_off`), команды МАП (`mac_stop_gen|mac_stop|mac_start`), `snmp`.
  Номер реле **зашит в команду** — отдельного поля «реле» нет. Реле действует на
  **устройство-источник**.
- `target` — устройство-получатель для **реле и команд МАП**; поля «Тип» и «Серийник»
  необязательные (пусто → источник). В UI — выпадающий список видимых устройств + ручной
  ввод. Показывается только для действий реле/команд МАП.
- `recipient` — адрес получателя для **`email`** (опционально; пусто → подпись поля
  «адрес получателя из настроек» E-Mail). Поле видно только для `email`.
- `trap_host` — IP приёмника trap, виден **только** для действия `snmp`.
- **Кулдаун — настраиваемый на каждое правило**, по умолчанию **30 c**: после срабатывания
  правило **не проверяем** заданное время (чтобы соседнее правило успело вернуть состояние
  и реле не «щёлкало» каждые 2 c).

## 6. Логика срабатывания

- Оценка правил — фоном, **раз в 30 c** (период `DefaultInterval`).
- **`param`**: фронт — условие истинно (после кулдауна) → действие; ложно → сброс и
  (для E-mail/SNMP) «Ok».
- **`mode`**: срабатывание при равенстве режима; обратного действия **нет**.
- **`time`**: специализированный контрол ввода времени; «своя» логика кулдауна —
  **23 ч 59 мин** (фактически раз в сутки); обратного действия **нет**;
  **состояние на старте — «уже сработало»** (не срабатывает сразу при запуске).
- Событие с действием **`mac_stop_gen`** при старте тоже получает состояние «уже
  сработало» (не срабатывает сразу).
- **Устройство не найдено**: если серийник **источника** (или заданного **target**)
  отсутствует в списке устройств (МАП/КЭС), событие **игнорируем**, а пару
  `тип:серийник` кладём в **локальный блэклист с TTL 1 минута** — чтобы больше не лезть
  в shm до протухания. Серийник — числовой, **без буквы**.
- Действия по «нашему» стеку:
  - **Режим (MODE)** — **общая серверная функция** вычисления режима (единственный
    источник правды), используется и `legacy-API`, и движком событий. Клиент считает
    сам (получает бинарное сырьё) — дублирование на клиенте осознанное;
  - **E-mail** → наш `mailer` (`SendText`/`SendHTML`, через аутбокс);
  - **Реле МАП** → **read-modify-write** регистра `0x586` (`Status_RELEdop`) как на
    странице управления МАП: читаем текущий байт, меняем бит `1<<(relay-1)`, пишем
     целый байт (второе реле сохраняет состояние). Реле КЭС — до подтверждения на железе (§11);
  - **МАП-команды** → `control.sock`: `mac_stop`=`cmd 01` (OFF), `mac_start`=`cmd 02`
    (ON), `mac_stop_gen`=`cmd 09` (DischOff) **только при `fw≥26`** (`VerPO&0x1F`);
    на прошивках `<26` команду **игнорируем**;
  - **SNMP-trap** → v2c на `trap_host`, OID-схема MICROART-MIB (пока `не реализовано`,
    нужен MIB/числовые OID — см. §11).

## 7. Логирование

- История на странице **не нужна**.
- **Все срабатывания и действия пишем в лог** — **отдельный лог на `.253`** (как
  ключевые события веб, но своей темой/тегом → отдельный файл), с результатом действия.
  Реализация — по образцу аудита web (отдельный syslog-тег → отдельный файл на log-хосте).

## 8. UI

- Пункт **Система → Менеджер событий**, страница `/system/events`.
- Таблица правил: устройство-источник (по серийнику), поле, условие, значение,
  действие, устройство-получатель, реле, IP trap; добавить/удалить/сохранить/очистить.
- Поля/операции/действия — по наличию и модели устройств.
- **Локализация ru/be/zh/en/ka/kk/uz/tg.**

## 9. Конфиг/движок

- Конфиг: **`/malina/etc/malina/events.json`** (свой версионированный формат).
- Состояние `trigger`/кулдаун — в памяти; рестарт сервиса — сброс (как legacy).

## 10. Не делаем

- BATMON и зарядник (источники/события).
- Действия на КЭС (реле/команды) — до подтверждения на железе.
- Историю срабатываний на странице.
- Legacy-shm/очереди/EEROM/ssmtp/SIGUSR1/`events.parsed`.

## 11. КЭС: реализовано и остаётся

Источник КЭС **реализован** (`kes-reader` → shm `kes-list`/`KESE/KESR/KESS` →
`kesSnapshot` → `events.ParamsKes`). Осталось (требует подтверждения на железе):

| # | Пункт | Состояние | Что нужно |
|---|---|---|---|
| 1 | **Источник данных КЭС** | ✅ `kesSnapshot` (снимок из `kes-reader`) | — |
| 1a | **Параметры КЭС** | ✅ `events.ParamsKes` (13 параметров, `k_*`; единицы через `measure`) | — |
| 2 | **Поля КЭС в UI** | ✅ `optgroup` по типу источника (`map`/`kes`) | — |
| 3 | **Серийник КЭС** | ✅ `kes-list` (`UID`), список в UI по типу (`EV_SERIALS`) | — |
| 4 | **Реле КЭС (3 шт)** | ⛔ `eventsActions.Relay(kind="kes")` → `errNotImpl` | **известно:** состояние — `Relay_C` 0x3E3, биты 0/1/2 = реле 1/2/3; legacy-запись — ячейка `0x0E3D` (кандидат, в карте не описана) — подтвердить на железе |
| 5 | **Команды КЭС** | ⛔ `MacCmd(kind="kes")` → `errNotImpl` | есть ли у КЭС команды управления и их коды/транспорт |
| 6 | **Режим КЭС (MODE-события)** | ⛔ `mapmode` — только МАП | алгоритм/коды режимов КЭС и подписи |
| 7 | **SNMP-trap для КЭС** | ⛔ `SNMPTrap` → `errNotImpl` | OID-схема (MICROART-MIB) или числовые OID |

Общий (не только КЭС) незавершённый пункт: подтверждение раскладки бит реле МАП.

## 12. Статус

Реализация: движок, конфиг, общая функция MODE, действие **E-mail**,
**реле МАП** (RMW `0x586`) и **МАП-команды** (`01/02`, стоп-генерации `09` при `fw≥26`);
логирование отдельным тегом. **SNMP-trap** — **реализовано** (v2c, community `public`,
порт 162, OID-схема MICROART-MIB, множители ×10/×100 + номер MPPT, Ок-трапы при
наличии Ok-нотификации); см. `docs/snmp.md`. **Источник КЭС** — **реализован**
(снимок из `kes-reader`, параметры `k_*`, серийники и поля в UI по типу).

Остаётся (требует железа):
- **Реле/команды КЭС** — до подтверждения раскладки (`Relay_C` 0x3E3, запись `0x0E3D`).
- Проверить раскладку бит реле МАП (0/1/2 = реле1/2/3) по модели.

Итог:
- target — необязательный (пусто → текущее устройство), допускается кросс-устройство (реле);
  серийник numeric из `map-list`/`kes-list`, в UI — список по типу источника + ручной ввод;
- SNMP-trap — **та же OID-схема MICROART-MIB**;
- **TIME и MODE**-события — **в первой версии** (для МАП); MODE — **единая серверная
  функция** (общая с legacy-API), подписи из ключей `p1.modeN` (все локали);
  клиент считает сам (бинарное сырьё);
- кулдаун настраиваемый на правило (по умолчанию 30 c); источник КЭС — реализован
  (действия на КЭС — до подтверждения на железе); BATMON/зарядник исключены;
- отдельный лог срабатываний/действий на `.253`.
