# Legacy API (совместимость)

Совместимость со старым HTTP-API «Малины» (`request_node.php` и веб-страницы).
Реализовано в `malina-web` (см. `web/README.md`). Авторизация — `docs/api-auth.md`.

## 1. Эндпоинты

| Эндпоинт | Метод | Авторизация | Назначение |
|---|---|---|---|
| `/read_json.php?device=map` | GET | нет | снимок полей МАП (расчётный JSON) |
| `/read_memory.php?offset=&count=` | GET | нет | массив байт образа памяти |
| `/check_daemons.php` | GET | нет | статусы демонов (совместимость) |
| `/write_eeprom.php` | POST | **HTTP Basic** (PAM) | запись в МАП |

Legacy-**чтение** — **без авторизации** (как в старой системе; нужно для внешних
потребителей/портала). Legacy-**запись** — Basic (пароль → PAM, кэш 5 мин,
см. `docs/api-auth.md` §5).

## 2. Выбор устройства

Legacy-модуль **закрепляется за одним МАП** (по серийнику + букве) и читает/пишет
именно его; при потере ждёт возврата, затем подхватывает первый доступный.
`read_json.php`/`read_memory.php` обслуживают закреплённый МАП. `write_eeprom.php`
пишет **только** в закреплённый МАП; если привязки нет — `error`.

## 3. `GET /read_json.php?device=map`

- `device=map` — единственный поддерживаемый (иначе `400 {"error":"unsupported device"}`).
- Ответ: `text/html; charset=UTF-8`, тело — **JSON-объект** с полями МАП
  (расчётный снимок, обновляется раз в секунду в основном цикле модуля).
- Формат/семантика полей — `docs/legacy_read_json_map.md` (реверс старого JSON).

Пример:
```
GET /read_json.php?device=map
Content-Type: text/html; charset=UTF-8
{"0":...,"_Uacc":..., ...}
```

## 4. `GET /read_memory.php?offset=&count=`

- `offset` — смещение (байт, ≥0), `count` — количество байт (≥0); границы
  обрезаются по размеру образа (`0x000..0x7FF`).
- Ответ: `text/html; charset=UTF-8`, тело — **JSON-массив байт** (`[0..255]`).

Пример:
```
GET /read_memory.php?offset=0&count=4
[3,1,132,0]
```

## 5. `GET /check_daemons.php`

- Ответ: `text/html; charset=UTF-8`, тело — JSON статусов демонов в формате старого
  `check_daemons.php`: `{"0":..,"1":1,...,"mapd":0|1,"mpptd0":1,...}`.
- `mapd=0`, если МАП доступен (найден или есть сохранённый снимок), иначе `1`.
  Остальные демоны в нашей системе отсутствуют → `1`; `dbe_flash` (износ флеша) → `1`.

## 6. `POST /write_eeprom.php`

Тело — `application/x-www-form-urlencoded`, поле **`data`**:

```
data=[[<addr>,<val>], ...]
```

- `addr`, `val` — **десятичные** (как в старом PHP/JS).
- `addr == 0` → **команда МАП** (`val` — код команды, 1..9).
- `addr != 0` → **запись байта** в ячейку (`addr` 0..0x7FF, `val` 0..255).
- Порядок пар сохраняется. Классификация — **по номеру регистра** (0 → команда).
  Смешанный набор (команды и регистры) исполняется последовательными однородными
  запросами: подряд идущие регистровые записи — одним запросом, каждая команда —
  отдельно.

**Авторизация:** HTTP Basic; пользователь `malina`, пароль → PAM. Неверно/нет — `401`.

**Исполнение:** команда ставится в очередь legacy-модуля и исполняется в его
**основном цикле**; фактическая запись — через `map-reader` (обрамление
`pre 3`/`post 7`, ретраи — там же, см. `docs/map-write.md`). **Сразу после записи**
модуль перечитывает МАП и пересобирает снимок `read_json.php` и образ
`read_memory.php`. Таймаут ответа клиенту — 10 с; при длительной записи (ретраи
`map-reader`) клиент может получить `error`, а операция завершится позже.

**Ответ:** текст `text/html; charset=UTF-8`:
- `Ok` — успех;
- `error` — ошибка (плохой `data`, нет привязки к МАП, отказ/таймаут МАП, не Basic).

Примеры:
```
# включить МАП (команда ON=2)
POST /write_eeprom.php
Authorization: Basic ...
data=[[0,2]]
→ Ok

# записать часы 09:54 (0x1B6=438, 0x44B=1099) — разные регионы, одним вызовом
data=[[438,77],[1099,4]]
→ Ok
```

Замечание: команды и регистры в одном вызове допустимы (разбиваются автоматически
на однородные запросы). Ограничение на одну заявку к `map-reader` — **≤64 операций**
(длинные серии регистров режутся на несколько заявок автоматически).

## 7. КЭС (реализуемые ручки)

Из всего legacy-API КЭС реализуются **только три** ручки:

| Ручка | Метод | Авторизация |
|---|---|---|
| `/read_json.php?device=mppt` | GET | **без авторизации** (read открыт, как map) |
| `/read_sec.php?id=&offset=&count=` | GET | **без авторизации** (read открыт, как map) |
| `/write_sec.php?id=&relay=&mode=` / `?id=&data=` | GET | **HTTP Basic + PAM** (как `write_eeprom`) |

Остальные КЭС-ручки (`get_mppt_e.php`, `mppt_errors*.php`, `mppt_counters_history.php`,
`wind_mppts_set.php`, `devices.php`, `find_devices.php`, `write_eeprom.php`,
`get_eeprom_state.php`) **не переносятся**.

Политика авторизации КЭС согласована: чтение (снимок/ячейки) — открыто, запись —
Basic+PAM; это повторяет МАП-политику (`docs/api-auth.md` §1).

### 7.1 Контракт ручек (legacy-совместимость)

Разбор legacy-исходников — `docs/legacy/kes-legacy-malina2.md` (§1c, §3, §4);
живое подтверждение формата на `.68` — в том же доке §1b.

**`GET /read_json.php?device=mppt`** — возвращает JSON-массив снимков КЭС (`mpptd`
пишет в shm 2016 — 4 слота по 1024 Б, каждый объект терминирован `#EOF`):
```json
[{"timestamp":"…","time":"…","UID":"…","Vc_PV":"…", … "R1":"…","R2":"…","R3":"…"}]
```
- Значения — **строки** (как в legacy).
- Полный список полей → `docs/legacy/kes-legacy-malina2.md` §1b.
- Пустые слоты (длина ≤ 10) отбрасываются.
- `?device!=mppt` → `error`.

**`GET /read_sec.php?id=N&offset=A&count=C`** — байты **виртуального адресного
пространства** КЭС `id` (RAM-раскладка) в диапазоне `[A, A+C)`, возврат JSON-массив
десятичных. Виртуальное пространство строится так: массив нулей размером
`kesVirtualSize` (0xE80 — покрывает весь публикуемый диапазон параметры/настройки/
телеметрия/BMS-MPPT), затем значения из снимка `KESE+KESR+KESS` раскладываются по
их исходным RAM-адресам (LE по размеру ячейки) — «первоначальное размещение» в
памяти КЭС. `A ≥ 0`, `C ≥ 1`, `A+C ≤ kesVirtualSize`; вне диапазона/без `id`/`offset`
→ `error`. `id` — 1..N.

**`GET /write_sec.php?id=N&relay=R&mode=on|off|1|0`** — реле КЭС:
- `R` = 1..3; текущее состояние читается из `0x3E3` (`Relay_C`, биты 0/1/2 = реле 1/2/3);
- если реле уже в требуемом состоянии — **ранний `Ok`** (без записи);
- иначе RMW битов → запись байта состояния в командную ячейку **`0x0E3D` (3645)**;
- ответ — текст `Ok`/`error`/`unread`.

**`GET /write_sec.php?id=N&data=[[cell,val],…]`** — запись произвольных ячеек
(десятичные), приоритет у `relay` (если передан — `data` игнорируется).

### 7.2 Индекс `id` и источник данных

Пересчёт legacy ↔ target (фиксирует конвенцию `M1`):

| Аспект | Legacy (`read_sec`/`write_sec`) | Наш API |
|---|---|---|
| `id` | **1-based** (`1..N`) | `id-1` — индекс в `kes-list`; чтение/запись — по реальному номеру слота `KesInfo.ID` |
| ячейка/адрес | **десятичный** (`data=[[cell,val]]`) | наружу — десятичный (как legacy); в control-сокет — hex без префикса (`addr:"E3D"`), конвертация внутри |
| ответ | `Ok` / `error` / `unread` | `Ok` / `error`; `unread` (очередь 2200) заменяется на `error` |
| лимит КЭС | 4 (0..3) | 32 (`kesSlots`); `id` принимается в диапазоне реально занятых слотов |

- В legacy `id` — 1..N; внутри ручек `$id-1` (0-based) — индекс в списке КЭС.
  В нашей реализации `id-1` — индекс в `kes-list` (`loadKesList`, компактный по
  занятым слотам), а чтение/запись идёт по реальному номеру слота (`KesInfo.ID`).
- Источник снимков `read_json`/`read_sec`/`write_sec` — **`kes-list` и payload слота
  `kes-reader`** (`/dev/shm/malina-kes-state`, контракт — `docs/kes-reader.md` §4);
  `read_sec` дополнительно строит виртуальное адресное пространство (см. §7.1).
- Спека совместимости формата — `docs/kes-reader.md` §4.2; реализация индекса/
  серийника — как в §4 того же дока.

Спека совместимости: `docs/kes-reader.md` §4.2; разбор legacy — `docs/legacy/kes-legacy-malina2.md`.
