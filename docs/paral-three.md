# Параллельная и трёхфазная работа МАП: находки и проблема определения топологии

Источники: пользовательский паспорт `passport-mac-tit-03082023.pdf` и
`passport-titanator-prilozeniapolnaya-versiya_04082023.pdf`; карта памяти
`protocol_MAP_cells_2026_07_15.doc`. Значения прочитаны с реальных МАП (`.60`).

## 1. Роли и ячейка `_LCD_MAP_iFaze` (0x139)

Каждый МАП сам объявляет свою роль в меню «3-Фаз,|| /Внешние Устройства →
3-Фаз /Параллельный» ячейкой **`_LCD_MAP_iFaze` (0x139, контракт `LCD_MAP_iFaze`)**:

| Значение | Пункт меню | Смысл |
|---|---|---|
| `0` | «Главный» | ведущий, **однофазная** схема |
| `1` | «Глав./Фаза1» | ведущий **и** фаза L1 (3-фазная) |
| `2` | «Фаза2» | фаза L2 (3-фазная; «ведомая фаза») |
| `3` | «Фаза3» | фаза L3 (3-фазная; «ведомая фаза») |
| `4` | «Параллелн.» | **ведомый** в параллельной цепочке |
| `255` | (нет пункта) | однофазная работа **без 3-фазной доп. платы** (параллель недоступна) |

Важно: «ведомые фазы» (`Фаза2`/`Фаза3`, значения 2/3) — это **не** параллельные
ведомые; это фазные приборы 3-фазного комплекса. Параллельные ведомые — только
значение `4` («Параллелн.»).

## 2. Ячейка `_LCD_SlaveMAPNum` (0x155) — что в неё заносится

Дословно из паспорта (пункт «Кол-во/Адрес Параллельн.» / «Slave MACs Number/Adr»):

> «Для **главного или любого фазного МАП** определяет **количество приборов в
> цепочке** параллельно подключённых при синхронной работе **или Адрес
> параллельного МАП** в этой цепочке.»

То есть смысл зависит от роли (`_LCD_MAP_iFaze`):

| Роль | Что в `_LCD_SlaveMAPNum` |
|---|---|
| Ведущий: «Главный» (0) или фазный (1/2/3) | **количество приборов в параллельной цепочке** |
| Ведомый: «Параллелн.» (4) | **адрес (номер) этого прибора** в цепочке |

Инженерная карта памяти описывает ту же ячейку как «сколько идёт после текущего;
`0` — этот ведомый последний», что совпадает с «адресом» в виде убывающего номера.

## 3. Пределы

- Паспорт: «синхронная (параллельная) работа — **до 10 приборов в однофазной
  сети** и **до 30 в трёхфазной**».
- Прочитано с реального МАП: максимум пункта (`_LCD_SlaveMAPNum`, таблица
  максимумов меню, ячейка `0x165`) = **9** (т.е. до 9 параллельных/ведомых на
  цепочку; с ведущим — 10 приборов).
- Лимит нашего `map-reader`: 9 MAP-слотов.

## 4. Схемы (псевдографика)

**Однофазная параллель (1 ведущий + N ведомых, цепочка):**
```
            ┌─────────────────────────┐
            │ ВЕДУЩИЙ (iFaze=0)       │  SlaveMAPNum = число приборов цепочки
            └───────────┬─────────────┘
                        │  шина синхронизации / параллельный выход
     ┌──────────────────┼──────────────────┬───────────────┐
     ▼                  ▼                  ▼               ▼
┌─────────┐        ┌─────────┐        ┌─────────┐     ┌─────────┐
│Ведомый1 │        │Ведомый2 │        │Ведомый3 │ ... │ВедомыйN │
│iFaze=4  │        │iFaze=4  │        │iFaze=4  │     │iFaze=4  │
│адрес=...│        │адрес=...│        │адрес=...│     │адрес=0  │
└─────────┘        └─────────┘        └─────────┘     └─────────┘
```

**Трёхфазная система (3 ведущих + ведомые у каждого):**
```
 ФАЗА L1                  ФАЗА L2                  ФАЗА L3
┌───────────────┐  sync  ┌───────────────┐  sync  ┌───────────────┐
│ВЕДУЩИЙ Ф1     │◄──────►│ВЕДУЩИЙ Ф2     │◄──────►│ВЕДУЩИЙ Ф3     │
│iFaze=1        │        │iFaze=2        │        │iFaze=3        │
└──────┬────────┘        └──────┬────────┘        └──────┬────────┘
       │ параллель L1           │ параллель L2           │ параллель L3
   (iFaze=4, свои адреса)   (iFaze=4, свои адреса)   (iFaze=4, свои адреса)

Ведомые L1 ⟂ Ведомые L2 ⟂ Ведомые L3 — между собой НЕ взаимодействуют.
Синхронизация — только между ведущими Ф1/Ф2/Ф3.
```

## 5. Как определять по карте памяти

Все нужные ячейки уже входят в контракт/`MapData`:

| Что | Ячейка | id в контракте |
|---|---|---|
| Роль/фаза | `LCD_MAP_iFaze` | 99 (0x139) |
| Кол-во/адрес параллели | `LCD_SlaveMAPNum` | 110 (0x155) |
| Плата синхронизации 3ф/паралл. | `SyncDiz_Plat` (b0) | (0x024) |
| Режим синхронизации фаз | `LCD_MAP_Sync` | (0x13F) |
| Ошибки синхронизации | `RSErrDop` (b0/b1/b5/b6) | (0x447) |
| Частота предыдущей фазы | `ThFMAPSync` | (0x449) |
| Суммарные токи параллельных по фазам | `I_Akb_MAP_faz1/2/3` | (0x528/0x52A/0x52C) |

Алгоритм:
1. **Схема.** 3-фазная, если есть приборы с `iFaze ∈ {1,2,3}` (и `SyncDiz_Plat`
   b0 = 1). Иначе однофазная (ведущий `iFaze=0` + ведомые `iFaze=4`).
2. **Роль.** `iFaze==4` → ведомый; `0` → однофазный ведущий; `1/2/3` → фазный
   ведущий; `255` → однофазный без платы (параллель недоступна).
3. **Фаза.** У фазных ведущих — напрямую (`iFaze=1/2/3`). У **параллельного
   ведомого фазы в его ячейках нет** (см. проблему ниже).
4. **Номер/адрес ведомого.** Из его `_LCD_SlaveMAPNum` (у ведущего в этой же
   ячейке — число приборов цепочки).

## 6. Проблема: фаза параллельного ведомого не определяется из его карты памяти

**Суть.** У ведомого (`iFaze=4`) в памяти нет номера фазы и ссылки на ведущего.
Единственные «фазные» ячейки — это `iFaze` фазных ведущих (1/2/3),
синхро-диагностика на ведущих (`RSErrDop`, `ThFMAPSync`) и агрегаты
`I_Akb_MAP_faz1/2/3` у ведущего (суммарные токи всех параллельных МАП каждой
фазы). Ни одна из них не привязывает **конкретного** ведомого к фазе/ведущему.

**Из-за этого невозможно достоверно определить топологию и место каждого
ведомого при трёхфазной схеме, основываясь на данных регистров МАП.**

**Следствия:**
- Однофазная схема — однозначно: цепочка одна, фаза не нужна, порядок — по
  `_LCD_SlaveMAPNum`.
- Трёхфазная схема с ведомыми только на одной фазе — тоже однозначно
  (единственная цепочка с ведомыми).
- Трёхфазная схема с ведомыми на **нескольких** фазах — по ячейкам ведомого
  **нельзя** понять, к какой фазе/ведущему он относится.

**Варианты решения (если понадобится):**
1. Вести привязку «ведомый → фаза/ведущий» из монтажа/конфигурации (мы знаем,
   кто по какой шине подключён).
2. Запросить у MicroArt отдельную ячейку (номер фазы/мастера для ведомого).
3. Косвенно — по агрегатам `I_Akb_MAP_faz1/2/3` у ведущих определить, на каких
   фазах есть параллельные группы и их суммарный ток (но не поштучную привязку).

## 7. Проверено на реальных МАП (.60)

Прочитано из shm (контракт), сервис не останавливался:

| Слот | Модель | Порт | `LCD_MAP_iFaze` | `LCD_SlaveMAPNum` |
|---|---|---|---|---|
| 0 | D (Доминатор) | /dev/ttyUSB0 | **0** («Главный») | **0** |
| 1 | T (Титанатор) | /dev/ttyAMA0 | **0** («Главный») | **0** |

Оба прибора — **однофазные ведущие без ведомых** (`SlaveMAPNum=0` = в цепочке
только он). Значение `255` встретится только на приборах без 3-фазной/
параллельной платы.

## 8. Что делать в `map-reader`

- Публиковать сырые поля (`LCD_MAP_iFaze`, `LCD_SlaveMAPNum`, `SyncDiz_Plat`,
  `LCD_MAP_Sync`, `RSErrDop`, `ThFMAPSync`, `I_Akb_MAP_fazX`) — уже есть в контракте.
- При желании вычислять производные: `role` (master/slave), `phase` (для ведущих),
  `slave_ordinal` (у ведомых), `is_3phase` (по наличию фазных ведущих + платы).
- Для ведомых фазу считать **неизвестной из МАП** и заполнять внешней привязкой
  (например, по порту/цепочке), либо не отдавать вовсе, пока не решено.
