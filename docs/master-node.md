# «Мастер-Узел» на нашей админке — требования (согласовано)

Статус: **требования согласованы** (кроме TLS-верификации, см. §9), реализация не начата.
Разбор legacy-функционала — `docs/legacy/master-node.md`.

## 1. Цель

Перенести функционал «Мастер-Узел» на наш сайт (`malina-web`): страница **«Отобразить»**
показывает состояние нескольких узлов «Малина», страница **«Настройка»** — их список.
Рефакторинг умеренный, логика — legacy.

## 2. Ключевые принципы

- **Опрос только сервером.** `malina-web` сам обращается к узлам; **клиент опрашивает
  только наш сайт** и сам remote не дёргает. Показывать адрес узла в UI **можно** —
  запрещено именно «дёргать» remote из браузера.
- **Только legacy-ручки узлов** (`/check_daemons.php`, `/read_json.php`), никакого
  нового API. Наш собственный узел опрашивается так же — по HTTP(S) к своим legacy-ручкам.
- **Внешний и внутренний узлы равнозначны.** Добавят `127.0.0.1`/`localhost` — начнём
  опрашивать; не добавят — не начнём. Особой «self»-логики нет.
- **Наш узел ничего нового не отдаёт.** Блоки АКБ/MPPT показываем, только если удалённый
  узел сам сообщил о подсистеме в `check_daemons.php`.
- **Язык — только русский** (legacy-функция; i18n не делаем).

## 3. Ленивый кэширующий прокси

- Опрос узлов — **только по запросу клиента** (фонового пула нет).
- Кэш — **файлы в tmpfs**: `/dev/shm/malina-master/<id>.<endpoint>.json`
  (ключ = `id` + endpoint). Переживает рестарт `malina-web`; ребут — не требуется.
- **TTL 5 c.** Свеж (mtime ≤ TTL) → отдаём кэш; иначе идём в remote, пишем кэш, отдаём.
- **Кэшируем и неуспех**: недоступность remote тоже кэшируется на TTL → отдаём
  `no_data`, **дохлые хосты не долбим** (защита от «ддоса» узла толпой клиентов).
- Одновременные клиенты — **single-flight** на (`id`, endpoint).
- При изменении/удалении узла его кэш **сбрасывается**.
- Каталог кэша при **старте web не чистим** (файлы протухают сами по TTL).

## 4. Конфиг узлов

- Путь: **`/malina/etc/malina/master/nodes.json`** (каталог `0755`, файл `0600`).
- Формат (наш, не legacy `nodes.list`):

```json
{
  "version": 1,
  "nodes": [
    { "id": "a1b2c3d4", "name": "Garage", "scheme": "http", "host": "node1.local", "port": 80 }
  ]
}
```

| Поле | Тип | Смысл |
|---|---|---|
| `version` | int | версия схемы |
| `nodes[].id` | string | стабильный id (8 hex), генерируется при добавлении |
| `nodes[].name` | string | подпись, ≤ 32 символов |
| `nodes[].scheme` | string | `http` (по умолчанию) или `https` |
| `nodes[].host` | string | IPv4 **или hostname** (`localhost` допустим) |
| `nodes[].port` | int | TCP-порт, **всегда задан**, по умолчанию `80` |

- **Лимит узлов — 30.**
- **Дубли `host:port` запрещены.**
- Импорт legacy `nodes.list` — **не делаем**, настраиваем с нуля.

## 5. Серверные эндпоинты (наши)

Адресация — по `id`. Авторизация — **cookie-сессия** (как у страниц; токены/Bearer не используем).

| Эндпоинт | Проксирует |
|---|---|
| `GET /api/master/check_daemons?id=<id>` | `<scheme>://<host>:<port>/check_daemons.php` |
| `GET /api/master/read_json?id=<id>&device=map\|bat\|mppt` | `<scheme>://<host>:<port>/read_json.php?device=<device>` |

- **Гейтинг вызовов** (клиент сам решает, что звать, по результату `check_daemons`):
  - `map` — **только если `mapd == 0`** (если МАП `1` — не звать);
  - `bat` — если `batmond == 0`;
  - `mppt` — если есть MPPT (хотя бы один `mpptdN == 0`);
  - `charger` — если `chargerd == 0`.
  - **bat/mppt — отдельными вызовами** (без legacy-костыля с многострочным `map`).
- Ответ отдаём **как есть** (pass-through: тело и `content-type`), кэшируем и отвечаем браузеру.
- Ошибки: неизвестный `id` → `404`; недопустимый `device` → `400`; remote недоступен →
  `502 {"error":"no_data"}` (в т.ч. из кэша-ошибки). Ошибка одного эндпоинта не ломает
  остальные — узел показываем частично.
- Транспорт: `scheme` из конфига (`http`/`https`), порт из конфига; к remote — **без
  авторизации**; **таймаут 1 c**.
- **TLS для `https` — без проверки сертификата** (`InsecureSkipVerify`): принимаем любой
  сертификат. Осознанное решение: возможен MITM, узлы считаются доверенными (локальная сеть).

## 6. UI

- Пункт меню **«МАСТЕР-УЗЕЛ ▾»** → «Отобразить» / «Настройка».
- **`/master`** — «Отобразить»: наш chrome (меню) + **один общий iframe на всю страницу**.
  Внутри этого единственного iframe — legacy-вёрстка со всеми панелями узлов сразу
  (не по фрейму на узел). Стили/скрипты legacy не текут в наш сайт — конфликтов с меню и
  обвязкой нет. Legacy-«шапку» (синюю полосу страницы) не берём — рисуем наш chrome.
- **Список узлов и панели рендерит сервер** внутри этого iframe; JS внутри iframe опрашивает
  наши `/api/master/*` по каждому узлу (remote сам не дёргает).
- **Заголовок панели узла**: `name` + адрес `host:port` + иконка статуса.
- Недоступный узел/подсистема — затемнение/индикатор ошибки (как legacy).
- **`/master/settings`** — «Настройка»: сервер-рендер **одной формы на весь список**
  (строки узлов + «добавить» + «сохранить/удалить»), сохранение `POST /master/settings`.
  Поля: `name`, `scheme`, `host`, `port`; валидация (id генерим, дубли host:port запрещены,
  лимит 30).
- **Мобилку не заморачиваем** (legacy-панели фикс-ширины; на узких экранах — как получится).

## 7. Не делаем (зафиксировано)

- Импорт legacy `nodes.list`.
- Bearer-токены для master-API (только cookie-сессия).
- Аудит изменений настроек мастер-узла.
- i18n строк мастер-узла (только русский).
- Новый API на удалённых узлах (только legacy) и «self»-логику.
- Адаптив/мобильную вёрстку панелей.
