# Legacy «Мастер-Узел» — скоуп и ручки

Разбор пункта меню **«МАСТЕР-УЗЕЛ»** старой «Малины»
(бэкап `titanator_malina_fixed_20261007`, разделы `settings/html` и
`settings/web-data`). Пункт — выпадающее меню с двумя страницами:

- **Отобразить** (`master_node.php`) — сводная панель по нескольким узлам
  «Малина» одновременно;
- **Настройка** (`master_node_set.php`) — список узлов агрегации.

Документ описывает: назначение, состав файлов, модель данных, обе страницы,
а затем **отдельно все «ручки»** — локальные (на самом узле) и удалённые
(на других хостах).

## 1. Назначение

«Мастер-Узел» — это **агрегатор**: один узел показывает в браузере состояние
*других* узлов «Малина» (МАП, АКБ/BMS, MPPT, зарядник и статусы демонов),
обращаясь к ним по HTTP. Источник данных о составе узлов — файл
`/settings/web-data/nodes.list` (редактируется на странице «Настройка»).

Агрегатор не хранит историю и ничего не пишет на удалённые узлы: только
периодически **читает** их JSON-снимки и рисует мнемосхему. Локальный узел тоже
читается (поллинг «самого себя»), т.к. `nodes.list` может содержать `127.0.0.1`.

## 2. Скоуп (файлы)

Страницы и их фронтенд (`settings/html`):

| Файл | Роль |
|---|---|
| `master_node.php` | страница «Отобразить», верстка панелей |
| `js/master_node.js` | поллинг узлов и отрисовка панели |
| `master_node_set.php` | страница «Настройка» |
| `js/master-node-set.js` | CRUD-редактор списка узлов (до 10) |
| `master_node_load.php` | отдать текущий `nodes.list` |
| `master_node_save.php` | сохранить `nodes.list` |
| `get_nodes.php` | отдать `nodes.list` (для страницы отображения) |
| `request_node.php` | прокси-ручка: HTTP-запрос к другому узлу |

Данные и общестраничные ручки:

| Файл | Роль |
|---|---|
| `/settings/web-data/nodes.list` | конфигурация узлов (JSON-массив) |
| `check_daemons.php` | статусы демонов узла (свой + удалённый профиль) |
| `get_wlan_state.php`, `get_lan_state.php` | состояние сети в шапке |
| `switch_lang.php` | переключение языка в шапке |
| `read_json.php` | снимки данных МАП/АКБ/MPPT из shm (вызывается на удалённых узлах) |

Общий каркас шапки (`js/local_js.js`, `locale/*`, `css/*`) — вне скоупа, но
упомянут там, где задаёт поведение страниц.

## 3. Модель данных: `nodes.list`

JSON-массив записей, каждая — один узел:

```json
[{"malina_ip":"127.0.0.1","malina_port":"80","malina_name":"Garage"}]
```

| Поле | Тип | Смысл |
|---|---|---|
| `malina_ip` | строка | IPv4 узла (проверяется `FILTER_VALIDATE_IP`) |
| `malina_port` | строка | TCP-порт веб-сервера узла, 10…65535 (иначе `80`) |
| `malina_name` | строка | подпись, до 10 символов, санитайзится |

В штатном бэкапе список — из одной записи на себя (`127.0.0.1`). Ограничение
редактора — **до 10 узлов**.

## 4. Страница «Отобразить» (`master_node.php` + `js/master_node.js`)

При загрузке PHP:

1. читает `nodes.list`, декодирует JSON;
2. перекладывает IP всех узлов в `$_SESSION['ip']` (белый список для прокси);
3. рендерит по одной панели `create_device($i)` на каждый узел.

Панель (`create_device`) — это мнемосхема на Bootstrap-гридах: заголовок
(иконка, IP+имя, строка режима МАП, загрузка, АКБ-бартер и выработка), тело с
блоками:

- **МАП** (`_map`): напряжения, токи, реле 1/2, режим, часы, активная мощность;
- **АКБ** (`_bat`): напряжение, 100 %-остаток, температура;
- **Charger** (`_charger`): зарядник;
- **MPPT 1…4** (`_mppt1..4`): `Vpv`, `Pout`, температура, реле 1..3;
- **служебные бары и «лампы»** (`_ac_map`, `_ac_home`, `_dc_charger`,
  `_dc_mppt`, `_dc_map`, штекеры, домик);
- **info-блок** (`_info`) для накопления строк ошибок.

Все элементы имеют id вида `<index>_<суффикс>` и наполняются JS.

### Поллинг (`js/master_node.js`)

- при старте `get_nodes.php` → массив `nodes` (синхронно, `async:false`);
- каждые **3000 мс** — `update_nodes()`;
- каждые **5000 мс** — `tick()` (шапка: Wi‑Fi/LAN/статусы демонов);
- язык — `switch_lang.php` + `location.reload()`.

`update_nodes()` для каждого узла `i`:

1. `request_node.php` с `dev=/check_daemons.php` → JSON статусов узла. Если
   ответ `ERROR`/пусто — иконка узла красная (`fail`), иначе зелёная;
2. если на узле есть **МАП** (`mapd==0` **или** `batmond==0`) — запрашивает
   `/read_json.php?device=map`, заполняет поля МАП, реле, температуры,
   режим (`map_mode[_MODE]`), ошибки в `_info`, «активность» баров;
3. если есть **batmon** (`batmond==0`) — `/read_json.php?device=bat`:
   `C_100_remain`, дневная выработка `mppt_day_E`;
4. если есть **charger** (`chargerd==0`) — снимает `dimmed` с блока зарядника;
5. если есть **MPPT** (сумма `mpptd0..3` < 4) — `/read_json.php?device=mppt`:
   по каждому MPPT `Vc_PV`, `P_Out`, `Temp_Int`, `I_Ch`, реле (`Relay_C` битовой
   маской `[0,1,2,4]`); суммирует ток/мощность/энергию. Если batmon нет —
   подставляет суммарную энергию MPPT в поле выработки.

Особенности/деградация:

- при отсутствии подсистемы — блок «затемняется» (класс `dimmed`);
- `request_node.php` вызывается синхронно (`async:false` на время инициализации)
  и асинхронно в цикле; `id` в ответе — индекс узла;
- если узел недоступен, `remote_daemons[i]` = `'ERROR'` → красная иконка;
- защита от «падения»: `typeof ... === "undefined"` прерывает обработку узла.

Важный нюанс: обработчик ответа МАП ожидает до **трёх** строк (`map`,
`map_mppt`, `map_bms`) — агрегированных данных MPPT/BMS по I2C. Текущий
`read_json.php?device=map` в этом бэкапе отдаёт одну строку, поэтому ветки
`map_mppt`/`map_bms` фактически не задействуются (исторический формат).

## 5. Страница «Настройка» (`master_node_set.php` + `js/master-node-set.js`)

PHP-страница рендерит форму-заготовку: контейнер `#pb` («Loading …»), пустой
`#last_row` и кнопки **save** / **add_node**. Редактор строится целиком в JS:

- при загрузке `master_node_load.php` → `data_array`, затем `objects_restore()`
  строит строки (`ip_row`); каждая строка — поля `field1` (IP, pattern IPv4),
  `field2` (порт number 10…65535), `field3` (имя 1..10), `field4` (удалить);
- `add_node()` — добавить строку (лимит 10, иначе `alert(loc['limit'])`);
- `delete_node()` — удалить строку и перенумеровать;
- `save_data()` — собрать строки, выкинуть пустые IP, `POST master_node_save.php`
  с `data=JSON`; при ответе `1` — кнопка зелёная, `alert(loc['saved_success_1'])`,
  перерисовка и `location.reload()`; иначе — кнопка красная;
- `tick()` каждые 5 с обновляет шапку (сеть/демоны).

## 6. Ручки — локальные (на самом узле)

### 6.1 `GET get_nodes.php`

**Назначение:** отдать конфигурацию узлов странице «Отобразить».
**Логика:** `echo file_get_contents('/settings/web-data/nodes.list')`.
Ответ — «сырой» JSON-массив (или пусто, если файла нет). Без валидации и
авторизации. Вызывается из `js/master_node.js` (`async:false` при старте).

### 6.2 `GET/POST master_node_load.php`

**Назначение:** загрузить `nodes.list` в редактор.
**Логика:** читает `/settings/web-data/nodes.list`; если
`json_decode($data) === NULL` → `failed`, иначе отдаёт исходный JSON.
Проверка лишь на валидность JSON, содержимое не нормализуется.

### 6.3 `POST master_node_save.php` (поле `data`)

**Назначение:** сохранить список узлов.
**Логика:**

1. `json_decode($_POST['data'])`; если `null`/`false` → `failed`;
2. по каждой записи:
   - `malina_ip` обязан пройти `FILTER_VALIDATE_IP`, иначе `failed`;
   - `malina_port` вне `[10..65535]` → принудительно `"80"`;
   - `malina_name` обрезается до 10 символов и чистится регуляркой
     `preg_replace('/["\\\'`^<>&]*/im','', ...)`;
3. `file_put_contents('/settings/web-data/nodes.list', json_encode($result))`;
   неудача → `failed`;
4. успех → `echo '1'`.

Ответ — `1` либо `failed`. Авторизации нет (наследие; менять на новом стенде).

### 6.4 `POST request_node.php` (поля `url`, `port`, `dev`, `id`)

**Назначение:** HTTP-прокси — прочитать JSON-ручку **другого** узла из браузера
мастер-узла (обход same-origin).
**Логика:**

1. `session_start()`; белый список `dev`
   `[/check_daemons.php, /read_json.php?device=map, /read_json.php?device=bat,
   /read_json.php?device=mppt]`;
2. если `dev` не из списка **или** `url` не в `$_SESSION['ip']` (заполнен
   страницей `master_node.php` из `nodes.list`) → `sleep(1); die;`
   (тихий отказ + замедление перебора);
3. открывает `fsockopen(url, port, ..., timeout=1)` и шлёт
   `GET /<dev> HTTP/1.0`, `Host: <url>`, `Connection: Close`;
4. читает тело ответа, отрезает заголовки по `\r\n\r\n`;
5. нормализует `id` через `intval` (иначе `0`);
6. отвечает строкой `<id>\n<answer>` (или `<id>\nERROR` при сбое).

Особенности: таймаут 1 с; при недоступности узла возвращается `ERROR`; ответ
всегда с префиксом индекса, чтобы JS мог разложить ответы асинхронных запросов
по узлам. В коде есть безобидные легаси-огрехи (`is_int(intval(...))` всегда
истинно, `$id` в ветке ошибки заголовков) — на поведение не влияют.

### 6.5 `GET check_daemons.php` (в т.ч. как удалённая ручка)

**Назначение:** статусы демонов узла для шапок и панелей.
**Логика:**

1. `pidof`-проверки через `sudo /usr/sbin/check_daemon.sh <name>` для
   `mapd`, `mpptd`, `batmond`, `dbed`, `chargerd`;
2. «расширенные» демоны: `emd` (через `get_emd_pid.sh`), `emon` (pidof
   `emoncmsd`, либо облако `mac_collector`+`mac_sender`). `0` — работает, `1` — нет;
3. читает байты shm-сегмента **5000** (8 байт) и OR-ит их с фактом процесса,
   формируя набор именованных флагов: `mapd`, `mpptd0..3`, `chargerd`, `dbed`,
   `batmond`, `emd`, `emon`, `dbe_flash`, плюс числовые ключи `"0".."7"`;
4. `echo json_encode($arr)`. С параметром `?services=run` отдаёт вместо этого
   только «сырые» статусы процессов (`$daemons`).

Смысл: `0` — подсистема доступна, `1` — нет. На удалённых узлах именно этот
ответ решает, рисовать ли блоки панели и каким цветом.

### 6.6 Общестраничные ручки шапки

Используются обеими страницами (как и всеми остальными), но входят в скоуп,
т.к. от них зависит UI:

- **`GET get_wlan_state.php`** — `str_replace("\n",":", shell_exec('/usr/sbin/get_wlan_connection.sh'))`;
  скрипт печатает три строки (Mode, ESSID, IP), PHP склеивает их через `:`;
  JS в `tick()` разбирает по `:` и рисует «AP …»/«<ESSID> <IP>»/OFF.
- **`GET get_lan_state.php`** — то же с `/usr/sbin/get_lan_connection.sh`
  (IP `eth0`); в шапку выводится `lan_mode[0]`.
- **`GET switch_lang.php`** — `sudo /usr/sbin/switch_lang.sh` (переключает
  симлинк `/settings/locale` RU↔EN) и `sleep(2)`; JS после ответа перезагружает
  страницу.

Опорные скрипты (в `usr/sbin`):

| Скрипт | Логика |
|---|---|
| `check_daemon.sh` | `pidof $1 >/dev/null; echo $?` (0/1) |
| `get_wlan_connection.sh` | `iwconfig wlan0` → Mode, ESSID; `ifconfig` → IP |
| `get_lan_connection.sh` | IP `eth0` из `ifconfig` |
| `get_emd_pid.sh` | `pidof -x emd` |
| `switch_lang.sh` | симлинк локали RU↔EN |

## 7. Ручки — удалённые (на других хостах)

Вызываются **только** транзитом через `request_node.php` (браузер мастера →
`request_node.php` → узел). Узел — такая же «Малина», где должны быть
развёрнуты соответствующие PHP-скрипты. Все — `GET`, без авторизации.

### 7.1 `GET /check_daemons.php`

Полное описание логики — в §6.5. На мастер-узле ответ определяет: доступен ли
узел вообще (иконка), и какие блоки рисовать (МАП/АКБ/MPPT/зарядник).

### 7.2 `GET /read_json.php?device=map`

**Назначение:** снимок полей МАП из разделяемой памяти.
**Логика:** `shmop_open(2015)` → читает **2048** байт → берёт подстроку до
маркера `#EOF` → отдаёт как JSON-объект (поля `_Uacc`, `_UNET`, `_UOUTmed`,
`_INET_16_4`, `_PNET_calc`, `_IAcc_med_A_u16`, `_PLoad_calc`, `_Relay1/2`,
`_flagUnet2`, `_Temp_Grad0/2`, `_MODE`, `_I_mppt_avg`, счётчики RS-ошибок,
`time` и т.д.). Формат полей — `docs/legacy_read_json_map.md`.
Наш `malina-web` реализует только `device=map` (см. `docs/legacy-api.md`).

### 7.3 `GET /read_json.php?device=bat`

**Назначение:** снимки АКБ/BMS.
**Логика:** `shmop_open(2017)` → читает **2048** байт → режет на два блока по
1024 байта (`0` и `1024`), каждый — до своего `#EOF`; непустые (`strlen>10`)
собирает в JSON-массив `[ {...}, {...} ]`. JS берёт элемент `[0]`:
`C_100_remain` (% остатка), `mppt_day_E` (дневная выработка).

### 7.4 `GET /read_json.php?device=mppt`

**Назначение:** снимки до четырёх MPPT.
**Логика:** `shmop_open(2016)` → читает **4096** байт → режет на **4** блока по
1024 байта, каждый до своего `#EOF`; непустые клеит в JSON-массив.
JS по каждому элементу читает `Vc_PV`, `P_Out`, `Temp_Int`, `I_Ch`, `Pwr_kW`,
`Relay_C`, `RSErrSis`, `V_Bat`, `time`.

Общий контракт shm-сегментов (см. также `docs/map-memory.md` / `docs/map-contract.md`):
`2015` — МАП (2048 Б), `2016` — MPPT ×4 (4×1024 Б), `2017` — АКБ ×2 (2×1024 Б),
`5000` — байтовые флаги демонов (8 Б); каждый JSON-блок завершается `#EOF`.

## 8. Замечания для переноса на новый стенд

- **Прокси-агрегатор** (`request_node.php`) — отдельная ценность: единственный
  способ смотреть чужие узлы из браузера. При переносе нужен белый список
  (узлы из конфигурации) и таймаут; с нашей моделью авторизации read можно
  оставить открытым (см. `docs/api-auth.md`).
- **Конфигурация узлов** (`nodes.list`) — простой JSON на `/settings`; при
  переносе сохранить формат (`malina_ip`/`malina_port`/`malina_name`), иначе не
  совместим старый экран.
- **Обе страницы без аутентификации** — в новой системе закрывать входом по PAM.
- Удалённые ручки мы поддерживаем только для `read_json.php?device=map` и
  `check_daemons.php`; `bat`/`mppt` — функционал иных подсистем (batmon/MPPT),
  вне нашего профиля, но нужен для полной совместимости «Мастер-Узла».
- Введённый в валидацию лимит **10 узлов** и символьный санитайз имени — часть
  контракта экрана настройки.
