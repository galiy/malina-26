# Batmon API (legacy-совместимость): контракт и реализованная логика

Статус: **реализовано в `malina-web`** (эмуляция), источник контракта — **реверс
бэкапа `.68`** (`daemons/batmond`, `daemons/*.pl`, `html/js/master_node.js`).
Связано: `docs/legacy-api.md` (§7 ручки КЭС), `docs/legacy/master-node.md`
(агрегатор «Мастер-Узел»), `docs/legacy/event-manager.md` (события АКБ).

## 1. Назначение

`read_json.php?device=bat` — legacy-ручка снимков **АКБ / BMS** (`batmond`). На
нашем узле (`malina-web`) физического `batmond`/батареи **нет**, но агрегатор
«Мастер-Узел» для корректного отображения дневной выработки в кВтч требует
ветку batmon (иначе суммирует строковые `Pwr_kW` → `NaN`, см. §6). Поэтому ручка
**эмулируется**: отдаёт объект точного состава/типов `batmond`, из которого
агрегатор берёт два поля.

## 2. Legacy-источник (`.68`)

`read_json.php` (case `bat`):

```php
$shm = shmop_open(2017,"a",0,0);          // сегмент АКБ/BMS
$str_json = shmop_read($shm,0,2048);
$result1 = trim(substr($str_json,0,   strpos($str_json,"#EOF")));
$result2 = trim(substr($str_json,1024,strpos($str_json,"#EOF",1024)-1024));
echo "[".(strlen($result1)>10?$result1:"").(strlen($result2)>10?",".$result2:"")."]";
```

- **shm `2017`** = 2 слота по 1024 Б; каждый блок — JSON-объект, терминатор `#EOF`;
- непустые (`strlen>10`) клеятся в JSON-массив `[ {...}, {...} ]`;
- панель берёт элемент `[0]` (слот 0).

Кто пишет shm 2017 — демон **`batmond`** (ARM-бинарь на `.68`). Состав полей и
их форматы извлечены из строк формата этого бинаря (`strings`), семантика — из
perl-потребителей (`emd.pl`, `mac_collector.pl`, `passpersist-ma.pl`,
`mserverUPS.pl`, `ups_agent.pl`).

## 4. Логика полей (реверс `.68`)

- **Панель `master_node.js`** (ветка `batmond==0`) берёт из `[0]`:
  `C_100_remain` → «%» (`#_bat_100`/`#_map_bat_h`), `mppt_day_E`/1000 → «кВтч»
  (`#_alt_e`). Больше ничего из bat для карточки узла не нужно.
- **`emd.pl` (события АКБ)** — `bm_event`: 1=DoD% `100−C_100_remain`, 2=SoC%
  `C_100_remain`, 3=`Ah_user` (слот 1), 4=глубина `C20_t − C_Ah_remain`.
- **`mac_collector.pl` (облако)** — `C20`, `C20_t`, `cons_Ah`, `C_100_remain`→`C100_REM`,
  `TTG`, `mppt_day_E`→`GREEN_ENERGY`, `E_wind_day`→`WIND_ENERGY`, `est_soc`→`SOC`,
  `Iavg`→`IAVG`; из сл.1 — `Sun_I/P`, `wind_I/P`.
- **`passpersist-ma.pl`** — персистентность `C_100_remain`, `C20_t`, `C_Ah_remain`,
  `Ah_user`, `TTG`.
- **`mserverUPS.pl`/`ups_agent.pl`** — экспорт в UPS/NUT: `C_100_remain`, `C20`, `cons_Ah`.

## 5. Наша реализация (`malina-web`)

Хендлер `handleReadBat` (в `web/internal/web/keslegacyapi.go`), **открыт** (без
авторизации, как остальное legacy-чтение — `docs/api-auth.md`):

- Возвращает `[ {слот 0}, {слот 1} ]` — **ровно те же ключи и типы** (строки), что
  `batmond` на `.68` (§3). Обёртка в массив, как `read_json.php`.
- **Реальная величина — только `mppt_day_E`** (слот 0): суммарная суточная энергия
  присутствующих КЭС в Вт·ч:
  ```go
  mppt_day_E = Σ по КЭС из kes-reader  (Pwr_kW*1000 + Pwr_W)
  ```
  Источник — снимки КЭС (`/dev/shm/malina-kes-state`, `kesSnapshotJSON`/`parseKesPayload`).
  Это полный аналог «дневной выработки» на узле без батареи.
- Остальные поля — **нули** в штатном формате (`"0.0"`, `"0.00"`, `"0"`,
  `"0.000"`, `"0.0000"`): батареи на узле нет (`C_100_remain`=`"0.0"`,
  `est_soc`=`"0.0"` и т.д.).
- `timestamp`/`time` — текущие.

## 6. Зачем это нужно (паритет поведения)

`check_daemons` узла (`docs/legacy-api.md` §5) отдаёт **`batmond:0` только при
наличии КЭС** (`presentKesCount() > 0`): агрегатор «Мастер-Узел» уходит в ветку
batmon и берёт `mppt_day_E` (**Вт·ч**, целое → корректное деление). В ветке «нет
batmon» агрегатор суммирует строковые `Pwr_kW` через `+=` и делит на 1000 → `NaN`
(и ×1000 занижение) — см. `docs/legacy/master-node.md` §7.4.

При **отсутствии КЭС** (узел только с МАП) `batmond:1` — не эмулируем batmon и не
маскируем выработку МАП нулём (`mppt_day_E=Σ(КЭС)=0`); NaN в этой ветке не
возникает (массив КЭС пуст, сумма = 0).

Итог для узла с КЭС: панель «Мастер-Узел» показывает корректные
`mppt_day_E/1000` кВтч (равно сумме энергии КЭС), как на узле `.68` с батареей.

## 7. Ограничения

- Это **эмуляция** batmon, а не реальный мониторинг АКБ: поля батареи
  (`C_100_remain`, `C20*`, токи/напряжения, интегралы, модель ветра/солнца) — нули.
- При появлении реального BMS/batmon на узле заглушку следует заменить
  настоящими данными (состав/типы §3 останутся).
- `mppt_day_E` отражает **энергию КЭС**, а не АКБ — корректно для узла, где
  дневная выработка идёт от КЭС.
