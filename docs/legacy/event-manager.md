# Legacy «Менеджер событий» (Система → Менеджер событий)

Разбор legacy-функционала из бэкапа `titanator_malina_fixed_20261007`
(разделы `settings/html` и `settings/daemons`). Пункт меню **Система → Менеджер событий**
(`events.php`), бэкенд — демон **`emd`** (Perl, `/settings/daemons/emd.pl`).

Суть: пользователь задаёт **правила** вида «если параметр устройства по условию
сравнивается со значением → выполнить действие» (отправить E-mail, SNMP-trap,
включить/выключить реле, остановить/запустить генерацию МАП). Демон раз в 2 c читает
телеметрию и отрабатывает правила.

## 1. Состав (файлы)

| Файл | Роль |
|---|---|
| `html/events.php` | страница (каркас; таблицу строит JS) |
| `html/js/events.js` | редактор правил (строки полей field1..field14), сборка JSON |
| `html/events_get.php` | отдаёт `/settings/web-data/events.list` (JSON) |
| `html/events_set.php` | пишет `events.list` и `events.parsed`, дёргает SIGUSR1 emd |
| `html/clear_events.php` | `sudo /usr/sbin/clear_events.sh` (снести правила, убить emd) |
| `daemons/emd.pl` | демон-исполнитель (996 строк Perl) |
| `usr/sbin/send_usr1_emd.sh` | `kill -USR1` демону (перечитать правила) |
| `usr/sbin/clear_events.sh` | `rm events.list events.parsed; kill -9 emd` |
| `usr/sbin/get_devices.sh` | наличие устройств: `MAC:`/`MPPT:`/`CHARGER:` (из `/var/map/devices_found`) |
| `usr/sbin/check_emd.pl`, `emd_*.sh`, `get_emd_pid.sh` | запуск/останов/проверка демона |
| `web-data/events.list`, `web-data/events.parsed` | конфиг (JSON) и плоский формат для демона |
| `locale/{map,mppt,batmon}_email.txt`, `mac_modes.txt` | тексты писем и названия режимов МАП |

## 2. Поток данных (legacy)

```
events.php + events.js  --(save POST)-->  events_set.php
   events.list (JSON правил) ──┐
   events.parsed (плоский) ────┴──> sudo send_usr1_emd.sh (SIGUSR1)
emd.pl: read_and_parse(events.parsed) + read_map/read_mppt/read_bat (shm)
        цикл 2 c: оценить правила → do_action
```

`events_set.php` превращает JSON в строки вида
`event=<N>#device=<D>#<key>=<value>#...#` (только поля с `visibility=true`),
демон парсит их в `@arr_events` (хэш на правило).

## 3. Модель правила (events.list / @arr_events)

| Поле | Смысл |
|---|---|
| `event` | номер правила (порядковый) |
| `device` | `1`=MAC (МАП), `2`=MPPT, `3`=BATMON |
| `mppt_no` | номер MPPT `1..4` (для MPPT; `undefined` иначе) |
| `mac_event` | индекс наблюдаемого параметра МАП (см. §4) |
| `mppt_event` | индекс параметра MPPT |
| `bm_event` | индекс параметра АКБ |
| `mac_mode` / `mppt_mode` | значение режима для срабатывания (когда событие=MODE) |
| `compare` | `1`=≤(le), `2`=≥(ge), `3`= `==`(eq), `4`= `≠`(ne) |
| `value_compare` | порог/значение для сравнения (или `HH:MM` для события TIME) |
| `action` | `1`=E-mail, `2`=Реле ON, `3`=Реле OFF, `4`=Стоп генерации МАП, `5`=SNMP-trap, `6`=МАП OFF, `7`=МАП ON |
| `relay` | для реле: `1..4` = номер MPPT, `5` = реле МАП |
| `device_relay` | номер реле на устройстве `1..3` |
| `ip_trap` | IP приёмника SNMP-trap |

В UI (`events.js`) каждое поле — объект `{visibility, value[, attr]}`; при сохранении
в `events.parsed` попадают только видимые поля.

## 4. Источники телеметрии (legacy shm) и набор полей

Демон читает **разделяемую память** legacy (то, что нам использовать нельзя):

| Шм | Что | Поля |
|---|---|---|
| `2015` (2048 б) | МАП | `@map_fields_array` |
| `2016` (4096 б) | MPPT ×4 (по 1024 б) | `@mppt_fields_array` |
| `2017` (2048 б) | АКБ (2 блока по 1024) | BATMON |
| `2018` (1024 б) | зарядник | (не используется в событиях) |

**МАП (`mac_event`)**: `1`=время, `2`=`_MODE`, `3`=`_UNET`, `4`=`_INET`, `5`=`_PNET`,
`6`=`_Uacc`, `7`=`_PLoad` (в UI лейбл «PACC»), `8`=`_IAcc_med`, `9`=`_E_NET`,
`10`=`_E_ACC`, `11`=`_E_ACC_CHARGE`, `12`=`_I_mppt_avg`, `13`=`_Temp_Grad2` («t° МАП»),
`14`=`_Temp_Grad0` («t° АКБ»), `15`=`_P_mppt_avg`.

**MPPT (`mppt_event`)**: `1`=время, `2`=`Mode`, `3`=`Vc_PV`, `4`=`Ic_PV`, `5`=`P_PV`,
`6`=`V_Bat`, `7`=`I_EXTS0`, `8`=`I_EXTS1`, `9`=`Pwr_kW`, `10`=`Temp_Int`, `11`=`Temp_Bat`.

**АКБ (`bm_event`)** — вычисляемые: `1`=DoD % (`100 − C_100_remain`), `2`=SoC %
(`C_100_remain`), `3`=`Ah_user` (счётчик), `4`=глубина (`C20_t − C_Ah_remain`).

Особые «событийные» поля: **TIME** (`mac_event`/`mppt_event` = `1`) — сравнение по
`HH:MM` (срабатывает раз в сутки в эту минуту); **MODE** (`=2`) — сравнение с выбранным
режимом (для МАП — из `mac_modes.txt`, для MPPT — из `Mode+Sign`).

## 5. Логика срабатывания (`emd.pl`)

- Цикл **раз в 2 c**: перечитать устройства (`get_devices.sh`), МАП/MPPT/АКБ из shm,
  затем для каждого правила — обработчик по `device` (`map_event`/`mppt_event`/
  `batmon_event`).
- У каждого правила есть `trigger` (в памяти, сбрасывается при старте).
  - Условие **истинно** и `trigger==0` → **`do_action`** (и `trigger=1`).
  - Условие **ложно** → `do_action_ok` (сброс `trigger=0`; для E-mail/SNMP дополнительно
    шлётся уведомление «Ok», т.е. «условие вернулось в норму»).
- E-mail: берёт шаблон `email.full` + строку из `{map,mppt,batmon}_email.txt`
  (подстановка `#val#` = текущее значение), до 4 попыток через `send_email.sh` (ssmtp).
- SNMP-trap: `Net::SNMP` v2c, community `public`, порт `162`, OID из `MICROART-MIB`
  (`snmptranslate`); в trap кладётся значение параметра (с множителем) и номер MPPT.
- Реле: чтение/запись через EEPROM (`0x586` для МАП, `0x3E3` для MPPT) — проверка
  «реле настроено на внешнее управление» (`8`), затем команда через **очередь сообщений**
  (`2100/2101` для МАП, `2200/2201` для MPPT).
- Команды МАП: «стоп генерации» (`0:9` при прошивке ≥26, иначе `0:1`), «стоп» (`0:1`),
  «старт» (`0:2`) — тоже через очередь сообщений.
- Демон пишет heartbeat `/var/map/emd_time_label` (используется индикатором в шапке).

## 6. Что нам использовать НЕЛЬЗЯ (и почему)

- **shm legacy** `2015/2016/2017/2018` и формат JSON в них — «legacy API».
- **IPC msg queues** `2100/2101/2200/2201` для команд реле/МАП.
- Прямая работа с **EEPROM** МАП/MPPT и `send_email.sh`/ssmtp, `snmptranslate`/MIB.
- Файл `events.parsed` и сигнал `SIGUSR1` — деталь реализации Perl-демона.

Наш сервис (`malina-web`) уже имеет собственные источники телеметрии (map-reader →
снимок МАП), свой **mailer** и свой **control.sock** записи в МАП — их и используем.

## 7. Особенности/баги legacy (учесть при переносе)

- Лейбл `mac_event=7` — «PACC», а поле фактически `_PLoad`.
- Заголовок-комментарий в `emd.pl` путает коды `compare`; по коду: `3`=равно, `4`=не равно
  (UI это подтверждает).
- `lock` сбрасывается в конце каждого обработчика, т.е. «одно событие за цикл» фактически
  не соблюдается.
- Нет кулдауна/антидребезга, кроме `trigger`-фронта; спам-защиты нет.
- Нет истории сработавших событий (только письма/traps).
- Всё завязано на конкретные legacy-индексы полей и коды устройств.

## 8. Предложения по переносу к нам (рефакторинг «по полной»)

### 8.1. Где живёт логика
- Реализовать **внутри `malina-web`** (Go-компонент `internal/events`), отдельного
  демона/Perl не заводить. Оценка правил — фоновая горутина (интервал 2 c, как legacy).
- Конфиг правил: `/malina/etc/malina/events.json` (свой версионированный формат).
  Состояние `trigger` — в памяти (как legacy); при рестарте сервиса сбрасывается.

### 8.2. Источники данных (наши)
- Использовать **наши** снимки телеметрии (map-reader/снимок МАП), без shm/legacy-API.
- Поддержку MPPT/АКБ включать **по факту наличия подсистемы** (как в «Мастер-Узле»):
  сейчас у нас МАП; появятся MPPT/batmon — добавятся их поля. Наш узел ничего нового
  не отдаёт.

### 8.3. Модель правила (наш формат)
```
{ "id":"a1b2c3d4", "enabled":true,
  "device":"map|mppt|batmon", "mppt_no":1,
  "field":"_UNET", "op":"le|ge|eq|ne|time|mode", "value":"180",
  "action":"email|relay_on|relay_off|mac_stop_gen|mac_stop|mac_start|snmp",
  "relay":5, "relay_no":1, "trap_host":"" }
```
- Поля — **именами** (а не индексами), как в снимках/`mapFieldNames`.
- Действия:
  - **E-mail** → наш `mailer` (`SendText`/`SendHTML`, через аутбокс) — прямое попадание.
  - **Реле / МАП стоп/старт** → через наш **control.sock** (запись в МАП), без очередей/eeprom.
  - **SNMP-trap** — опционально (нужен OID-маппинг; можно отложить/выключить по умолчанию).
- Семантика фронта и «Ok»-уведомления — **сохранить** (срабатывание при входе в условие;
  при выходе — уведомление, если действие email/trap).

### 8.4. UI
- Пункт **Система → Менеджер событий**: страница `/system/events` (наша вёрстка,
  серверный рендер + немного JS). Таблица правил: устройство, MPPT, поле, условие,
  значение, действие, реле, IP trap; кнопки добавить/удалить/сохранить/очистить.
- **Локализация ru/be/zh/en/ka/kk/uz/tg** (как у E-Mail).
- Поля/операции/действия показываем **по наличию подсистем**.

### 8.5. Эксплуатация/наблюдаемость
- **Аудит** каждого срабатывания (правило, значение, действие, результат) — у нас уже есть.
- Опционально: **кулдаун** на правило (мин. интервал) и/или «только по фронту»
  (флаг), чтобы не спамить.
- Отдельный признак «правило включено/выключено».

### 8.6. Открытые вопросы (legacy)
1. Действия: делаем **все** (включая SNMP-trap) или пока email + реле/МАП, а SNMP отложить?
2. Нужен ли **кулдаун/антидребезг** (в legacy нет)?
3. Нужна ли **история** срабатываний на странице (в legacy нет)?
4. Формат/путь конфига `/malina/etc/malina/events.json` — ок?
5. Интервал опроса правил — **2 c** (как legacy) или иной?
6. Языки UI — ru/be/zh/en/ka/kk/uz/tg (по правилам), подтверждаете?
