## 2. Замечания

### H1 (высокий). Legacy API КЭС: есть только имя, спеки совместимости нет — **✅ решено**

**√ Решение:** `docs/legacy-api.md` §7 переработан из «план» в конкретную спеку
совместимости трёх ручек (§7.1 — метод/параметры/авторизация/источник/маппинг
`id`/адресация `offset`/формат ответа; §7.2 — источник `kes-list`+payload, пересчёт
`legacy_id = slot_id+1`). `read_sec` решён через **виртуальное адресное пространство**
(`kesVirtualSize` = 0xE80), `windspeed`/`Mode`/`Sign`/`MPP` отдаются **пустыми строками**
(в контракт не публикуются — `web/internal/web/kesmem.go`). Остальные КЭС-ручки явно
помечены «не переносятся».

**Где:** `docs/legacy-api.md:107-110` (§7 «КЭС (план)»), `docs/kes-reader.md:283`
(§8 п.4), `docs/legacy-endpoints.md:99-100`.

**Что заявлено.** «Legacy-API КЭС (`read_sec.php`, `write_sec.php`,
`read_json.php?device=mppt`, `get_mppt_e.php`, `mppt_errors*.php`,
`wind_mppts_set.php`, `devices.php`, `find_devices.php`) — к реализации вместе с
`kes-reader`. Спека совместимости: `docs/kes-reader.md` §4.2».

**Проблема.** `docs/kes-reader.md §4.2` — это спека **target**-API (control-сокет
`kes-reader`: JSON `{"cmd":"write",…}`, hex-адреса, 0-based `id`), а не legacy HTTP.
Спеки совместимости (как legacy-запрос превращается в что) **нет**. При этом:

- `read_sec.php` читает **сырой образ** ячеек из shm: `${(id-1)*2048 + offset}`,
  `offset == RAM-адрес`, 1-based `id` (`docs/legacy/kes-legacy-malina2.md` §20,
  §11). У нас слот `kes-reader` — **структурированный** `[KESE][KESR][KESS]`
  (`kes.go:302-398`), поля упакованы последовательно, **адресной индексации
  нет**. Значит `read_sec.php` из текущего shm-контракта отдать нельзя — нужен либо
  отдельный raw-image (2048 Б на КЭС, как legacy shm 1995), либо явный маппинг
  `legacy offset → поле`.
- `read_json.php?device=mppt` отдаёт legacy-JSON c полями `UID, Vc_PV, Ic_PV, V_Bat,
  P_PV, P_Out, P_Load, P_curr, I_Ch, I_Out, Temp_Int, Temp_Bat, Pwr_kW, Sign_C0/1,
  I_EXTS0/1, P_EXTS0/1, Relay_C, RSErrSis, Mode, Sign, MPP, windspeed, FW, R1/R2/R3`
  (`docs/legacy/kes-legacy-malina2.md` §5, §1b). Маппинг этих имён на `KESE`/`KESR`
  нигде не зафиксирован; часть полей (`Mode`/`Sign`/`MPP`/`windspeed`) мы **не
  публикуем** (см. `docs/kes-reader.md:266-267`), а legacy их отдаёт — надо решить,
  отдавать ли `null`/`0`.
- `write_sec.php` (legacy) принимает `id` **1-based**, ячейки **десятичные**,
  ответ `Ok`/`error`/`unread`; наш write — JSON/hex/0-based. Трансляция не описана.

**Рекомендация.** До старта compat-слоя написать `docs/legacy-api-kes.md` (или
раздел в `docs/legacy-api.md`), где для **каждой** legacy-ручки зафиксировать:
метод, параметры, авторизацию, источник данных (shm-секция/файл/`kes-list`),
маппинг `legacy id (1-based) → slot id`, `offset`-адресацию (`read_sec`) и формат
ответа (включая legacy-специфику: PHP-массив при `offset=0` vs объект `{addr:byte}`
при `offset>0`, §20). Отдельно решить судьбу ручек, которые **не покрываются**
текущим контрактом (`read_sec` без raw-image; `windspeed`/`Mode`/`Sign`/`MPP`).

### H2 (высокий). Противоречие по авторизации read-ручек КЭС — **✅ решено**

**√ Решение:** принято мотивированное решение «открыть read» для КЭС (повторяет
МАП-чтение, нужно для внешних потребителей/портала): `read_sec.php` и
`read_json.php?device=mppt` — **без авторизации**, `write_sec.php` — HTTP Basic+PAM
(`docs/legacy-api.md` §7, `docs/api-auth.md` §1). Двойного стандарта нет: и МАП-чтение,
и КЭС-чтение открыты. В `docs/legacy/kes-legacy-malina2.md` §20 уточнено: **Basic на
чтение — факт конкретной установки `.68`** (nginx `auth_basic` на `\.php$`), а не
требование к нашему совместимому слою.

**Где:** `docs/legacy-api.md:15-17` vs `docs/legacy/kes-legacy-malina2.md:613`.

- `docs/legacy-api.md:15-17`: «Legacy-**чтение** — **без авторизации** (как в старой
  системе; нужно для внешних потребителей/портала). Legacy-запись — Basic».
- `docs/legacy/kes-legacy-malina2.md:613`: «Авторизация: **HTTP Basic** нужна и на
  чтение, и на запись (`.68`: `admin`)» — это про КЭС/`read_sec.php`.

**Проблема.** Общее правило «read без auth» выведено из МАП-ручек
(`read_json.php?device=map`, `read_memory.php`) и **неверно** распространяется на
КЭС: legacy-`read_sec.php` требовал Basic. В `docs/legacy-endpoints.md:99`
`read_sec.php` значится без пометки об auth.

**Рекомендация.** В спеке (`H1`) для КЭС-ручек задать auth **явно per-ручка**
(чтение КЭС — Basic+PAM, как legacy; либо мотивированное решение «открыть read» с
обновлением §15-17, чтобы не было двойного стандарта).

### H3 (высокий). Разбор legacy КЭС: адреса выродились в `?x??`, документ сам себе противоречит — **✅ решено**

**√ Решение:** восстановлены реальные адреса и сведены ранние секции с §18/§20:
командная ячейка реле — **`0x0E3D`** (дес. `3645`), состояние — **`0x3E3`** (`Relay_C`),
страницы EEPROM — **`0x0080`** (`0x0000,0x0080,0x0100,…0x0380`). Где адрес подтверждён
снифом, но не железом — помечено «подтверждена снифом, не на железе»; где не
зафиксирован — явно «**адрес не зафиксирован**» (вместо `?x??`). Проверено: остатков
`?x??` в документе нет.

**Где:** `docs/legacy/kes-legacy-malina2.md` — `:160, :183, :237, :310, :312, :325,
:351, :407, :426-427, :444, :448, :467, :508, :512, :532, :552, :563, :567, :572,
:577`.

**Проблема.** Там, где по смыслу должен быть конкретный адрес, стоит литерал
`?x??`, из-за чего документ местами нечитаем и противоречив:

- `:310` — «**`?x??` = `?x??`** — ячейка, в которую `write_sec.php` пишет новое
  состояние реле»;
- `:237` — «Формируется запись ячейки **`?x??` (?x??)**»;
- `:351` — «состояния слалась ячейкой `?x?? = ?x??`»;
- `:552` — «с адресов `0x0000,?x??,0x0100,…,0x0380`» — по логике здесь `0x0080`
  (страницы по 128 Б);
- `:567` — блок EEPROM задан как **`?x??..?x??`**.

При этом **поздние** секции тот же адрес уже подтверждают: `:613-643` (§20) и
`:635` — командная ячейка реле = **`0x0E3D`**; `docs/kes-memory.md:68` тоже
подтверждает `0x0E3D`. То есть ранние секции (`:183, :237, :310, :325, :351,
:407, :467, :508, :512`) не сведены с поздними и продолжают называть ячейку
«не подтверждена / `?x??`».

**Рекомендация.** Пройти документ и либо восстановить реальные адреса, либо явно
пометить «адрес неизвестен», а не `?x??`. Свести ранние секции с §18/§20:
командная ячейка реле — **`0x0E3D`** (write-only), состояние — **`0x3E3`**
(`Relay_C`). Это критично: по этому разбору будут кодить compat-слой (`write_sec.php`).

### M1 (средний). Convention `id`/адресов legacy ↔ target не зафиксирован — **✅ решено**

**√ Решение:** в `docs/legacy-api.md` §7.2 добавлена таблица пересчёта legacy ↔ target:
`id` 1-based → индекс `kes-list` + `KesInfo.ID`; ячейка/адрес наружу десятичный, в
control-сокет hex без префикса (конвертация внутри); `unread` (очередь 2200) заменяется
на `error`; лимит КЭС 4 → 32. замена `unread` — `error`.

**Где:** `docs/legacy/kes-legacy-malina2.md` §20, `docs/kes-reader.md` §4.2.

| Аспект | Legacy (`read_sec`/`write_sec`) | Target (`kes-reader` control) |
|---|---|---|
| `id` | **1-based** (`1..N`) | **slot index, 0-based** (`kes.go`, `kes-list.ID`) |
| ячейка/адрес | **десятичный** (`data=[[cell,val]]`) | **hex без префикса** (`addr:"E3D"`) |
| ответ | `Ok` / `error` / `unread` | JSON `{"ok":…,"code":…,"ecode":…}` |
| лимит КЭС | **4** (0..3) | **32** (`kesSlots`) |

**Проблема.** Никакой таблицы пересчёта нет. `unread` (в legacy — «в очереди 2200
необработанная команда») в нашем API аналога не имеет (есть `internal`/таймаут).
Для compat-слоя это нужно спецом.

**Рекомендация.** В спеке (`H1`) зафиксировать пересчёт `legacy_id = slot_id + 1`,
перевод hex↔десятичный, и чем заменять `unread`.

### M2 (средний). Доку противоречит код: публикация после записи — best-effort — **✅ решено**

**√ Решение:** док приведён к коду. `docs/kes-reader.md` §4.2.4 теперь: после записи —

**Где:** `docs/kes-reader.md:159-163` (§4.2.4) vs `daemons/kes-reader/write.go:240-252`.

**Док говорит:** «пулер … затем **полный успешный цикл чтения** и публикует

**Код:** `publishAfterWrite` — best-effort: до `kesPollRetries` попыток; при неудаче

возвращает `ok:true` **без публикации** (`write.go:186-189`, `:251`).

**Рекомендация.** Либо привести док к коду («обновление — best-effort; при неудаче
чтения ответ всё равно `ok`, слот обновится следующим циклом»), либо — если
гарантия нужна — считать неудачу контрольного чтения ошибкой операции.
