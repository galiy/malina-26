# E-Mail — отправка почты из сервиса

Статус: **реализовано** (`web/internal/mailer`; страница «Система → E-Mail»,
`/system/email`). Порт идеи из legacy
«Система → E-Mail» (там был ssmtp + куча полей) — с полным рефакторингом.

## 1. Цель

Дать нашему сервису (`malina-web`) **отправлять почту** (алерты/уведомления от
внутренних процессов). Пользователь **не вникает в технику**: выбирает сервис из
списка, вводит минимум данных; для секрета — пошаговая инструкция со ссылками.
Пользователь письма не сочиняет и не отправляет.

## 2. Провайдеры (пресеты)

Только эти:

| Сервис | SMTP | Порт/безопасность | Что вводит пользователь |
|---|---|---|---|
| Mail.ru (inbox/list/bk/VK) | `smtp.mail.ru` | 465 SSL | почта + «пароль для внешних приложений» |
| Яндекс.Почта | `smtp.yandex.ru` | 465 SSL (587 STARTTLS) | почта + «пароль приложения» |
| Gmail | `smtp.gmail.com` | 465 SSL (587 STARTTLS) | почта + App Password (нужна 2FA) |
| **Другой SMTP** | ввод | host + порт + security (SSL/STARTTLS/нет) | host, порт, логин, пароль |

Прести: host/порт/security зашиты; пользователь вводит почту + секрет. Для
«Другой SMTP» — ручной ввод.

**Инструкция у полей** для каждого сервиса (шаги + ссылки), локализована (см. §7):
- Gmail: `myaccount.google.com/apppasswords` (+ 2FA `myaccount.google.com/security`).
- Яндекс: `passport.yandex.ru/security/app-passwords` (включить IMAP и «Пароли приложений»).
- Mail.ru: `help.mail.ru/mail/faq/password/external/` («Пароли для внешних приложений»).

## 3. Отправка

- **Прямой SMTP из нашего сервиса** (Go, `net/smtp` + TLS), **без ssmtp/MTA**.
- TLS — **строгая проверка сертификата**.
- `From` = адрес аккаунта (провайдеры не дают слать «от чужого имени»).
- **Один** получатель (адрес в настройках).
- Таймаут отправки — **10 c**.
- OAuth2 **не делаем** (для headless-устройства неподъёмно).

## 4. Две функции для внутренних процессов

1. **Простой текст**: тема + текст.
2. **HTML с параметрами**: тема + HTML-шаблон + карта подстановок (плейсхолдеры).

Обе кладут письмо в **аутбокс** (см. §5) и возвращают id; отправка — фоном.
(Тест со страницы настроек может слать синхронно и вернуть результат.)

## 5. Аутбокс

- Хранилище — **tmpfs**: `/dev/shm/malina-outbox` (переживает **рестарт сервиса**,
  **теряется при ребуте хоста** — так и задумано).
- Запись = JSON-файл: `id`(8 hex), `created`, `subject`, `body`, `html`(bool),
  `recipient`, `attempts`, `lastError`, `nextAttempt`.
- Фоновый отправитель: раз в цикл берёт «созревшие» (`nextAttempt ≤ now`), шлёт;
  при ошибке — `nextAttempt = now + 1 мин` (ретрай **не чаще 1 раза в минуту**),
  `attempts++`, `lastError` сохраняется. Успех — файл удаляется.
- **Лимит 200** писем; при переполнении отбрасываем старейшее.
- На странице настроек — **список аутбокса**: тема/дата/получатель/попытки/**последняя
  ошибка** (диагностика); кнопки «удалить» (по строке) и «очистить всё».

## 6. Конфиг и секрет

- Конфиг: **`/malina/etc/malina/email.json`** (0600): `provider, from, username,
  host, port, security, recipient` (без секрета).
- Секрет (пароль приложения) — **шифруем ключом устройства (AES-256-GCM)**:
  ключ — `/malina/var/spool/sys/debug/ticker` (0600, генерируется при отсутствии);
  шифротекст — в `email.json` (`secret_enc`). Секрет хранится только внутри.
  Это **«защита от дурака»** (обфускация на устройстве), а не реальная
  at-rest-защита — так согласовано. Если файл ключа пропал — секрет считается
  не заданным (нужно ввести заново).
- Секрет **никогда не логируем** и не показываем в UI (поле «пусто — не менять»).

## 7. UI и локализация

- Пункт меню **Система → Настройка E-Mail**: выбор сервиса, поля, инструкция,
  «Сохранить», «Отправить тестовое», список аутбокса.
- **Локализация — ru/be/zh/en/ka/kk/uz/tg** (по правилам проекта): и подписи UI, и тексты
  инструкций (4 языка).

## 8. Аудит

- Сохранение настроек (без секрета).
- **Любая отправка** (enqueue/sent/failed) — событие с результатом; тема/получатель
  можно, тело/секрет — нет.

## 9. Не делаем

- OAuth2 (Google/Яндекс).
- Провайдеры кроме 4-х (Rambler/Outlook/Yahoo/Zoho/iCloud/GMX/360/WorkMail и т.п.).
- Пользовательский compose и список получателей.
- `ssmtp`/MTA/sudo.

## 10. Статус

**Реализовано (первый срез):**
- `internal/mailer`: пресеты (mail.ru/яндекс/gmail/custom), конфиг `email.json`,
  секрет AES-256-GCM (ключ `/malina/var/spool/sys/debug/ticker`), аутбокс в tmpfs
  (`/dev/shm/malina-outbox`, лимит 200), фоновый отправитель (таймаут 10 c, ретрай
  ≥1/мин), `SendText`/`SendHTML` (в аутбокс) и `SendNow` (синхронно).
- `/system/email` (+save/test/outbox): форма, инструкции, тест, список аутбокса с
  удалением/очисткой; локализация ru/be/zh/en/ka/kk/uz/tg.
- Аудит: `email_settings` и `email_send` (enqueue/sent/failed/test), без секрета.
- Тесты `internal/mailer` (валидация, crypto roundtrip, аутбокс/лимит, шаблон).
- Задеплоено и проверено на устройстве (сохранение, шифрование, ключ, тест, аудит).

Открытых вопросов нет.
