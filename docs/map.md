# МАП «Титанатор»: подключение и протокол

Справка по подключению МАП к ПАК «Малина» и по протоколу обмена. Нужна для
демона опроса `daemons/map-reader` (см. требования к демону).
**См. также:** `docs/microart-protocol.md` (общий протокол MicroArt),
`docs/map-memory.md` (карта памяти), `docs/map-reader.md` (демон),
`docs/map-contract.md` (бинарный контракт), `docs/map-write*.md` (запись).

> Кадровый уровень (экранирование, CRC, эхо, настройка терминала) описан в
> каноническом `docs/microart-protocol.md`. Здесь — только специфика МАП.

## Подключение (железо)

- МАП подключён к **аппаратному UART на пинах GPIO14/15** («порт консоли»),
  не по USB.
- Линия: **8N1, без чётности**, Tx/Rx + GND.
- Демон обращается к **`/dev/serial0`**.

### Настройка образа (BT сохраняется)

Чтобы аппаратный PL011 обслуживал GPIO14/15, а Bluetooth остался живым, BT
уводится на mini-UART (стадия образа `image/stage-malina/05-map-uart`):

- `config.txt` (`[all]`): `enable_uart=1`, `dtoverlay=miniuart-bt`;
- `cmdline.txt`: без `console=serial0,...` (только `console=tty1`);
- getty на UART замаскирован.

Проверка после перезагрузки:

```sh
readlink /dev/serial0          # -> ttyAMA0
cat /proc/device-tree/aliases/serial0
hciconfig                      # hci0 жив (BT на mini-UART)
```

Откат (если BT не нужен): заменить `dtoverlay=miniuart-bt` на
`dtoverlay=pi3-disable-bt` (как было на старой Малине: BT выключен, МАП на
`ttyAMA0`).

### МАП через USB-RS232 (если подключён по USB)

USB-serial (FTDI и клоны) по умолчанию копит принятые байты до **16 мс**
(`latency_timer`), из-за чего побайтовое эхо МАП ловит `ErrRS_eco` («код 2»).
Ставим **1 мс** — udev-правило `system/udev/60-usb-serial-latency.rules`
(`/etc/udev/rules.d/60-usb-serial-latency.rules`), применяется при подключении
адаптера. Аналог настройки Windows «Время ожидания (мсек): 1». Для драйверов без
`latency_timer` (PL2303/CP210x/CH341) параметра нет — правило не срабатывает.
Проверка: `cat /sys/bus/usb-serial/devices/ttyUSB0/latency_timer` → `1`.

## Протокол

МАП поддерживает **два** варианта: **нативный COM Микроарт** (основной) и
**Modbus-RTU**. Приоритет опроса: **сначала Микроарт**, скорости в порядке
**115200 → 19200 → 57600 → 9600** (приоритет 115200). 38400 не поддерживается
(в доке `_LCD_RSBAUD`: 2400/9600/19200/57600/115200, далее спец-значения).

### Нативный COM Микроарт (приоритетный)

Кадровый уровень (ASCII-посылки `r/w/o/e`, побайтовое эхо, экранирование,
контрольная сумма, коды ошибок, адресация) — **общий и описан в каноническом
`docs/microart-protocol.md` §2–§5**. Здесь — только специфика МАП:

- Приоритет/порядок скоростей пробы — **115200 → 19200 → 57600 → 9600**
  (приоритет 115200; на части железа 115200 работает штатно, см. §9 канонического
  дока). 38400 не поддерживается
  (`_LCD_RSBAUD`: 2400/9600/19200/57600/115200, далее спец-значения).
- Пауза между посылками: МАП считает связь потерянной, если нет посылки > 5 с.
- Адресация: EEPROM `0x000..0x3FF`, RAM с `0x400`.

### Modbus-RTU (альтернативный)

- Чтение блока `0x03`, байтовая адресация ячеек (как `mapgateway`).
- CRC16 (Modbus). Сигнатура семейства — см. ниже.

### Признаки МАП (идентификация)

Базовый критерий (`_Device` в ячейке `0x00` == `3`, кадр валиден):

Проба МАП по native Микроарт — **двухшаговая** (см. `docs/microart-protocol.md`
§10): сперва малое чтение 1 байта `_Device` → если `==3` это МАП, иначе чужое
MicroArt-устройство (`==5` КЭС/MPPT → мгновенно отпускаем, Modbus не шлём);
затем для МАП — полная сигнатура `0x00..0x2F`. При кадре ошибки (`e 04`/`e 06`)
проба повторяется один раз на той же скорости: первый кадр после пробы на чужом
боде устройство отклоняет, второй проходит.

Прочие признаки **не отбраковывают** устройство, а используются для обогащения
(модель/версии), чтобы валидный МАП не уходил в медленный перебор Modbus:

- `_VerPO` (`0x02`) — версия ПО (может быть `0`; не признак «не МАП»);
- `_DevOpt` (`0x07`) — версия процессора: `1` — МАП Sin/Доминатор, `2` — снят с
  производства, `3` — Титанатор (входит в определение модели).

**Чужое устройство:** валидный MicroArt-кадр с `_Device != 3` (например, **КЭС/MPPT
`0x05`**) — порт немедленно отпускается, **Modbus туда не шлём** (см.
`docs/map-reader.md`; backoff `10 мин`). Так `map-reader` не занимает КЭС — его берёт
`kes-reader` (probe КЭС: `_Device==5`).

### Модель (буква)

```
_DevOpt(0x07) == 3          -> T (Титанатор)
иначе  _SyncDiz_Plat(0x24)&1 -> D (Доминатор; есть плата синхронизации 3ф)
иначе  _VerPow(0x01)&0x80    -> H (Гибрид; есть гибрид-плата)
иначе                        -> P (Pro)
```

Порядок важен: у Доминатора 3-фазная плата проверяется **раньше** гибрида.
Разделить Sin и Доминатор по документации невозможно (`_DevOpt=1` общий) — модель
определяется по схеме выше.

### Серийный номер (информационное поле)

`_SerialNum0` (`0x18`, младший), `_SerialNum1` (`0x19`, старший) — число;
`_SerialNum2` (`0x22`, резерв=0), `_SerialNum3` (`0x23`, ASCII-буква).
Не идентификатор (возможны нулевые и повторяющиеся значения). Буква `_SerialNum3`
публикуется в контракте (`serial_letter`), но в UI, меню, заголовках, подписях и
при определении/сопоставлении устройства **не учитывается** — везде используется
только число (`_SerialNum0` + `_SerialNum1`).

### Поля `map-list`

`port`, `protocol`, `baud`, `model` (буква `P`/`H`/`D`/`T`), `serial`,
`serial_letter`, `state`, `last_seen`. Конкретные регистры/телеметрия — отдельно,
силами горутин опроса (публикуются другим механизмом).

## Проверка обмена (только чтение)

Чтение страницы 48 байт с адреса `0x0000` (курсивом — требуется echo-обмен):

```sh
stty -F /dev/serial0 115200 cs8 -cstopb -parenb raw -echo
# далее native-обмен с побайтовым эхо и проверкой контрольной суммы
```

Проверено на устройстве: МАП отвечает на **115200** native-протоколом;
`_VerPO=0x84` (ПО 4.4), `_DevOpt=0x03` (Титанатор), `_VerPow` с битом гибрида.

## Тайминги обмена (важно)

Числовые тайминги обмена (эхо ~50 мс, ответ ~200 мс, max-miss=9, пауза > 5 с) —
в каноническом `docs/microart-protocol.md` §8. Здесь — только МАП-специфика:

МАП строго следит за эхо: если наш ответный байт приходит с задержкой, МАП
возвращает ошибку **`ErrRS_eco` (`e 02`)** — «нет эхо». На практике это давало
«флап»: демон терял МАП и вскоре находил снова.

Причины и меры (по опыту отладки на `.60`):
- **Latency Timer USB-serial** (FTDI) по умолчанию 16 мс — для USB-подключения
  обязателен `latency_timer=1` (udev-правило `system/udev/60-usb-serial-latency.rules`).
- **Опрос порта**: неблокирующее чтение с паузами (polling) добавляло задержку на
  каждый байт. В демоне чтение переведено в **блокирующий режим** с таймаутом
  `VMIN=0, VTIME=1` (100 мс) — ядро отдаёт байт сразу, эхо уходит без задержки.
- **Повтор чтения** в том же цикле (3 попытки) гасит единичные сбои.
- **`max-miss = 9`** (неудачных попыток подряд) — кратковременные сбои не приводят к «потере» МАПа в списке.

Итого для стабильности: быстрый эхо-ответ (блокирующее чтение) + запас по промахам.

> Запись в ячейки (`w`, `ComMAP_*`) — только по явному разрешению. Для
> диагностики/поиска используются исключительно читающие команды.
