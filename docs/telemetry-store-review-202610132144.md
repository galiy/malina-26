## Замечания

### 1. Чтение — не «поток», результат материализуется целиком

Дизайн §1.3/§9 — ответ как поток; §1.7 — RSS ≤ 16 МиБ. Фактически `Query`
накапливает `[]Row`, `encodeReadReply` собирает один `[]byte` (потолок
`maxFrame` 64 МБ). Запрос «ряд целиком» за годы раздувает память (~300 МБ).

**✅ Выполнено (лимит, не стриминг).** Введены **лимит периода**
(`-maxrange`, дефолт ~400 суток) и **лимит строк ответа** (`-maxrows`, дефолт
300 000); при превышении — **отказ** (`read_reply.status` 2/3), не частичный
ответ (`store.go` `Query`, `Options.MaxRows/MaxRangeMS`, `api.go` `doQuery`;
§1.4). Стриминг не вводим намеренно: он усложняет протокол и клиент, а
«вменяемый период» + лимит строк закрывают риск раздувания памяти и запросы «за
годы». Покрыто `TestQueryLimits`, `TestAPIReadTooWide`.

### 2. `index_footer`: раскладка в коде расходится с §5

§5 объявлял `entry_count` → `entries` → `magic` → `crc32`; код пишет
`entries*` → `entry_count` → `magic` → `crc32` (`encodeIndexFooter`). Формат
самосогласован, но документ расходился.

**✅ Выполнено (документ).** §5 приведён к фактическому порядку (записи сначала,
затем хвост `entry_count`/`magic`/`crc32`; `crc32` покрывает `entries`). Код
формата не меняем — он самосогласован.

### 3. `validKey` допускает `"."` и `".."` — выход за корень

`validKey` пропускал `"."`/`".."`; `filepath.Join(root, "..")` выходит за каталог
данных.

**✅ Выполнено.** `validKey` запрещает `.` и `..` (плюс `/`, NUL, пустое, >10
символов); §1.5 уточнён. Покрыто `TestValidKeyDotDot`.

### 4. `write_reply.written` не отражает фактически записанные строки

`doWrite` возвращает `len(rows)` сразу после постановки в очередь; writer может
молча отбросить строки (битый ключ/убывающее время/нет версии).

**❌ Отказ (с обоснованием).** §7 требует, чтобы **клиент не блокировался** на
запись на диск: ответ отдаётся сразу после постановки в очередь. Точное число
реально записанных строк потребовало бы ожидания flush (диск) — то есть
блокирующий ответ, что прямо противоречит §7. Отклонённые строки не теряются
молча — логируются сервером. Смысл поля уточнён: `written` = «принято в
очередь», а не «записано на диск» (§10, README). Если для отладки продюсера
понадобится точная сверка — это отдельный (асинхронный) диагностический канал,
а не изменение семантики ack.

### 5. `minTime` активного сегмента ведётся неверно и не используется

`flushBlockLocked` перезаписывал `as.ref.minTime` на каждом flush (это
`first_time` последнего блока), и `minTime` нигде не читался.

**✅ Выполнено.** `minTime` ставится один раз при создании сегмента
(`newActiveLocked` = `first_time` первого блока), перезапись убрана; добавлено
**отсечение сегментов по `[minTime,maxTime]`** в `readSeries` (§9 п.1). Покрыто
`TestStoreSegmentSkip`.

### 6. Режимы запроса не валидируются сверх диапазона 1..4

`doQuery` проверял только `1 ≤ mode ≤ 4`; не контролировалось число устройств и
метрик; пустой `device_ids` означал «все устройства» (не оговорено).

**✅ Выполнено.** `validMode`: 1/2 — ровно одно устройство; 3/4 — одно и более;
2/3 — непустой список метрик; 1/4 — метрики не задаются; пустой список
устройств — **ошибка** (не «все устройства»). Иначе `status=1`. Семантика
зафиксирована в §1.4. Покрыто `TestAPIBadMode`.

### 7. Прочие (минорные)

- **✅** `format_ver = 2` — зафиксировано в §5.
- **✅** Длина `type` ограничена 10 символами (как `device_id`) — уточнено в §1.5.
- **✅** `device_type`/`device_id` из заголовка не сверялись с путём.
  Реализована сверка в `loadSegment`: при расхождении сегмент пропускается с
  логом (дублирование работает как проверка целостности).
- **❌** `Store.Write` формально блокируется при полной очереди (глубина 1024).
  **Отказ (с обоснованием):** при штатном темпе ~0,17 стр/с очередь 1024 — это
  запас на часы, блокировка недостижима; неблокирующий `select/default`
  приводил бы к **потере строк**, что хуже. Оставлено.
- **✅** Запечатывание только по размеру (граница бакета — не триггер). Принято
  как упрощение: инвариант «≤1024 файлов в каталоге» не нарушается (бакет
  определяется `seq` сегмента). Отдельного изменения не требуется.
- **✅** `Registry.Project` и `FTInt`/`FTFloat`/`FTBytes` не используются самим
  tsdb. Оставлено намеренно — это **общий API** пакета `lib/tscontract` для
  продюсера `malina-web`; сервер проекцию делает напрямую в `readBlock`.
