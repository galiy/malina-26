# Прошивка МАП: устройства и общая структура

Задача охватывает несколько моделей МАП. Сейчас в работе **Титанатор**;
**Доминатор** — следующий, у него будут отличия (образы, ЦПУ, набор ячеек
протокола, возможно — процедура). Поэтому всё, что специфично для устройства,
лежит в его подкаталоге, а общими остаются только инструменты и правила.

## Структура

```
docs/firmware/
├── readme.md              # этот файл: правила, структура, статус устройств
├── tools/                 # ОБЩИЕ инструменты съёмки usbmon (не зависят от модели)
│   ├── capture-start.sh
│   ├── capture-stop.sh
│   ├── parse-stage.sh
│   ├── decode-ftdi.py
│   └── README.md
├── titanator/             # МАП «Титанатор» — текущая работа
│   ├── readme.md          # требования, собранная информация, журнал, артефакты
│   └── logs/<этап>/       # pcap, meta.json, разборы, скриншоты
└── dominator/             # МАП «Доминатор» — задел на будущее
    ├── readme.md          # что известно, отличия, чек-лист
    └── logs/              # пусто до начала работ
```

Правило: **общее — в `tools/`, особенное — в `<устройство>/`**. Образы `.map2`
остаются в `map2gui/` (там же загрузчик); в документе устройства указываются
конкретные файлы и хеши.

## Общие правила (действуют для всех устройств)

- Сеть и устройства — только по явному разрешению оператора.
- Прошивку выполняет оператор; агент не нажимает кнопки и не открывает порт.
- Оператор объявляет «начало»/«конец» этапа; агент снимает лог отдельной сессией
  и складывает артефакты, **не разбирая их во время прошивки**.
- Разбор — отдельно: `tools/parse-stage.sh`.
- Коммит/пуш — только по явному запросу. Приватные данные — только в `.kilo/`.
- Съёмка — пассивный `usbmon` + `tshark`; `strace` не используется (тормозит и
  мешает прошивке).

## Как снимать (кратко)

```sh
# устройство по умолчанию — titanator; для Доминатора: FW_DEVICE=dominator
docs/firmware/tools/capture-start.sh <этап> "примечание"
# ... оператор работает в map2gui ...
docs/firmware/tools/capture-stop.sh          # только сложить, без разбора

# позже, когда разрешено парсить:
FW_DEVICE=titanator docs/firmware/tools/parse-stage.sh
docs/firmware/tools/parse-stage.sh docs/firmware/titanator/logs/<этап>
```

`meta.json` каждого этапа содержит `device` — по нему видно, к какой модели
относится съёмка.

## Что может отличаться у Доминатора

Отличия фиксировать в `dominator/readme.md` по мере выяснения:

- семейство/имена образов `.map2` и их заголовки;
- ЦПУ и версия бутлоадера (у Титанатора `dsP33MU810`, `VerBoot=9`);
- набор ячеек меню и адреса (у Титанатора в 4.x добавились `0x10`, `0x31`,
  `0x32`, `0x7A` и др.);
- наличие/отсутствие платы синхронизации 3 фаз (влияет на модель);
- процедура входа в режим программирования и скорость линии.
