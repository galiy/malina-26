# Прошивка МАП «Доминатор»

Документ устройства. Общая структура задачи — `docs/firmware/readme.md`,
сравнение протоколов — `docs/firmware/protocol-differences.md`.

**Статус (2026-11-03):** этапы 1–4 выполнены (съёмка всех этапов), этап 5 —
разбор логов выполнен, результаты ниже. Прошивка и восстановление настроек
проведены, итоговая верификация прошивки в логах отсутствует.

## 1. Правила и порядок работы

- Сеть/устройство — только по явному разрешению оператора.
- Прошивку выполняет оператор; агент не нажимает кнопки в `map2gui`.
- **Вход в режим прошивки — только вручную** (кнопки/питание). Командного
  перехода у Доминатора нет (в отличие от Титанатора).
- Порядок этапа (изменён оператором 2026-11-03):
  1. агент объявляет название этапа;
  2. оператор — «Начало»;
  3. агент включает сниферы и сообщает о готовности;
  4. оператор проводит этап;
  5. оператор — «Конец»; агент сохраняет артефакты **без разбора**.
- Коммит/пуш — только по явному запросу. Приватные данные — в `.kilo/`.

## 2. Требования оператора

- Целевой образ: `map2gui/mXP11p9v30_0_46k22_d.map2`.
- Подключение: **USB-порт МАП** (FTDI).
- Скорость прошивки заранее неизвестна (предупреждение оператора) — измерена.
- Настройки ЖКИ: снять/восстановить; при необходимости — правки вручную.

## 3. Устройство

Опрос (только чтение) на 57600 8N1, MicroArt:

```
0x0000..0x000F: 03 8D 1E 00 C8 07 02 01 E1 01 00 00 0D 05 04 00
```

| Ячейка | Значение |
|---|---|
| `_Device` (0x00) | 3 |
| `_VerPow` (0x01) | 0x8D |
| `_VerPO` (0x02) | **30** |
| `_POW` (0x05) | 7 |
| `_UACC` (0x06) | 2 |
| `_DevOpt` (0x07) | **1** — Доминатор/Sin |
| `_RAM_END` (0x08-09) | 0x01E1 |
| `_Language` (0x0A) | 0 |
| `_VerPlatPic` (0x0C) | 13 |
| `_VerPlatNet` (0x0D) | 5 |
| `_VerPlatPowDop` (0x0E) | 4 |

Особенность: **первый кадр после смены скорости устройство отклоняет `e 04`**
(ErrRS_cod), со второй попытки отвечает — см. `docs/microart-protocol.md` §7.
Полный разбор: `logs/20261103_092017_probe-57600/device-info.md`.

USB: FTDI FT232R (`0403:6001`), серийник в документе скрыт. Адрес/шина меняются
при переподключении (bus 5/7, dev 11/20), инструменты к этому устойчивы.

## 4. Образ прошивки

`map2gui/mXP11p9v30_0_46k22_d.map2`, 181 012 Б, SHA-256
`95483ab3b512d46aee06e8a2892f2305b2ee79909b716ac74072b7cbd413923f`.

- Заголовок: `mXP11v30_0&19#…` (у Титанатора — `mXP1…&31#`).
- Подпись в заголовке: **32 байта** (64 hex; у Титанатора — 31 байт).
- Тело: 87 665 Б, передаётся с экранированием (см. `protocol-differences.md`).
- Версия образа 30.0 совпадает с `_VerPO` устройства — прошивка контрольная
  (не апгрейд).

## 7. Результаты анализа

### 7.1. Скорости

- Монитор/меню — **57 279 бод** (`SET_BAUD 0xC034`, номинал 57600).
- Прошивка — **19 200 8N1** (`0x809C`). Это отличие от Титанатора (625000).
- Фактический темп прошивки ≈495 Б/с — ограничение побайтового эха USB.

### 7.2. Прошивка

Поток: `lrunU` + подпись 32 Б + тело 87 665 Б (с экранированием) + `0x55`.
Покрытие тела **100%**, ошибок нет, образ передан целиком. Маяк `Load\r\n`
в начале, эхо-рукопожатие устройства `L=;19yU` (у Титанатора `L9131yU`).

### 7.3. Меню и восстановление

- Сохранение: 32 строчных чтения (09:23:55.840–56.118), 256 Б == cfg.
- Восстановление нового cfg: `0x0000=03` → блок 256 Б → `0x0000=06`;
  записано == cfg, 0 отличий.
- Восстановление старого cfg (`…20260923`): блок записан точно, затем ручные
  правки (каждая: `0x0000=03` → ячейка → `0x0403=00` → `0x0000=07`):
  `0x03F=02`, `0x0DE=01`, `0x033=A0`, `0x0DC=00`, **`0x181=50`** (исправлено
  с `60`), `0x101=00`.
- В этапе `monitor-after-restore` зафиксирована ещё одна запись того же блока
  (09:40:59.400–.683), тоже == cfg.

### 7.4. Ручной сброс

- Неудачные запуски монитора на 57600: 09:34:00 и 09:34:13 (только управление,
  данных нет).
- Переключение на 19200 в 09:35:08 → монитор заработал.
- Сброс: пауза в данных 09:36:58.9–09:37:02.2 (**3.3 с**), после — опрос RAM
  на 19200. Команды сброса в линии нет (ручной).

## 8. Ограничения и открытые вопросы

1. Итоговая верификация после прошивки в логах не зафиксирована (после
   терминатора `0x55` — тишина; проверка, вероятно, внутри МАП).
2. Причина неудачных запусков монитора на 57600 до переключения на 19200 не
   установлена: на 57600 обмен шёл, но без данных; после сброса и на 19200 —
   стабильно.
3. Почему в `monitor-after-restore` повторно записан блок меню — по логу это
   действие оператора; автоматического поведения не выявлено.
4. Скорость из ячейки `0x1B5` (`_LCD_RSBAUD`) в снимке 2026-11-03 — `03`
   (57600), в старом бэкапе — `02` (19200); после восстановления старого cfg
   скорость в линии оставалась 57600 (используется текущая настройка).
5. `0x403` пишется как служебный флаг после одиночных правок; семантика не
   документирована.
