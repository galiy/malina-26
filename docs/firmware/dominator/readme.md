# Прошивка МАП «Доминатор» — задел

Работы не начаты. Общая структура задачи — `docs/firmware/readme.md`.
Инструменты съёмки — `docs/firmware/tools/` (общие).

## Что известно на 2026-10-29

- Модель в протоколе: `_DevOpt(0x07) == 1` — «МАП Sin/Доминатор» (общий код,
  разделить Sin и Доминатор по документации нельзя).
- Есть плата синхронизации 3 фаз (`_SyncDiz_Plat(0x24) & 1`) — по ней Доминатор
  отличается от Pro/Hybrid в определении модели.
- Прошлый реверс `.map2` (сентябрь 2026) ориентировался на **PIC18F46K22** —
  для Титанатора это оказалось неверно (там `dsP33MU810`). ЦПУ Доминатора
  **не подтверждён**.
- Образы Доминатора в репозитории отсутствуют; в `map2gui/` и
  `disasm/map2gui/firmware/` лежат образы семейства `mXP1…` (Титанатор/SINE).

## Что выяснить на этапе 1–2 (по Доминатору)

1. Требования оператора: что и зачем прошиваем, с какой версии, какой образ.
2. Точная модель платы и версии: `_VerPO`, `_VerPow`, `_DevOpt`,
   `_SyncDiz_Plat`, версия бутлоадера.
3. ЦПУ и соответствие образа (после Титанатора нельзя опираться на старый
   вывод про PIC18F46K22).
4. Набор ячеек меню/EEPROM и отличия от Титанатора (адреса, новые/удалённые
   параметры).
5. Процедура входа в режим программирования и параметры линии.
6. Есть ли отдельный набор настроек для сохранения/восстановления.

## План (когда начнём)

Повторить цикл Титанатора: требования → сбор информации → съёмка пассивным
`usbmon` по этапам → разбор → стратегия. Логи — в `dominator/logs/`
(`FW_DEVICE=dominator`).
