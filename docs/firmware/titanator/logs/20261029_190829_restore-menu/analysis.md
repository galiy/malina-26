# Разбор этапа restore-menu (восстановление настроек ЖКИ)

Источник: `usb.pcapng` (8.4 МБ), разбор `parse-stage.sh`.
Итог обмена: TX 11 037 Б = RX 11 037 Б (побайтовое эхо), 17 452 события,
19:08:29–19:09:17 MSK.

## Блок восстановления

В TX-потоке значения меню из `map2gui/Titanator_bak_202610291803.cfg`
(`0x100…0x1F8`, 256 Б) встречаются **три раза**:

| # | Время MSK | Смещение в TX | Команда перед блоком | Назначение |
|---|---|---|---|---|
| 1 | 19:08:56.038–57.007 | 5719 | `0x77` (`w`) | запись блока в МАП |
| 2 | 19:09:01.515–01.814 | 6927 | `0x72` (`r`) | контрольное чтение |
| 3 | 19:09:02.634–02.933 | 8197 | `0x72` (`r`) | повторное контрольное чтение |

Непрерывные серии (пауза < 40 мс), в которые попадают проходы:
19:08:55.864–57.662 (2156 событий, 1.798 с), 19:09:01.338–02.157 (1956, 0.819 с),
19:09:02.458–03.251 (1920, 0.793 с).

Копии 2 и 3 **совпадают побайтово**; копия 1 отличается на +129 байт (в копиях
2/3 присутствует вставка `CA 0A 72 7F 01`, которой нет в записи) — это разница
«эхо записи» vs «ответ на чтение», а не расхождение данных.

## Оговорки

- Значения сверены с `Titanator_bak_202610291803.cfg` после разбора кадров
  MicroArt (адрес и данные экранируются: `0x0A→DB DC`, `0xDB→DB DD`).
  Результат: в cfg 288 байт, **совпало 287**; единственное расхождение —
  **`0x124`: в cfg `FF`, в МАП записано `FE`** (контрольное чтение тоже даёт
  `FE`). Адрес `0x124` — область «Реле II» (`_LCD_ReleII_Funk`), вероятно
  нормализация значения программой.
- Одиночные ячейки пишутся кадрами по одному байту, каждая — после
  `w 0x0000=A5` (открытие командной транзакции).
- Первый `SET_BAUD` при открытии — `wValue=0x8004, wIndex=0x0001` (по
  FTDI-кодированию ≈706 кбод, дробная часть 2/8); далее программа штатно
  выставляет 19200 (`0x809C`). Служебный шаг, требует уточнения на этапе 5.
- Опрос между операциями — пачки по ~300 мс, как в этапах `monitor*`.
