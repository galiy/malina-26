# Разбор этапа monitor-flashmode (монитор + включение режима прошивки)

Источник: `usb.pcapng` (6.0 МБ), разбор `parse-stage.sh`.
Период: 18:56:22–18:57:04 MSK. TX 6893 Б / RX 6894 Б (побайтовое эхо),
10 745 событий.

## Что происходило

| Время MSK | Событие |
|---|---|
| 18:56:37.484 | `SET_LATENCY=1` (Wine открыл порт) |
| 18:56:41.697–41.702 | `RESET` → 8N1 → `SET_BAUD` (9600, divisor 312.125) → flow-control |
| 18:56:41.7–18:56:56.3 | штатный обмен монитора, пачки ~300 мс |
| **18:56:56.252–56.287** | **три записи — вход в режим прошивки** (см. ниже) |
| 18:56:56.306–56.678 | последние байты (эхо + один `00`), далее тишина |

После 18:56:56.7 МАП перестал отвечать — сессия закончилась.

## Кадры записи (всего 5 за сессию)

Кадр MicroArt: `'w' P A1 A0 D0..Dp S`, P = число байт данных − 1,
сумма wire-байт ≡ 0 (mod 256). Все кадры ниже проходят проверку суммы.

| Время MSK | Адрес | Данные | Роль |
|---|---|---|---|
| 18:56:42.608 | `0x0000` | `A5` | открытие командной транзакции (см. ниже) |
| 18:56:42.623 | `0x0403` | `00` | запись в RAM-ячейку 0x0403 |
| 18:56:56.254 | `0x0000` | `A5` | открытие командной транзакции |
| **18:56:56.269** | **`0x0091`** | **`55 AA`** | **магия входа в загрузчик** |
| **18:56:56.287** | **`0x0000`** | **`06`** | **команда «применить/перезагрузиться»** |

Ответы МАП — `'o'` с контрольным байтом, без данных.

## Вывод: точка перевода в режим прошивки

Последовательность **18:56:56.252–56.287**:

1. `w 0x0000 = A5` — открыть командную транзакцию;
2. `w 0x0091 = 55 AA` — записать магическую пару в ячейку `0x0091`
   (в документированной карте памяти этой ячейки нет: между `0x60..0x8F` и
   `0xD0..`);
3. `w 0x0000 = 06` — команда завершения/перезагрузки.

После шага 3 МАП замолкает; на следующем этапе (`flash`) загрузчик уже работает
с бутлоадером.

### Почему именно `0x0091 = 55 AA` — ключевой элемент

Та же схема «`0x0000 = A5` → … → `0x0000 = 06`» используется и в обычных
операциях: на этапе `restore-menu` она обрамляет запись каждой ячейки
(19:08:56.0–57.6) и закрывается тем же `0x0000 = 06` в 19:08:57.645. То есть
`A5` и `06` — открытие и закрытие командной транзакции (0x0000 ведёт себя как
регистр команд, хотя по карте памяти это `_Device`).

**Уникальный для этого этапа кадр — `w 0x0091 = 55 AA`** (в `restore-menu` его
нет). Это и есть содержимое команды перевода МАП в режим прошивки.

## Оговорки

- Вход в режим на железе, возможно, требует и ручных действий (кнопки/питание).
  В логе зафиксирован последний serial-акт перед тем, как МАП замолчал; нажатия
  кнопок по USB не видны.
- `0x0403` — RAM-адрес (сразу за `0x400`), запись `00` в 18:56:42.623, вероятно,
  сброс служебного флага; к входу в загрузчик прямого отношения не имеет.
- Проверить воспроизводимость: повторить вход и убедиться, что пара
  `0x0000=A5` → `0x0091=55 AA` → `0x0000=06` повторяется один-в-один.
