# Инструменты съёмки serial-обмена МАП (этап 3)

Пассивный перехват USB-обмена с МАП (FTDI FT232R, `0403:6001`) через `usbmon`.
Порт не открывается, байты в МАП не пишутся, к USB-тракту ничего не добавляется.
`strace` не используется (отклонён оператором: тормозит и мешает прошивке).

## Требования

- модуль ядра: `sudo modprobe usbmon` (после загрузки — `/dev/usbmon*`);
- каталог устройства: `docs/firmware/<устройство>/` уже должен существовать;
- `tshark`/`dumpcap` (Wireshark 4.x);
- `sudo` — только чтобы читать `/dev/usbmonN` и перенести дамп; пароль берётся из
  связки ключей (`secret-tool lookup service sudo username sasha`).

## Порядок

Перед этапом (оператор ещё ничего не нажимал):

```sh
docs/firmware/tools/capture-start.sh monitor "включить монитор"
```

Скрипт находит FTDI по sysfs, создаёт каталог
`docs/firmware/<устройство>/logs/<ГГГГММДД_ЧЧММСС_MSK>_<этап>/` и запускает
`tshark` на шине `usbmonN`. Устройство задаётся переменной `FW_DEVICE`
(по умолчанию `titanator`; для Доминатора — `FW_DEVICE=dominator`). Дождись строки «захват пошёл» — и только потом работай в `map2gui`.

После этапа:

```sh
docs/firmware/tools/capture-stop.sh
```

Скрипт останавливает захват, переносит дамп в каталог этапа и **не разбирает**
его: по правилу оператора во время этапов прошивки логи только складываются.
Разбор — отдельно и позже:

```sh
docs/firmware/tools/parse-stage.sh                     # последний этап (FW_DEVICE)
docs/firmware/tools/parse-stage.sh docs/firmware/titanator/logs/<этап>
```

## Артефакты этапа

| Файл | Что это |
|---|---|
| `usb.pcapng` | сырой дамп usbmon (весь USB-трафик шины, включая служебный) |
| `timeline.md` | (после разбора) протокол по меткам времени MSK: CTRL-запросы FTDI + пачки TX/RX, hex+ASCII |
| `serial-tx.bin`, `serial-rx.bin` | (после разбора) потоки host→МАП и МАП→host |
| `serial-tx.hex`, `serial-rx.hex` | hex-дампы этих потоков |
| `summary.md` | (после разбора) объёмы TX/RX, длительность, паузы ≥ 50 мс, список CTRL-событий |
| `meta.json` | этап, примечание, время старт/стоп (MSK), bus/dev/serial, целевая прошивка и SHA-256 |
| `capture.stderr` | служебный вывод `tshark` |

CTRL-запросы расшифровываются: `SET_BAUD` (14 бит целой части + 3 дробных
бита с шагом 1/8, третий бит — в `wIndex[0]`),
`SET_LATENCY` (latency_timer), `SET_DATA` (биты/чётность/стоп-биты), сброс,
line-control. Служебный слой логируется полностью — по требованию оператора.

## Ограничения

- Полезная нагрузка FTDI берётся из полей диссектора `ftdi-ft.if_a_tx_payload` /
  `if_a_rx_payload`; при их отсутствии — из сырых данных URB (для IN срезаются
  2 байта modem/line status). **Первый живой этап проверить по счётчикам TX/RX**:
  если программа явно обменивается, а счётчики нулевые — включить отладку декодера.
- Фильтра по адресу USB-устройства нет: устройство само идентифицируется наличием
  FTDI-нагрузки; иначе смена адреса при ре-энумерации потеряла бы байты.
- usbmon даёт гранулярность USB-транзакции (URB), а не отдельного байта; точные
  межбайтовые тайминги на линии по нему не восстановить — только пачки и паузы.
- Дамп пишется в `/tmp` и переносится на остановке: `tshark` под root сбрасывает
  привилегии и не может писать в каталог пользователя.

## Проверено на живой съёмке (2026-10-29)

- `monitor`: TX 4418 Б = RX 4418 Б (побайтовое эхо), открытие порта и
  `SET_BAUD 19200` видны полностью.
- `monitor-save-menu`: 21 679 Б в каждую сторону, пакетное чтение меню найдено.
- `flash`: 166 МБ дампа за ~7.5 мин, без влияния на прошивку.
- `restore-menu`: запись блока меню и два контрольных чтения найдены по `w`/`r`.

## Замечания по эксплуатации

- Модуль `usbmon` не загружается автоматически: после перезагрузки ПК нужен
  `sudo modprobe usbmon` (можно добавить в `capture-start.sh` вызовом
  `modprobe`, если разрешено).
- При ре-энумерации USB (перезагрузка МАП/ПК) адрес устройства меняется; декодер
  не фильтрует по адресу и опознаёт FTDI по полям `ftdi-ft.*`.
- `capture.stderr` содержит предупреждение Wireshark о запуске от root — это
  ожидаемо и не влияет на запись.
