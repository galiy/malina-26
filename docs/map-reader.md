# map-reader: спецификация (согласовано)

Демон опроса МАП (Микроарт). Дополняет `docs/map.md` и `docs/map-memory.md`.

## Общее

- Язык — Go, systemd-сервис, каталог `daemons/map-reader/`.
- Железо любое: любой последовательный порт, разные модели/типы **вперемешку**.
- Области чтения и модель определяются **на каждом порту отдельно**.
- Чтение + запись. Запись — по Unix-сокету командой `write` (см. `docs/map-write.md`
  и `docs/map-write-api.md`).

## Поиск устройств

- Кандидаты: `ttyUSB*/ACM*/AMA*/ttyS*`, `by-id`, `serial0/1`; дедуп по `rdev`;
  занятые другими процессами порты игнорируем; список пересобирается каждый цикл.
- Проба порта: сначала native **Микроарт**, затем **Modbus-RTU**; скорости
  `115200 → 19200 → 57600 → 9600` (38400 не поддерживается); для Modbus
  дополнительно `312500/625000` (RS485); ответ ≤200 мс;
  бюджет ~2 с на порт.
- Признак МАП (страница `0x00..0x2F`): **`_Device(0x00)==3`** ∧ валидный кадр.
  `_VerPO`/`_DevOpt` устройство **не отбраковывают** (уточняют модель). `_DevOpt==2` —
  это лишь «снятый процессор», не признак «не МАП».
- **Чужое MicroArt-устройство:** валидный кадр с `_Device!=3` (напр. КЭС/MPPT `0x05`) →
  проба сразу прекращается, **Modbus не пробуем**, порт закрывается, backoff `10 мин`
  (`defBackoffForeign`) — быстро отдать порт, не занимать чужое устройство. Modbus —
  только если валидного MicroArt-ответа не было ни на одной скорости.
- Модель (буква): `_DevOpt==3` → `T`; иначе `0x24&1` → `D`; иначе `0x01&0x80` →
  `H`; иначе `P`.

### Один порт — несколько МАП (Modbus)

- Native — точка-точка: один МАП на порт.
- Modbus: если найден `unit=1`, на том же порту ищем `unit=2,3,4…` до первого
  неответившего; **все найденные** добавляем в список.
- Все МАП одного порта опрашивает **одна** горутина (последовательно) — смысла
  параллелить нет.

## Циклы

- Опрос телеметрии одного МАП/порта — **1 раз в секунду**.
- Потеря МАП — 9 неудачных **попыток** подряд (успех сбрасывает счётчик;
  ретраи в цикле считаются отдельными попытками); сканирование — 10 с (нет МАП) / 60 с (есть);
  backoff пустого порта — 30 с / 600 с; максимум 9 МАП.

## Синхронизация времени МАП

- Источник времени — системные часы (локальная TZ).
- Проверка — **только в окне `XX:X0:00 .. XX:X0:05`** (первые 5 с ПОСЛЕ «круглой»
  10-минутной точки). До точки окно не открывается — иначе установили бы
  «предыдущую» минуту с отставанием почти в минуту. Вне окна не проверяем.
- На один МАП — **одна проверка на окно** (даже если коррекция не удалась).
- Сверяем время МАП (`_LCD_TimeCyr` 0x1B6 + `_TimeCyr_MINUT` 0x44B) с системным и
  **корректируем только при расхождении >1 мин**. Запись идёт тем же путём, что
  команда `write` (обрамление `pre 3`/`post 7`, ретраи; протокол пулера), после —
  полное перечитывание карты и публикация; записанные значения не перепроверяем.
- Отключение — флаг-файл `/malina/etc/malina/map-time-sync.off` (существует → выкл);
  переключатель — в web («Параметры системы»). Наличие файла **кэшируется (TTL 1 мин)**,
  чтобы не дёргать ФС на каждом цикле; кэш общий для всех горутин (под мьютексом).
- Детали (успех/ошибка синка) — только в лог.

## Чтение памяти

- Читаем **все документированные** ячейки за проход; за `0x400+_RAM_END` не лезем;
  `_SoC/_SoH` — только Титанатор.
- Области **статические** (по семейству); `_RAM_END` попадает в контракт, но
  граница задана статическими регионами — они заведомо укладываются в `RAM_END`
  известных моделей.
- Modbus: байтовая адресация совпадает с native (регистр = 2 байта, младший байт —
  по младшему адресу); порядок байт многобайтовых ячеек предполагается тем же, что
  в native (подлежит проверке на реальном Modbus-МАП).
- Области по семейству (см. `docs/map-memory.md`):
  - **T**: 8 областей (`0x000..0x08A`, `0x0D7..0x107`, `0x120..0x127`, `0x138..0x1CE`,
    `0x400..0x458`, `0x516..0x52E`, `0x582..0x59F`, `0x718..0x71B`);
  - **P/H/D**: 7 областей (`0x000..0x083`, `0x0D7..0x107`, `0x120..0x127`,
    `0x138..0x1CE`, `0x400..0x458`, `0x516..0x52E`, `0x582..0x59F`).

## Modbus-RTU / RS485

Отличия от нативного Микроарт и что реализовано:

- **Нет эхо**: фиксы Микроарт (`ErrRS_eco`, побайтовое эхо, `latency_timer` под
  эхо) к Modbus неприменимы. Кадр — бинарный с CRC16.
- **Множество устройств на шине**: перебор `unit=1,2,3…` до первого неответившего;
  все МАП одного порта опрашивает **одна** горутина (последовательно) — на RS485
  нельзя двум «мастерам» говорить одновременно.
- **t3.5**: перед каждым кадром выдерживается межкадровый интервал (3.5 символа;
  для >19200 — 1.75 мс) — `modbus.go:interFrameGap`.
- **Скорости RS485**: к стандартным добавлены нестандартные `312500`/`625000`
  (`_LCD_RSBAUD485`) через `termios2`/BOTHER (`serial.go:setBaudOther`).
- **Направление (half-duplex RTS/DE)**: реализовано (`serial.go:enableRS485`,
  `TIOCSRS485`), но **выключено** (`rs485Direction=false`): USB-RS485-адаптеры
  переключают направление сами, а принудительный RS485-режим на GPIO-UART (наш
  RS232-МАП) сломал бы линию. Включать — при реальном GPIO-RS485.
- **Адрес устройства**: `_LCD_DevAdr` (0x1CA); фактически покрывается перебором
  unit.

Общие меры (сброс входа перед посылкой, повтор чтения, `max-miss`, блокирующее
чтение) работают и для Modbus.

> **Не сделано сознательно:** обработка «локального эхо» на полудуплексной шине
> (мастер может принять свой же запрос). Риск признан; вернёмся, если проявится
> на реальном RS485.

## Публикация: POSIX shared memory (бинарно)

- Один именованный сегмент (по умолчанию `/dev/shm/malina-map-state`):
  `[header 64B][list: 9×72B][slots: 9×slotSize]`.
- **Список** — компактные бинарные записи `ListItem` (по одной на слот), читаются
  классом `MapList` (`DecodeList`) без обращения к payload’ам.
- **Слот** — заголовок (`state`, `gen`, `seq` seqlock, `len`, `crc32`) + бинарный
  контракт `MapData`. Аллокатор слотов — в демоне (`sync.Mutex`, наименьший
  свободный); горутина пишет **только свой слот** и свою запись списка.
- Читатель: по `MapList` берёт `(ID, Gen)`, читает слот `ID`, проверяет `gen`
  (защита от переиспользования), затем `DecodePayload` → `ContractMeta`+`MapData`.
- Публикуем **каждый цикл** (1 с), без сравнения значений.

Полное описание форматов, Go-классов и полей — `docs/map-contract.md`.

## Контракт (бинарный, классы MapList / MapData)

- **Имена полей — из документации** (карта памяти), порядок = id (`documentedCells`).
- Значения **сырые** (масштабирование — на потребителе); несколько ячеек одного
  значения слиты в один тег; битовые карты раскладываются потребителем по описанию.
- Один контракт на все модели; отсутствующие поля помечены в битовой карте
  присутствия.
- `map-list` (внешний API) читается из блока списка: `id`, `gen`, `port`,
  `protocol`, `baud`, `model`, `unit`, `serial`, `serial_letter`, `state`,
  `last_seen`. `serial_letter` сохраняется в контракте, но потребители (UI, меню,
  заголовки, сопоставление устройства) его не используют — там только `serial`.

## Прочее

- Control-сокет: `/run/malina-map/control.sock`, синхронные команды
  (`ping`, `list`, `write`). Команда `write` — запись в МАП (см. `docs/map-write-api.md`).
- **Идентификация устройства — `id`+`gen`.** `id` — номер слота (переиспользуется),
  `gen` — **timestamp назначения слота (`uint64`, мс)**; совпадать должны оба.
  `write` с несовпавшим `gen` → `no_device`.
- Логи — syslog/stderr, без локального файла; юнит `Restart=on-failure` + лимит
  стартов.
- **Тесты/контроль** (`daemons/map-reader/test/`):
  - `fakemap.py` — эмулятор МАП на PTY (чтение+запись), для `write_test.go`;
  - `shm_dump.py` — контроль через shm: декодирует дамп `/dev/shm/malina-map-state`
    и печатает значения ячеек по адресам (обход без правок демона).
  - `go test .` — round-trip записи на `fakemap.py` + тесты валидации/обрамления.
