# tsdb — хранилище рядов телеметрии

Лёгкий append-only сервис для хранения версионированных двоичных строк
телеметрии устройств (МАП/КЭС, набор типов открыт) на SD-разделе `/malina`.
Дизайн и требования — `docs/telemetry-store.md`.

## Что делает

- Ключ строки — `(тип устройства, идентификатор, время)`; `тип`/`ид` — строки
  (`ид` — серийник, до 10 символов); время — Unix ms.
- Контракты — **по типам устройств**, независимая нумерация версий; реестр
  ключуется парой `(device_type, version)`. Версия контракта — на блок.
- Блок — **колоночный**: `bhdr` + `col_offsets` + колонки (время — дельты-varint);
  запрос выбранных метрик читает только нужные колонки.
- Раскладка: `/malina/var/malina-ts/<type>/<device_id>/<bucket>/seg-NNNNNN.ts`.
  Файлы только дописываются; при достижении предела сегмент запечатывается
  (index_footer в хвосте файла). Отдельных файлов конфигурации/индекса нет.
- **Единая writer-горутина**: клиент кладёт строки в очередь и не блокируется;
  **flush — сразу при получении** (без таймера). Периодического fsync нет; fsync —
  при запечатывании и при завершении. Никаких компакций/фоновых оптимизаций.
- Устойчив к пропускам (удалённые файлы) и авто-инициализируется при отсутствии
  дерева.

## Транспорт (двоичный, локальный — без HTTP/JSON)

- Только **Unix domain socket** `/run/malina-ts/tsdb.sock` (права `0600`).
  Сервис **не слушает TCP** — сетевого доступа нет.
- Сообщения — кадры с префиксом длины (`u32` LE); в конце кадра — `crc32`.
- Кадры (§10): запись `MTSW` → ответ `MTSK`; чтение `MTSR` → поток `MTSA … MTSE`.
- Режимы: 1 — ряд целиком по устройству; 2 — выбранные метрики по устройству;
  3 — выбранные метрики по нескольким; 4 — ряд целиком по нескольким.
- Валидация режима и лимиты выборки: период `-maxrange` (дефолт ~400 суток),
  строк на ответ `-maxrows` (дефолт 300 000). `read_reply.status`: `0` ok, `1`
  неверные параметры/режим, `2` период > лимита, `3` слишком много строк.
- `write_reply.written` — число строк, **принятых в очередь** (не факт записи).

## Сборка

```
make arm          # dist/malina-tsdb-armv7
go test ./tsdb/   # из каталога модуля daemons
```

Установка — по общим правилам проекта (`deploy/manifest.tsv`, `stage2.sh`,
`deploy/update.sh`): бинарник → `/malina/usr/local/sbin/malina-tsdb`, юнит
`malina-tsdb.service`.

## Контракты

Контракты версионируются и встроены в клиент и сервер; реестр ключуется парой
`(device_type, version)`. `payload = presence[ceil(n/8)] | значения присутствующих
полей в порядке схемы`. Типы значений: `FTInt` (zigzag-varint), `FTU8`, `FTU16`
(LE), `FTFloat` (IEEE-754 LE), `FTBytes` (len-varint + байты).

Схемы и кодеки вынесены в общий пакет **`daemons/lib/tscontract`** (импортируется
и хранилищем, и продюсером `malina-web`). Зарегистрированы (схемы — `docs/stat.md`):

- `map` v1 — 26 колонок (регистры МАП, u8/u16);
- `kes` v1 — 15 колонок (ячейки КЭС, u8/u16);
- `mbms` v1..v32 — BMS отдельным рядом: `Vn` = `n` ячеек × (u16+u8+u8),
  `device_id` — тот же, что у МАП.

Хранилище раскладывает поля по колонкам и проецирует выбранные метрики.
