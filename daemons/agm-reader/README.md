# agm-pzem-usbip

Сервис на bash: находит PZEM-017 на локальном USB-serial (CH340) и публикует
его через **usbip** (`usbip bind`). Периодически проверяет привязку: после
выдёргивания и повторного подключения (в тот же или другой USB-порт) PZEM снова
идентифицируется и привязывается.

Python не требуется.

## Идентификация и освобождение порта

Алгоритм повторяет требования agm-reader:

- кандидаты — только CH340 (`1a86:7523`) на `/dev/ttyUSB*` и
  `/dev/serial/by-id/*`; в USB-serial других VID/PID пробы не шлются.
  VID:PID CH340 не гарантирует PZEM (таких адаптеров много), поэтому
  окончательное решение — активная Modbus-проба;
- порт берётся под `flock`, а занятые другими демонами порты (map/kes/bms)
  определяются через `fuser`/`/proc` и не открываются;
- проба — Modbus RTU **9600 8N1**, slave `1` (`PZEM_SLAVE`), функция `0x04`,
  8 input-регистров.
- принятый ответ строго 21 байт: `slave`, `0x04`, `0x10`, CRC16 Modbus,
  правдоподобные U/I/P и регистры аварий только `0x0000`/`0xFFFF`; эхо запроса
  (если адаптер его возвращает) находится и отбрасывается по сигнатуре кадра;
- порт закрывается сразу после пробы; при успехе — `usbip bind`, при неудаче —
  пауза 30 с для этого порта (чтобы другие сервисы успели найти на нём своё
  устройство);
- после `usbip bind` tty-узел исчезает: устройство уходит в `usbip-host`.

Карта ответа (8 input-регистров, big-endian):

| Байты payload | Поле | Масштаб |
|---|---|---|
| 3–4 | напряжение | 0.01 В |
| 5–6 | ток | 0.01 А |
| 7–10 | мощность (LE, 32 бит) | 0.1 Вт |
| 11–14 | энергия (LE, 32 бит) | 1 Вт·ч |
| 15–16 | флаг аварии по высокому | 0 / 0xFFFF |
| 17–18 | флаг аварии по низкому | 0 / 0xFFFF |

CRC — два последних байта, little-endian.

## Периодическая проверка

Раз в `CHECK_INTERVAL` секунд (по умолчанию 30):

- сохранённый busid проверяется в `/sys/bus/usb/devices`;
- если устройства нет (выдернули) — состояние сбрасывается и идёт поиск;
- если драйвер больше не `usbip-host` — состояние сбрасывается и идёт поиск;
- если привязка жива — порты не сканируются;
- state хранится в `/malina/var/lib/agm-pzem-usbip` и переживает SIGKILL/сбой; при штатной остановке (unbind) снимается;
- при старте без state сервис ищет уже привязанный CH340 (`usbip-host`) и
  восстанавливает состояние (на случай SIGKILL/ручного bind).

При остановке сервиса (TERM/INT) выполняется `usbip unbind`, чтобы вернуть
устройство локальному драйверу.

## Зависимости

- `usbip` и `usbipd` (`command -v usbip usbipd`). В Debian/Raspberry Pi OS
  пакет может называться `usbip` или входить в `linux-tools-common`; точное
  имя пакета проверить на устройстве (`dpkg -S "$(command -v usbip)"`).
- модуль ядра `usbip-host` (`modinfo usbip-host`, `modprobe usbip-host`);
  сервис пытается загрузить его сам.
- `flock`, `logger`, `stty`, `timeout`, `dd`, `od`, `stat`, `readlink`,
  `mktemp` (coreutils/util-linux), `pgrep` (procps), `modprobe` (kmod),
  `awk` (mawk/gawk), `sed`, `grep`, `tr`, `fuser` (psmisc, желательно; иначе
  медленный fallback по `/proc`).
- `Wants=usbipd.service`: если пакет поставляет unit, запускается он; если нет —
  скрипт поднимает `usbipd` сам.

## Установка (вручную)

`/etc` на устройстве read-only, поэтому юнит ставится в rw-окне:

```sh
sudo daemons/agm-reader/install.sh
```

Скрипт кладёт бинарник в `/malina/usr/local/sbin`, unit — в
`/etc/systemd/system/malina-agm-pzem-usbip.service`, а `/etc` меняет через
`malina-rw run` (rw-окно + `sync`), затем `systemctl enable` + `restart`.

Сервис **не входит** в общий деплой проекта; установка отдельная.

## Проверка

```sh
sudo /malina/usr/local/sbin/agm-pzem-usbip --status
sudo /malina/usr/local/sbin/agm-pzem-usbip --selftest
sudo /malina/usr/local/sbin/agm-pzem-usbip --probe /dev/ttyUSB1
# --force пропускает только предварительную проверку port_busy;
# чужой flock он не снимает, поэтому занятый порт всё равно не читается
sudo /malina/usr/local/sbin/agm-pzem-usbip --probe /dev/ttyUSB1 --force
sudo /malina/usr/local/sbin/agm-pzem-usbip --once   # только при остановленном сервисе
```

Логи — syslog, тег `agm-pzem-usbip` (уходят на лог-хост по общему правилу
rsyslog).

## Клиент usbip

На клиенте (например, `.2`) нужен модуль `vhci-hcd`:

```sh
sudo modprobe vhci-hcd
usbip list -r 192.168.13.60
usbip attach -r 192.168.13.60 -b 1-1.3.2
usbip port
usbip detach -p <port>
```

`busid` может измениться после переподключения в другой USB-порт — клиент
должен брать актуальный из `usbip list -r` и делать `detach`/`attach` заново.
Сервер `usbipd` слушает TCP **3240**; одновременно с устройством работает
один клиент. При остановке/рестарте сервиса клиент отваливается.

## Настройки

Переменные окружения (можно задать в drop-in юнита):

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `PZEM_SLAVE` | `1` | Modbus-адрес PZEM |
| `CHECK_INTERVAL` | `30` | период проверки, с |
| `PZEM_PROBE_TIMEOUT` | `0.3` | ожидание ответа пробы, с |
| `FOREIGN_BACKOFF` | `30` | пауза для «не нашего» порта, с |
| `NOTICE_INTERVAL` | `300` | как часто писать «PZEM не найден», с |
| `BIND_BACKOFF` | `10` | пауза после неудачного bind, с |
| `STATE_DIR` | `/malina/var/lib/agm-pzem-usbip` | состояние (busid) |
| `TMP_DIR` | `/run/agm-pzem-usbip` | tmpfs для временных файлов пробы |
| `LOCK_FILE` | `/run/agm-pzem-usbip.lock` | единственный экземпляр |

## Доступ

`usbipd` слушает TCP **3240** на всех интерфейсах без ограничений по адресу:
устройство доступно любому клиенту локальной сети. Протокол `usbip` не
аутентифицирует и не шифрует соединение — клиент получает полный доступ к
USB-устройству, включая запись Modbus.

## Известные ограничения

- PZEM-017 не имеет уникального серийника; идентификация — только активной
  Modbus-пробой (адрес + правдоподобные значения).
- Порог напряжения пробы — 0.05 В (как в agm-reader): при 0 В на сборке PZEM
  не будет опознан. Питание PZEM-017 идёт от измеряемой цепи.
- Пока устройство опубликовано, локального `ttyUSB` нет — это ожидаемо.
- После reboot привязка usbip не сохраняется; сервис привязывает PZEM заново.
- При аварийном завершении/потере state сервис пытается найти **единственный**
  уже привязанный CH340; если их несколько или state указывает на
  переиспользованный busid, автопривязка не выполняется/сбрасывается без
  `unbind`. Не экспортируйте другие CH340 через usbip на этом хосте.
- Read-only держатели порта (например, пассивный монитор) не считаются
  занятыми — как в `BusyRdevs` agm-reader; возможен конфликт с таким
  наблюдателем.
- Остаётся узкое окно между проверкой занятости и `usbip bind`; оно
  минимизировано (bind сразу после проверки), но не закрыто атомарно.
- Ручное снятие: `usbip unbind -b <busid>`.
- Если `usbip-host` в ядре недоступен, сервис будет писать ошибку `usbip bind`
  (с ограничением частоты) и повторять попытки.
