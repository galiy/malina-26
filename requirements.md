# Требования (план развития)

Зафиксированные требования на будущее. Не являются описанием текущего состояния.

## 1. Роль устройства

Устройство работает как сетевой шлюз/логгер (по аналогии с TCP-шлюзами,
логгерами и т.п.).

## 2. Сетевое поведение (Ethernet + Wi-Fi AP/STA)

### 2.1. Wi-Fi по умолчанию
- Устройство по умолчанию поднимает Wi-Fi **точку доступа (AP)**.
- Подключившись к этой AP, можно открыть **админку** и настроить устройство.

### 2.2. Настройки через админку
- **Wi-Fi клиент (STA):** имя сети (SSID), пароль (и прочие параметры: тип
  безопасности, скрытая сеть).
- **Wi-Fi точка доступа (AP):** SSID, пароль.
- **Ethernet:** режим — DHCP или static (IP/маска/шлюз/DNS).

### 2.3. Логика переключения (приоритеты)
1. **Ethernet активен** (carrier up) → STA **выключен**, включён **AP**.
2. **Ethernet неактивен** и **STA настроен** → попытка подключения как **STA**.
3. Если подключиться как STA **не удалось** → включить **AP**.
4. При отсутствии настроек (по умолчанию) → **AP**.

### 2.4. При работе в режиме AP
- Раздача адресов подключённым клиентам (DHCP-сервер на устройстве).
- При наличии Ethernet-аплинка — маршрутизация/NAT (детали уточнить отдельно).

## 3. Наблюдаемость
- Логи — в tmpfs с жёстким лимитом и ротацией.
- Переключение на удалённый syslog инициируется **самим фактом**
  получения/неполучения DHCP-опции 7, а **не из админки**:
  - опция 7 получена (или изменилась) → форвард логов на удалённый сервер по UDP;
  - опция 7 пропала → возврат к локальным логам в tmpfs.
- Изменение опции обрабатывается только при реальном изменении значения
  (без лишних перезапусков syslog при renew с тем же значением).
- Для режима Ethernet **static** (DHCP-опций нет) — позже добавить
  возможность **ручной** настройки удалённого syslog через админку.

## 4. Сетевой стек (технический выбор)

- **NetworkManager не используется** (усложняет логику AP/STA и не отдаёт
  DHCP-опцию 7).
- **Ethernet:** `dhclient` (ISC, standalone, без NM). DHCP/static; опция 7 — из
  lease/enter-hook. `dhcpcd` отвергнут: на ядре 6.12 падает по SIGSYS
  (встроенная seccomp в DHCP-пути).
- **Wi-Fi STA:** `wpa_supplicant`.
- **Wi-Fi AP:** `hostapd` + `dnsmasq` (DHCP для клиентов AP; при Ethernet-аплинке —
  NAT).
- **Оркестратор AP/STA:** отдельный сервис, следит за carrier Ethernet и
  переключает режимы по логике п.2.3.
- **Админка:** правит конфиги Ethernet/STA/AP; переключение remote-syslog по
  опции 7 — автоматическое (п.3), вручную (для static) — позже.

## 5. Immutable-root: что на `/malina`

Перенесено (структура путей от `/`):
- `/root` → `/malina/root`
- `/home` → `/malina/home`
- `/var/spool/cron/crontabs` → `/malina/var/spool/cron/crontabs`
  (`/var/spool/cron` — симлинк на `/malina/var/spool/cron`; создаётся tmpfiles).
- `/etc/wpa_supplicant` → `/malina/etc/wpa_supplicant` (симлинк).

Не переносим (остаётся как есть / tmpfs):
- `/var/lib/dhcp` (lease dhclient) — tmpfs.
- `/etc/systemd/system`, `/etc/passwd|shadow|group` — пока нет рантайм-управления.
- Логи и `/var/lib/systemd` — tmpfs.
- `/etc/fake-hwclock.data` — **сознательно не переносим**: время до синхронизации
  NTP теряется (на старте логи могут иметь неверные метки).

Bluetooth: `/var/lib/bluetooth` — **tmpfs** (BT нужен; пары теряются при
перезагрузке — приемлемо).

machine-id: PID1 читает его **до** монтирования `/malina`, поэтому держать в
`/malina` нельзя (systemd подставляет transient-tmpfs на `/etc/machine-id`).
Решение: **фиксированный `/etc/machine-id`** в образе (ro) +
symlink `/var/lib/dbus/machine-id` → `/etc/machine-id`.

Время (NTP): `systemd-timesyncd`, серверы `ru.pool.ntp.org`
(`/etc/systemd/timesyncd.conf.d/malina.conf`, `PollIntervalMinSec=16`).
Синхронизация форсируется сразу после получения адреса (хук dhclient), поэтому
после ребута время восстанавливается за секунды (fake-hwclock не используем).

## 6. Web/UI стек

- **Один Go-бинарник**: встроенная статика админки (`embed`) + HTTP API +
  **оркестрация AP/STA в том же процессе**.
- Без nginx, **без TLS** (SSL не нужен).
- Авторизация на бэкенде (basic-auth, как в легаси).
- Наблюдение за Ethernet — netlink/`carrier`; управление
  `hostapd`/`wpa_supplicant`/`dhclient` — через `systemctl`/`os/exec`.
- Кросc-компиляция: `GOARCH=arm GOARM=7`, `CGO_ENABLED=0`; компилятор на
  устройстве не нужен.
- Конфиги/состояние — в `/malina`; логи — в journald/rsyslog.
- **Контракты существующего API сохраняются 1:1** (несколько точек, не только
  `read_json.php`): те же пути/методы/коды/формат/авторизация.
- Оценка ресурсов (Pi 3, 927 МБ): RSS в простое ~10–25 МБ, диск ~8–15 МБ.
