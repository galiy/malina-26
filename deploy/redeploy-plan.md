# Методика переноса ПАК на новую систему (Вариант B) — инструкции для агента

> Это **инструкции для агента**, а не скрипты. Отдельного готового скрипта здесь
> нет: агент сам формирует команды по шагам, ориентируясь на единый источник
> правды раскладки — `deploy/local/deploy-local.sh --plan` и `deploy/manifest.tsv`.
>
> **Целевой ПАК — `.68`** (старый). Хост `.60` (основной дефолтный) в этой
> методике **не трогаем**. Для каждого шага — цель, критерии готовности и риски.

---

## Общая цель

Перевести старый ПАК `.68` с устаревшей системы (jessie + legacy-демоны) на
голый образ (Raspberry Pi OS bookworm) и развернуть артефакты проекта.

## 0. Предусловия

- Собран голый образ (`image/build.sh`) → `*malina-lite.img` в
  `/opt/raspberry_tmp/pi-gen/deploy/`. Образ содержит только **p1 (boot) + p2
  (root 3 ГиБ)**; p3 `/malina` отсутствует.
- Собранные arm-бинарники в `*/dist/*-armv7` (`make -C web arm` и т.д. по
  `deploy/restore.md`).
- Доступ по SSH к `.68`.
- Пароль SSH по умолчанию в голом образе: `malina` и `root` — **`malina-26`**
  (root-вход разрешён).

---

## Шаг 1. Инвентаризация и остановка процессов на старом ПАК (.68)

**Цель:** исключить любые записи в какой-либо раздел перед перезаливкой.

Обоснование безопасности (проверить фактически):
- корень `ro` (`mount | grep ' / '` → ro);
- логи — в tmpfs (`/var/log`, `/tmp`), волатильны;
- раздел `/settings` (rw) занят **только прикладными** сервисами — их душим;
- логика: если эти сервисы и запланированные задачи остановлены, активная запись
  в разделы отсутствует, и заливка образа в работающую систему безопасна.

Действия:
1. `mount -l` — зафиксировать ro/rw точки, каталоги с записью.
2. `ps aux`, init-сервисы, `crontab -l`, `/etc/cron.d/*` — найти всё пишущее.
3. Остановить пишущее (приоритетно, но не обязательно все — оставить `sshd`,
   иначе теряем канал):
   - прикладные демоны на `/settings` (mapd, mpptd, scd, emd, batmond,
     mserver*, mapgateway, bmslistener — если на этой машине);
   - cron-циклы: `* * * * * check_daemons.sh`, `malina_serv.sh` (чистка логов),
     `set_map_time`; `crontab -r` временно;
   - веб/php: nginx, php5-fpm;
   - наблюдаемость: rsyslog (в т.ч. пересылку), snmpd.
4. `sync`.

**Критерий готовности:** только `sshd` (+ ядро) потребляют ресурсы; `mount` не
показывает записываемых активных разделов, кроме `/settings`, на который никто
не пишет.

## Шаг 2. Заливка голого образа по сети (на работающей старой системе)

**Цель:** переписать SD `.68` голым образом по SSH, не вынимая карту.

Действие:
- С ноута: `dd` голого образа в корневой блок-устройство `.68` по SSH.
  Пример направления (агент выбирает способ сам, это не фиксированный скрипт):
  ```
  dd if=<голый образ>.img | ssh <польз>@.68 'dd of=/dev/mmcblk0 bs=4M conv=fsync'
  ```
- Канал SSH держать всё время заливки; не разрывать; после `sync`.
- Образ — только p1+p2; старая таблица разделов (в т.ч. старый p3 `/settings`)
  перетирается таблицей образа; остаток карты после p2 — неразмечен.

**Критерий готовности:** `dd` завершился без ошибок; `sync`; соединение цело.

**Риск и его снятие:** заливается блок-устройство, с которого работает система.
Активных записей нет (Шаг 1), поэтому существенной порчи не ожидаем; если канал
падает на перезаписи занятых блоков — проверка корректности после перезагрузки
(Шаг 3). Не прерывать `dd` по полпути.

## Шаг 3. Перезагрузка и вход в голую систему

- `ssh …@.68 'sync; reboot'` (или питание). Загружается голый образ (bookworm).
- Вход по SSH: `malina`/`root`, пароль `malina-26`. **Сменить пароли.**
- Проверить «голость»:
  - `systemctl is-active …` — нет сервисов `malina-*`;
  - `mount` — корень `ro`, `p3 /malina` ещё нет (`/malina` каталог пуст/нет монтирования);
  - `df -h`, `fdisk -l` — только p1 (boot) + p2 (root).

**Критерий готовности:** SSH работает на дефолтном пароле; раздел p3
отсутствует.

## Шаг 4. Пошаговое создание p3 и раскладки (вручную, не скриптом)

**Цель:** на `.68` создать p3 `/malina` и развернуть артефакты.

**Источник шагов — ДИНАМИЧЕСКИЙ, не фиксированный список.** Перед работой
получить актуальную последовательность:
- `deploy/local/deploy-local.sh --plan <target>` — печатает пошаговый план
  раскладки (создание p3, дерево, бинарники, ассеты, `manifest.tsv`, симлинки,
  юниты, pamcheck, purge NM, проверка);
- `deploy/manifest.tsv` — источник всех артефактов `src/dst/mode/policy`.

Агент воспроизводит эти шаги **на `.68`** (через SSH), адаптируя пути и команды
под устройство (карта внутри `.68`, а не в картридере ноутбука): `sfdisk -N 3`,
`mkfs.ext4 -L malina`, монтирование, раскладка по `manifest.tsv`, симлинки,
`systemctl --root`, pamcheck (chroot+qemu), purge NetworkManager, фиксы fstab.

Порядок шагов — как в `deploy-local.sh --plan` (см. ниже, сверяется с выводом
скрипта как с источником истины):
1. Разметка p3: начало от конца p2, `size=+` (весь остаток) → `mkfs.ext4 -L malina`.
2. Точка монтирования `/malina` в rootfs; fstab `LABEL=malina`.
3. Дерево `/malina`: `etc/malina/network`, `etc/wpa_supplicant`, `home`, `root`,
   `var/spool/cron/crontabs`, `usr/local/{bin,sbin,libexec,share/malina/web}`;
   seed-конфиги сети (`mode1.json`, `mode2.json`, `active`).
4. Симлинки: `/root`,`/home`,`/etc/wpa_supplicant` → `/malina/*`;
   `/etc/resolv.conf` → `/run/malina-net/resolv.conf`; dbus machine-id.
5. `machine-id`, `hostname` (свежие inode: rm + install).
6. Артефакты по `deploy/manifest.tsv` (`always`/`if_absent`; `/malina/*` на p3).
7. Бинарники (armhf) в `/malina/usr/local/{bin,sbin}`.
8. Веб-ассеты `web/assets/{templates,static,i18n}` → `/malina/usr/local/share/malina/web`.
9. `malina-pamcheck` (chroot+qemu, gcc из образа).
10. Владельцы/режимы (числовые uid/gid из образа; НЕ `chown -R` по `/etc`).
11. `systemctl --root` enable базовых юнитов + mask/disable по
    `system/provision/{masked,disabled}.txt`.
12. Purge NetworkManager; fstab-фиксы (убрать `tmpfs /var/lib/NetworkManager`,
    добавить `tmpfs /var/lib/dhcp`, `tmpfs /run/malina-ts-raw` (200M)); создать
    tmpfs-точки; `rm -rf /etc/NetworkManager`.
13. tmpfiles; `sync`; offline-проверка (см. `deploy-local.sh` «Проверка»).

**Критерий готовности:** `systemctl is-active malina-web malina-netd map-reader
kes-reader bms-reader bms-proxy malina-tsdb rsyslog ssh cron` — рабочие;
`/malina` смонтирован, p3 на месте; вход в веб работает; корень `ro`.

## Шаг 5. Пост-проверка и возврат к работе

- Убедиться в режиме сети (AP/STA), `ip -br a`, `nft list ruleset`.
- Включить/настроить reader-демоны (`enabled:true`, см. `deploy/local-deploy.md`).
- Сменить дефолтные пароли (по умолчанию `malina-26`).
- Зафиксировать результат в документации.

## Замечания

- `.60` в этой методике не затрагивается.
- Инструкции — **для агента**; агент обязан сам строить команды по источникам
  (`deploy-local.sh --plan`, `deploy/manifest.tsv`), а не использовать
  зафиксированные ниже примеры как «готовый скрипт».
- Перед фактической заливкой подтвердить у оператора явное разрешение (правило
  деплоя проекта), т.к. шаг 2 разрушает текущую систему `.68`.
