# Вариант B — перенос ПАК по сети (общий порядок)

> **Только общий порядок и ссылки.** Конкретные шаги, команды, пути, состав
> артефактов и проверки не дублируются: единственный источник истины —
> `deploy/local/deploy-local.sh` и `deploy/manifest.tsv`.
> Агент читает скрипт и разбирается сам; при расхождении с этим документом
> прав скрипт.

## Принципы

- Параметры (целевой хост, пользователь, доступы, образ, раздатчик) задаёт
  оператор. В репозитории нет хостов и паролей по умолчанию.
- Разрушительные операции — только после явного подтверждения оператора.
- Секреты и приватные данные не переносятся вместе с репозиторием.
- Не создавать отдельный «план раскладки»: порядок и проверки берутся из
  `deploy-local`, а не переписываются в этот файл.
- Все артефакты, включая бинарники, веб-ассеты, `manuals/`, unit-файлы и
  конфиги, ставятся так, как это делает `deploy-local`; отдельных списков
  «что ещё не забыть» здесь нет.
- После каждого логического этапа — проверка из `deploy-local`; при
  несоответствии остановиться и разобраться, а не продолжать «по памяти».

## Общий порядок

1. Согласовать с оператором целевой хост, раздатчик, доступы и образ.
2. Снять инвентарь целевой системы, остановить процессы, которые могут
   писать в разделы, и убедиться в сохранности канала управления.
3. Подготовить образ и выполнить заливку тем способом, который выбрал
   оператор; при необходимости — временный bootstrap сети.
4. Загрузить целевую систему и проверить доступ.
5. Воспроизвести на целевой системе шаги `deploy/local/deploy-local.sh`:
   раздел `/malina`, раскладка по `deploy/manifest.tsv`, бинарники,
   веб-ассеты и `manuals/`, pamcheck, владельцы/режимы, unit-файлы,
   fstab/NetworkManager, offline-проверки.
6. Перезагрузить систему и проверить сервисы, вход в web и встроенную
   справку; зафиксировать результат для оператора.

## Ссылки

- `deploy/local/deploy-local.sh` — единственный источник истины для
  локальной раскладки и проверок.
- `deploy/manifest.tsv` — состав системных артефактов.
- `deploy/local-deploy.md` — описание локального деплоя и образа.
- `deploy/restore.md` — восстановление из образа и репозитория.
- `deploy/deploy.sh` — обновление работающего прода в процессе доработок
  (не вариант B).

## Границы

- В этом документе не должно быть конкретных команд, адресов, паролей,
  пошаговых скриптов и перечней файлов «на память».
- Если для варианта B нужен новый шаг, сначала он появляется в
  `deploy-local` (или `manifest.tsv`), затем сюда добавляется только
  ссылка на него.
