# ადმინისტრატორის ინსტრუქცია

ეს გვერდი — მათთვის, ვინც ემსახურება მოწყობილობას: SSH-ით წვდომა, წვდომის
აღდგენა, სამსახურებისა და ჟურნალების მართვა. მოწყობილობებთან ჩვეულებრივი მუშაობისთვის
ის არ არის საჭირო.

## წვდომა SSH-ით

დაუკავშირდით მოწყობილობის ქსელს (წვდომის წერტილი ან საერთო ქსელი) და შეასრულეთ:

```
ssh malina@<მოწყობილობის-მისამართი>
```

- წვდომის წერტილის ქსელში მისამართი — `10.10.100.254`.
- საერთო ქსელში — მისამართი, რომელიც მოწყობილობამ მიიღო DHCP-ით ან ხელით არის
  მითითებული.

ნაგულისხმევად პაროლი — `malina-26`. ის მოქმედებს მომხმარებლისთვის `root`-ც.

პაროლი იცვლება გვერდზე «სისტემის პარამეტრები → პაროლის შეცვლა» და მაშინვე
მოქმედებს ვებ-შესვლასა და SSH-ზე.

## თუ პაროლი დაკარგულია

- თუ SSH-ით წვდომა შენარჩუნდა, შედით და შეცვალეთ პაროლი ვებ-გვერდის
  «სისტემის პარამეტრები» საშუალებით.
- თუ დაკარგულია ვებ-პაროლიც და SSH-პაროლიც, წვდომის აღდგენის სტანდარტული გზა
  მოწყობილობის ხელახლა დაყენების გარეშე არ არსებობს. მიმართეთ მას, ვინც
  პასუხისმგებელია მოწყობილობაზე.

## სამსახურების მართვა

გახსენით «სისტემა → სერვისები».

- ჩანართი **«Malina»** — ქვესისტემის სამსახურები. მათი გაშვება და შეჩერება შეიძლება.
- ჩანართი **«სისტემური»** — ოპერაციული სისტემის სამსახურები, მხოლოდ ნახვა.

შეჩერებამდე წაიკითხეთ კომენტარი სამსახურის ხაზში. ზოგიერთი სამსახურის
შეჩერება არ შეიძლება:

- ქსელის სამსახური — გაქრება წვდომა ადმინკასთან და წვდომის წერტილი;
- თავად ვებ-ადმინკა — ინტერფეისი დაიხურება;
- OS-ის კრიტიკული სამსახურები — შეიძლება დაარღვიოს მოწყობილობის მუშაობა;
- ტაიმერები და სამსახურები, რომლებსაც მართავს ავტომატიკა, ხელით გაშვება არ სჭირდება.

თუ წვდომა ქსელის სამსახურის შეჩერების შემდეგ დაიკარგა, გადატვირთეთ მოწყობილობა.

## გადატვირთვა და გამორთვა

- «სისტემის პარამეტრები → კვების მართვა» — გადატვირთვა და სწორი გამორთვა.
- «სერვისები → მალინას გადატვირთვა» — იგივე.

გადატვირთვის შემდეგ გაიხსნება მოლოდინის გვერდი. ის ამოწმებს ხელმისაწვდომობას ორ
წუთამდე. თუ მეტი — განაახლეთ გვერდი ხელით.

გამორთვისას დაელოდეთ სრულ შეჩერებას და მხოლოდ ამის შემდეგ გამორთეთ კვება.

## ქსელი: რეჟიმები და წვდომის აღდგენა

- **რეჟიმი 1 «წვდომის წერტილი»** — მოწყობილობა ქმნის Wi-Fi ქსელს. ადმინკა
  ხელმისაწვდომია მოწყობილობის მისამართზე ამ ქსელში (`10.10.100.254`
  ნაგულისხმევად). საკაბელო პორტი უკავშირდება საერთო ქსელს.
- **რეჟიმი 2 «Wi-Fi კლიენტი»** — მოწყობილობა უკავშირდება გარე Wi-Fi ქსელს.
  ადმინკა ხელმისაწვდომია მისამართზე, რომელიც მოწყობილობამ მიიღო ამ ქსელში.
  ადგილობრივი ქსელი საკაბელო კლიენტებისთვის რჩება `eth0`-ზე.

რეჟიმის შეცვლისას წვდომის მისამართი იცვლება. თუ შენახვის შემდეგ წვდომა გაქრა,
ეძებეთ მოწყობილობა ახალი მისამართით როუტერში. თუ გარე ქსელთან დაკავშირება ვერ
მოხერხდა, მოწყობილობა თავად დროებით ქმნის წვდომის წერტილს.

თუ საკაბელო სეგმენტზე აღმოჩენილია უცხო DHCP-სერვერი, მოწყობილობა აჩერებს თავის
მისამართების გაცემას, მაგრამ რჩება ხელმისაწვდომი თავის მისამართზე. როდესაც უცხო სერვერი
ქრება, გაცემა განახლდება ავტომატურად.

## ჟურნალები

«სისტემა → ინფორმაცია სისტემის შესახებ → ლოგები» — სისტემური ჟურნალების ნახვა.
ფაილების სია ფიქსირებულია, ჟურნალები ხელმისაწვდომია მხოლოდ წასაკითხად.

ჟურნალების გარე სერვერზე გადასაგზავნად მიუთითეთ მისამართი «სისტემის პარამეტრები →
ლოგირება». თუ ველი ცარიელია, გამოიყენება ქსელის პარამეტრებიდან აღებული
მისამართი.

## დრო

- მოწყობილობის დროის ზონა იცვლება «სისტემის პარამეტრები → ჰოსტი»-ში.
- MAP-ის დრო სინქრონიზდება მოწყობილობასთან ყოველ 10 წუთში, თუ სხვაობა ერთ
  წუთზე მეტია. ითიშება იქვე, «MAP-ის დროის სინქრონიზაცია»-ში.

## მონიტორინგი

«სისტემის პარამეტრები → მონიტორინგი» ჩართავს შეტყობინებების პერიოდულ გაგზავნას
გარე მიმღებზე. საჭიროა მიმღების IP და პერიოდის მითითება. თუ მონიტორინგი არ გჭირდებათ,
დატოვეთ გამორთული.

## API

- [Native API: lists, raws](api-native.md) — ტოკენები, სიები, ნედლი კონტრაქტები,
  ჩაწერა და სტატისტიკა.
- [Legacy API](api-legacy.md) — მთელი ძველი API და თავსებადობა «მასტერ-კვანძთან».
- Native-API იყენებს Bearer-ტოკენს ან cookie-ს. Legacy-კითხვა ღიაა უფლებამოსილების
  გარეშე, legacy-ჩაწერა — HTTP Basic (`malina` + პაროლი).

## რა ვქნათ გაუმართაობისას

1. გახსენით «ინფორმაცია სისტემის შესახებ»: შეამოწმეთ ტემპერატურა, კვება, დისკები და
   წარუმატებელი სამსახურები.
2. გახსენით «სერვისები»: ნახეთ სამსახურების მდგომარეობა.
3. გახსენით «ლოგები»: იპოვეთ შეცდომების შეტყობინებები.
4. თუ მოწყობილობა გაიყინა — გადატვირთეთ ის.
5. თუ პრობლემა მეორდება — შეინახეთ აღწერა და დრო, მიმართეთ დეველოპერს.
